Farfold：从统一接入，到完整工作台

Farfold 的目标是不修改 Agent 本体，做好统一工作台和完整的 Host 服务。公共 ACP 客户端可以降低多种协议的维护成本，但完整产品还需要文件、差异、终端、安装、配置、状态与恢复机制。

这份报告把“如何连 Agent”和“如何让用户顺畅工作”放在一起设计。候选方案尚未定案；本轮只研究与制作图文，没有改动应用实现。

1 · 你真正提出的四个问题

问题一：边界到底是什么？

Agent 决定任务怎么做，并保有原生会话与行为。Farfold 管工作环境、界面、资源服务和运行可靠性。已有 Agent 不改源码，不代表 Farfold 只需写前端。

问题二：哪些信息从哪里来？

Agent 报告过程；Host 观察文件和 Git；用户做审阅和选择。三者要保留各自来源，才能避免把“说改了”当成“实际文件状态”。

问题三：哪些公共，哪些专属？

公共能力按职责组织，专属差异收在 Agent 接入定义和 UI 扩展里。不是为每个 Agent 重写工作台，也不要求把差异全部抹平。

问题四：怎样检查有没有遗漏？

沿“开始 → 工作与干预 → 查看产物 → 离开与回来”逐项检查。每项写明负责人、数据、界面、失败处理和当前实现状态。

术语纠正：当前 Farfold 分别接入 Pi RPC、OpenCode HTTP/SSE、Codex App Server，是实现三种现有原生接口的客户端，不是自行发明三套协议。

2 · 同行共性是“完整 Host + 协议接入”，具体边界各有不同

这些参考支持“不修改外部 Agent，通过公开接口做 Host”的方向。不同产品复用既有 IDE 服务、自己建设工作台服务，或把执行服务独立出来；没有一份所有同行完全相同的模块清单。

5 · 代码变更不只是“接收事件”

已有 Farfold 的路径审阅可以保留；逐行 diff、文件预览和可能的撤销需要在它上面明确设计。代码与文档产物可以共享文件能力，不必按 coding / 非 coding 切成两套前端。

最新范围：开发旧会话不迁移，实施时可清理；只保留 Provider 等重要配置。优先复用本机 Agent 的产品方向不变，具体适配器必须符合这个要求。本轮未执行删除。

5A · 新增展开：统一模型服务管理

在完整职责图中，将原“账号与配置服务”展开。模型服务配置复用与 ACP 工作通信并列：一个决定 Agent 用什么连接，一个负责 Farfold 怎样与 Agent 交流。

参考 实际做法 / 约束 Farfold 借鉴
CC Switch 本轮读到的 UniversalProvider 针对 Claude / Codex / Gemini 生成各自配置；另有代理模式 采用统一记录和各 Agent 配置适配；不把代理、自动切换全部带入首轮。
OpenCode 原生 Provider 认证、模型 ID、自定义端点与配置组合 保留准确原生标识和环境；同名模型不等于同一调用来源。
Zed 外部 Agent 外部 Agent 通常独立认证；Gemini 在缺少进程密钥时可复用 Zed 的 Google key 共享 ACP 不自动带来共享账号；Farfold 需要独立建设配置管理。
Z.AI Coding Plan 专用接口与明确支持的工具范围 服务记录须带套餐 / 接口与兼容工具信息；不把订阅等同通用 API。

CC Switch 的保存与分发源码将共同记录保存、子配置同步、当前配置生效分开处理；实际配置写入失败可汇总，但数据库错误仍可能中止。这支持逐目标记录结果，不证明整体同步事务化，也不意味着任意 API 可自动转换协议。

统一目录

品牌用于导航；地区、普通 API、Coding Plan 是服务差异；用户可有多份连接。模型显示名与真实模型标识分开，未知别名保持分开，不通过名称猜测去重。

共同配置有归属

建议 Farfold 管理的共享记录为配置来源，各 Agent 的受管理配置为生成结果。发现已有原生配置时先辨认归属；只读发现与导入复用分开。外部修改产生差异时显示冲突，不自动来回覆盖。

兼容性有层次

分别判断套餐允许范围、接口格式、模型工具调用 / 图片能力、Agent 与适配器支持。已保存只表示记录成功；已应用表示对应环境接受配置；请求成功才记为本次验证可用。不能因 A 可用就给 B 打勾。

配置生效有时间

配置记录带版本，各 Agent 保存已应用版本。正在运行的任务绑定既定连接；切换默认只影响后续新任务，已有会话换模型须走原生支持的操作。一个进程内无法隔离账号时使用明确的连接隔离或禁用并行切换。

凭据与删除有边界

优先系统凭据存储及安全引用；必要的原生文件副本须纳入轮换和删除。移除 Farfold 连接不等于撤销供应商账号，也不自动清除用户在其他工具中的独立配置。诊断和导出不含密钥。

共享范围诚实

配置复用不自动池化额度，不自动重试或改用更贵的服务。专属登录继续由原生维护；代理是后续可选组件。主应用与外部 Agent 程序安装、配置管理是不同职责。

6 · 三套可能的 Host 架构

当前建议 A：模块化的应用内 Host + 公共 ACP。原因是 Farfold 目前专注单机 macOS，已有 Tauri 后端和持久化基础。先按职责整理完整 Host，可保留最多现有基础，避免同时引入一套后台服务的安装与升级问题。这是本报告的设计推断，尚非用户决策。

如果“彻底退出 Farfold 后，任务还必须继续”成为明确要求，再优先比较 B。若仅要求关闭窗口后继续，可先通过保留应用后台进程实现，不必立刻拆出独立 daemon。C 只在明确需要远程机器或多端访问时考虑。

交付前必须验证 窗口关闭、完整退出、电脑休眠、升级各不相同 A 方案明确退出规则；未知任务恢复诚实。独立后台不是休眠或崩溃的保证。 运行寿命设计及未来安装应用冷启动 / 配对恢复检查。

建议的下一轮推进方式（尚未启动）

  1. 先完成设计闭合：固定第一批接入组合、能力保留表、配置归属和重要配置保留；开发旧会话不迁移。不以“采用 ACP”替代这些事实。
  2. 开发获批后先做一个完整切片：安装发现 → 一次配置 → 真实任务 → 审阅 → 取消 / 恢复。选择能力覆盖最清楚的一路，不能只凭“原生 ACP”就判定优先。
  3. 再推广共同机制：逐路替换协议解析与配置适配，验证后在同一切片删除被替代控制路径；未迁移路径有明确边界，不给同一会话保留两个控制中心。
  4. 最后做三路交叉验证：同一服务跨 Agent 生效、并行账号隔离、外部升级、新架构会话续接、冷启动恢复与真实文件任务。现阶段只规划这些验证，不执行开发或安装。

19 条具体设计规则

流程 正常路径 失败 / 冲突处理 状态与边界
01 · 安装来源 Host 先列出已知位置和用户选定路径的安装；显示版本和来源；缺失时提供按需安装。复用程序和复用账号分别记录。 找不到则允许指定路径；多版本保留明确选择；不扫描读取任意账号数据。只启动选定的入口。 已对齐：本机优先 + 按需安装，主包不带 Agent。
02 · 固定接入组合 每个安装引用明确的 Agent、适配器与依赖版本；握手确认协议和能力。 未知版本显示未验证；明确缺少必要接口则阻止开始并说明升级 / 更换选定版本路径；不偷偷走原生旁路。 待事实核查：三路的确切支持组合。
03 · 启动与清理 Host 持有自己启动的进程，设置项目、配置目录和生命周期；ACP 成功握手后进入可工作状态。 启动超时先确认并清理本次拥有的失败进程；保留诊断。不能按程序名杀其他工具启动的进程。 建议规则；未进入实现。
04 · 添加共享连接 一次保存端点、协议、地区 / 套餐、凭据引用与模型映射；逐 Agent 生成受管理配置。 保存、应用、需要重启、请求验证分别显示；任一路失败不显示全部成功，失败路不影响其他已生效路。 已对齐体验；具体配置接口按接入包确定。
05 · 配置归属 Farfold 管理自己的共享连接与投影；既有原生账号可作为独立连接保留。导入已有连接须说明范围，之后一个字段只有一个写入来源。 检测到用户外部修改受管理字段时暂停覆盖，显示两份差异供选择；未管理字段保留，不双向无限同步。 建议默认；是否同步外部全局配置未获决定，默认不做。
06 · 选择与生效 全局默认只影响新任务；会话选定的连接与模型保留。任务开始绑定生效配置版本。 任务中改设置进入待应用，不能悄悄更换当前模型或账号。原生进程配置无法隔离时，分连接运行或禁用并行切换。 作用域需按 Agent 核实；用户无需重复输入密钥。
07 · 模型目录 品牌层归组，服务地区 / 套餐和账号连接分开；真实模型 ID、接口和能力作为底层记录。 同名不自动删；只归并有等价依据的条目。无映射时显示来源；禁止把国际站 key 自动投到另一端点。 建议规则；用户报告的 GLM 重复尚未运行复现。
08 · 凭据维护 轮换共享连接凭据后逐目标应用；保留每一路的生效版本；原生登录按原生生命周期维护。 失效、限额、网络故障分开显示。日志、导出和错误不带密钥；移除连接不等于注销供应商账号。 实施时列精确配置保留与删除清单。
09 · 创建与发送 选项目 / 工作副本、Agent 安装和连接，创建原生会话并保存身份后发送。共用准入限制和同工作副本互斥。 创建失败保留草稿；发送后断线且接受情况未知时不自动重发。先检查原生状态，避免同任务重复修改文件。 沿用当前最多两条活动任务的约束；未提出扩大并发。
10 · 运行状态 统一显示：启动中、就绪、执行中、等待用户、取消中、已结束、失败或状态待确认；保留原生原因。 未知不是失败也不是已完成；新一代连接不能接受旧一代响应改变当前任务状态。 用户用语为设计稿，不新增第二个 Agent 决策循环。
11 · 权限与提问 Agent 发起，Host 绑定到会话 / 任务 / 请求，前端显示原生选项，经 ACP 回答。 取消、退出或请求失效后旧按钮失效；不自动批准、不用普通聊天冒充原生提问。原生不提供的能力如实缺省。 必要能力由现有已接受行为表决定。
12 · 取消与中断 用户停止后显示取消中，直到原生终态或可核实退出；记录已发生的文件变化。 超时显示状态待确认，可提供结束自有进程的明确操作；取消不等于撤销磁盘修改。 建议规则；不同 Agent 的完成信号需对应。
13 · 事件与恢复 公共通道保留顺序、来源与连接代次；有界输出，断线后用真实快照和原生记录恢复显示。 发现缺口就标明并补读支持内容；不编造遗漏工具输出，不把持久化失败报成保存成功。 保留现有事件可靠性基础；替换原生解析。
14 · 产物审阅 工具卡片展示 Agent 上报，文件面板展示真实工作区差异并注明比较基线；只读预览与已审阅分开。 非 Git、未跟踪、大文件、二进制、冲突与外部编辑分别处理；未知归因不标成全部由 Agent 修改。 建议首轮只读预览 / diff；编辑、提交、撤销另行决定。
15 · 本机回调 按协商能力承接 ACP 文件与终端请求；校验路径和拥有关系，结束时释放自己创建的资源。 不支持则不宣告支持；输出截断保留提示；不能把 Host 观察或回调冒充对原生工具的完整沙箱。 依据所选适配器实际请求决定必做回调。
16 · 新会话续接 新架构产生的会话保存安装、项目、连接与原生会话引用；重启后重新发现并续接。 认证过期先恢复连接；版本或目录变化先解释原因。打不开不悄悄新建空白会话。 必须保留日常恢复能力；不要求迁移旧开发记录。
17 · 窗口与退出 建议应用内 Host；关闭窗口保留应用时可继续，完整退出先处理正在执行任务。 强退 / 崩溃 / 休眠后按未知状态恢复；不承诺完整退出后后台继续，不因此引入另一套控制中心。 关闭窗口是否默认后台继续仍为产品选择。
18 · 更新与安装失败 安装内容先暂存校验，再启用选定版本；Agent / 适配器更新与主应用更新分别管理。 失败保留当前可用安装，升级不影响活动进程；用户自行升级后重新校验。应用更新保护重要配置与新产生的数据。 不自动升级用户全局程序；更新建议不是本轮执行。
19 · 开发旧数据 本次切换不迁移开发旧会话；先列重要 Provider、端点、模型和必要设置，保留后验证可读取与可用性。 删除范围限制在明确的 Farfold 开发记录；不连带删除项目文件、独立原生历史或其他工具配置。 已对齐方向；本轮没有执行清理。

后续验证的完成标准：一次录入后每个兼容 Agent 确认实际连接与模型；断线不重复执行；待答请求不串会话；取消结果可确认；文件差异来源清楚；同一安装应用冷启动后恢复新会话；升级和清理不丢重要配置。这里列的是未来验证要求，不是已经通过的结果。

事项 结论 / 建议
已收紧的公共边界 一套客户端实现、多连接实例；Host 统一准入和身份归属，各连接保留原生能力及扩展。没有恢复三套 Farfold 原生客户端。
Pi 的候选选择尚未闭合 Registry 发布包符合复用本机程序，却缺少当前原生插话与部分扩展交互。优先查现成维护版本或推动适配器补齐；若选择维护适配器扩展，单独评估成本。不能悄悄删功能或改走原生旁路。
OpenCode 的取消必须闭合 本轮固定标签源码存在取消不支持路径。先选定并核实具有原生 ACP 取消的官方版本，再验证任务确实停止；若没有满足版本，报告接入阻塞。Farfold 不补一条 HTTP abort 旁路，也不修改 Agent 本体。
Codex 要冻结完整组合 已有权限、表单、插话扩展线索，但它们与当前旧二进制未证明兼容。需要固定 ACP SDK、适配器与 Codex 三者；只声明实际支持的表单和扩展。
配置归属有明确建议 Farfold 只写自己管理的连接配置；每个目标独立记录应用结果。已有原生登录可以保留独立来源，不做隐式双向同步。活动任务绑定旧配置，新配置在安全边界生效。
首轮范围保持克制 应用内 Host；只读文件 / diff 审阅；保留两条活动任务与工作副本互斥。完整退出不承诺继续工作。旧开发会话不迁移，保留重要配置；新会话恢复是必需项。

六个必须能解释清楚的失败场景

场景 要求的产品行为
发送后马上断线 先显示状态待确认，查询原生状态；没有证据时不自动补发。
等待授权时取消或切换会话 旧请求立即失效，回复不能落到另一会话；原生是否结束单独确认。
一个 Agent 改 Provider，另一个仍在运行 运行任务保持绑定配置；修改只在对应目标安全边界应用，显示每路结果。
外部编辑器与 Agent 同时改文件 diff 标明比较基线；不把所有磁盘改动归给 Agent，不自动覆盖外部改动。
升级失败或用户移动本机程序 旧可用安装保留；会话仍绑定原生身份；先修复启动引用，不伪造新会话恢复。
新会话冷启动恢复时缺少工具细节 恢复可读取内容，明确缺失范围；不把合成工具记录当作完整执行历史。

7 · 相比当前，真正要补的五组工作

  1. 协议层：增加共同 ACP 客户端，替换 Farfold 内三条原生工作通信与重复事件解析；保留仍需要的原生配置映射。
  2. 接入管理：把当前 Codex 的本机安装路径扩展成统一来源管理，补 Pi/OpenCode 的按需安装；同时管理适配器与依赖。
  3. 工作环境服务：把已有工作副本、文件引用与 Git 状态扩展为明确的文件/差异/终端服务，按 ACP 实际能力承接客户端回调。
  4. 工作台：补共同工具与产物展示、文件预览和逐行差异；已有路径审阅、侧栏和输入框可继续使用。专属操作继续按能力展示。
  5. 恢复与配置：现有身份、草稿、事件缺口、并发控制、迁移和备份是需要保留的基础；新接入不得绕过它们。Provider 跨 Agent 复用见新增的统一模型服务设计；仍需验证各接入包的实际配置作用域。

“覆盖清单完整”不等于“每项现在都要新增”。完整编辑器、交互终端、浏览器、Git 提交与撤销等属于可选择的工作台能力，应逐项确认本轮范围。跨 Agent 协作、LifeModel 和第四个 Runtime 不在本轮。

运行寿命

关闭窗口、退出应用、Agent 崩溃后分别发生什么？任务要不要继续，是 A/B 选择的主要依据。

先支持只读文件预览和逐行 diff，还是还需要编辑、提交与撤销？“审阅”与“应用修改”必须分开。

哪些原有账号可以复用？哪些 Provider 可以统一配置？选定哪版协议、SDK 和适配器作为兼容基线？
