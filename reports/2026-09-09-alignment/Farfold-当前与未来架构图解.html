先看哪些部分是可选的

任务交接与协作是两种候选增益，不要求先后实施，也不依赖 LifeModel。独立 LifeModel System 的来源贡献和上下文消费各自核验，正式模型写入始终经过用户批准。

从当前到未来

演进的是任务体验，保留的是执行权与数据边界。

维度 当前基础 未来可能方向
使用单位 一个 Farfold 会话绑定一个 Runtime 原生会话。 任务视图可以连接多个独立会话；原生会话身份仍不迁移。
工作连续性 标题、草稿、目录和原生 ID 续接，异常时明确恢复。 经用户选择，把目标、证据、文件和未完成事项交给另一 Agent。
任务组织 最多两条活动任务，同 Working Copy 排他；这是并发控制。 可选择组织者与参与者，明确分工、成果、冲突和停止条件；须另行验证。
个人理解 最简原型冻结、默认关闭；Codex 当前不贡献或消费。 承接独立 LifeModel System；贡献、用户审批、消费有独立边界。
接入扩展 Pi RPC、OpenCode HTTP/SSE、Codex stdio App Server。 未来适配器按官方能力选择接口，可能使用 SDK、RPC、Server 或 ACP；没有第四路实施承诺。

商业材料可以表达的价值

当前有依据的产品定位是：把多种 Agent 放进同一个可控制、可恢复的个人工作台。未来的价值假设是减少重复说明、跨 Agent 交接的返工，以及任务上下文切换带来的负担。

商业材料需要另外证明的部分

接入数量不等于用户价值或竞争壁垒。交接、协作和个人理解是否提高质量、节省时间，并足以覆盖额外费用，需要真实任务比较、用户留存与付费证据支持。
