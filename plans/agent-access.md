# Farfold 当前工作计划

更新：2026-10-09。**目标：把 Farfold 的能力做扎实，达到可面向市场用户、具备一线多 Agent 桌面工作台水准，再做必要的局部 UI 优化并交给用户试用。** 本文件是唯一活动计划；[PRODUCT.md](../PRODUCT.md) 是唯一产品契约，[当前状态](../docs/status.md)记录实际进展。旧六阶段及 UI 落地过程见[冻结原文](../docs/archive/2026-10-09-before-capability-hardening/plans/agent-access.md)，不作为当前操作顺序或测试授权。

## 1. 全量承接，不以整理缩减要求

2026-10-09 执行授权：用户明确要求持续开发，期间不使用 Farfold 并配合验证。必要的开发、检查、有界真实测试和正式应用更新持续推进；沿用已有明确选择的服务与模型，更新前核无活动工作、正常退出与数据保留。缺少账号、密钥或真实系统环境等具体条件时保留待办并继续独立工作。签名、公开分发及其他明确后置/排除范围不变，阶段提交不作为停止点。

[原始盘点](../docs/evidence/2026-10-09-host-capability-audit/index.html)共 **122 个唯一编号**：ARCH-01–ARCH-50、P01–P50、H01–H22。51 项源码具备、37 项部分具备、13 项缺少、8 项待实证、10 项范围待定、3 项明确后置/契约排除。

用户本次提到 112 项；122 减去 10 项范围待定确为 112，但 112 中仍含 3 项后置/排除。这只是数量核对，不能据此断定用户要删掉哪些内容。**全部 122 项都保留去向；109 项能力实现/验证逐项推进，10 项范围决定逐项落实，3 项后置/排除保持明确依据。** 盘点条目不等于缺陷数，也不能自动等同新增功能授权。

- 已明确的能力必须做到完整可用；不能只做入口、卡片、正常路径或写一句“不支持”就结项。
- 合并重复实现时保留每个原始 ID、各自完成条件与验证证据；共用测试只能覆盖它实际证明的条件。
- “源码具备”继续补缺少的实证；已测成功、已测失败、未测试和推断分别记录。未知或官方限制不算成功。
- 29 家八项标准逐格保留。官方 ACP 未暴露时继续核官方 SDK/CLI；真正没有官方方式的，写清具体缺口、已查依据和下一步，继续未完成，不降低标准。
- 本计划覆盖已知盘点，不承诺发现已绝对穷尽。开发和实际使用发现的新问题追加新编号，不改写原项来隐藏遗漏。

## 3. 工作包、责任与完成依据

“责任”是 Farfold 内的交付责任；故障归因另分 Farfold、协议/接入层、Agent、服务/认证、系统环境或未定位，不根据交付责任预判根因。

| 包  | 内容与责任                                         | 依赖及共同完成条件                                                                                             |
| --- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| A   | 发现、安装、账号与服务；接入层/认证/凭据模块       | 官方来源与作用范围可追溯；安装/切换/退出的取消、失败、未知保护完整；已选来源、真实身份与实际使用分开核验       |
| B   | 配置、模型与历史；接入层/元数据/共用配置界面       | 依赖 A；只采纳真实确认并保存的选择；模型生效、完整历史和继续原对话均有证据，不以新建替代恢复                   |
| C   | 执行、停止、恢复、并发；请求控制/进程管理/对话状态 | 依赖身份归属与 K 保存保护；同对话不重复发送、跨对话不串审批/停止，未知不自动重发；真实停止核到该请求的外部工作 |
| D   | 高级事件与官方能力；接入层/共用内容呈现            | 依赖 B/C 和官方能力核查；引导、压缩、分支、子任务等由 Agent 执行，结果与错误保真，不靠 UI 模拟                 |
| E   | 技能、工具与 MCP；接入层/共用管理                  | 复用官方配置与管理接口；列明启用对象、作用范围、可用状态和失败出口，不写 Agent 私有配置                        |
| F   | 输入、草稿、附件、命令；输入区/暂存                | 依赖 C/K；各种输入保真，附件可读性重核，切换和重启不丢内容、不自动发；真实 Agent 读取另留证                    |
| G   | 文件、差异、预览、意见、交付；内容栏/文件服务      | 依赖 F/K；内容、路径和版本一致，截断/权限/文件变化明确；保存打开与实际返工要核最终文件                         |
| H   | 内嵌网页及工具；浏览器/接入层                      | 依赖 C/K；页面范围、授权、撤回、取消和导航贯通；动作派发不等于生效，必须随后观察                               |
| I   | 历史搜索、整理与导出；索引/官方历史接口            | 依赖 B/K；检索范围完整说明，不自建正文账本；归档/删除/导出保护活动与未发送内容                                 |
| J   | 共用交互、通知、键盘和无障碍；桌面壳/共用 UI       | 依赖 C；成功、需要回应和失败可定位；系统实际送达/点击与应用内卡片分开验证                                      |
| K   | 数据、退出、诊断和安全；存储/进程/文件边界         | 贯穿所有包；存储故障保留可恢复内容，退出不误杀，诊断无秘密，破坏性验证只用明确专用对象                         |
| L   | 性能、资源与长期运行；前后端共享设施               | 首批建立测量基线，随后覆盖真实长内容、多任务及睡眠/断网；按测量制定上限并复验，不把受控夹具当实机性能          |
| M   | 工作树与并行目录；工作位置/生命周期                | 先核范围与设计，再依赖 C/K；建议基础创建、分支选择、已有工作树接入、安全回收；不自动升级为合并/PR平台          |
| N   | Windows；平台模块及同一 UI                         | 依赖稳定共用能力；本机路径、凭据、PTY、进程树、浏览器、通知与安装均实机留证，交叉编译单列                      |

每个条目的完成依据 = 下表专项条件 + 所属包共同条件 + 适用的产品标准。按风险覆盖正常、失败/拒绝、取消/未知、断连/重启、并发/共享资源、大文件/长对话、权限/凭据变化与平台差异；不机械要求无关组合，也不恢复已撤销的整组六条旅程门槛。

每次更新条目必须记录：实际改动及提交、Agent/模型/服务/系统与程序版本、验证种类、原始回执、通过/失败/未测、残余限制和下一步。证据可以共用，但不得超出实际覆盖范围。源码检查、夹具、协议探测、安装版、真实 Agent 效果分别记；文档整理不能把条目标成能力已完成。

## 4. 官方接口与范围决定的处理

29 家核查沿[首批名单](../docs/agent-first-release.md)逐项记录官方 ACP 声明、SDK/CLI 补充路径、语义/作用范围、实际接入、版本、证据及阻塞原因；在[现有跟踪数据](../docs/evidence/2026-10-09-host-capability-audit/agent-standard-coverage.json)所指证据基础上增量留证，旧成功/失败原文保留。原跟踪中的 232 个“本版未重新验证”不是 232 个失败。

- 官方客户端文件/终端回调不自动等于第二 Agent 循环；ARCH-44 先核具体需要、权限和生命周期，若必要且合规则落实，不以架构口号跳过。
- ARCH-47、H13–H15、H17 明确比较基础工作树方案、用户已有目录和共享配置/依赖/端口，形成可实施设计；不会仅写“复杂，待定”结项。现有契约不变更前，不擅自承诺文件系统隔离或代写 Agent 配置。
- H16 的自动合并/完整 Git/PR 管理、P29 的登录及敏感网页自动化、H22 的远程/定时/团队编排仍需明确范围结论。该决定必须处理，但范围决定不能冒充功能实现。
- H20 公开分发/签名/公证/更新渠道按用户要求后置；P50、H21 中编辑器、LifeModel 真实采集、多窗口、移动端、Linux 等按既有契约边界保留；不把其中与当前能力有关的普通数据保护一并推迟。
- 对标以 Harnss、Codeg 等同类多 Agent 工作台为主，终端/工作树型产品为邻近参考；不把某个 Agent 自家客户端或同行功能并集当唯一标准。同行公开宣称、源码与实际体验分别判断；已核资料见原审查报告，不继承其修改 Agent、独立 HOME 或自建事件账本的做法。
