更新：2026-09-20。阶段 6 的主体代码已落地，但产品出口未完成。旧计划及完成记录已完整归档到 [docs/archive/plans](../docs/archive/plans/)，不再在当前文件里并列多个执行入口。

产品要求以 [PRODUCT.md](../PRODUCT.md) 为准。当前实现、证据和缺陷分别见[源码架构](../docs/architecture.md)与[当前状态](../docs/status.md)。计划不是已完成能力的证明；不能改低产品要求来掩盖源码缺口。

### 00.1 保持的产品和工程边界

- 独立多 Agent 桌面工作台，当前为 macOS arm64 的 OpenCode、Codex、Pi；Farfold 不实现第二套 Agent loop。
- 一套界面，能力来自协议；Agent 保有认证、模型、工具、配置和历史；官方协议、SDK/CLI 接入，不维护自有 Agent fork。
- 连接按 command/args/env 与 initialize 判定，不校验已安装 Agent 的摘要；不私有 HOME、不 env_clear、不替 Agent 写配置。
- 元数据库只保存 Farfold 元数据，历史依赖 Agent；不恢复旧轮次账本、locator/generation 或旧专属 Panel。
- Agent 创建后固定；模型在草稿首条消息接纳前可选，接纳后固定，恢复立即固定。
- LifeModel 当前范围仅静态页与空注入接口；真实采集和注入不在本轮工作内。
- J1–J6 必须在可追溯的安装版上完成真人旅程；工程测试和历史截图不能代替。

2026-09-18 原决策与后续调整均保存在[完整旧计划](../docs/archive/plans/runtime-neutral-lifemodel-before-2026-09-20.md)。未复述的约束继续按产品契约与 AGENTS 执行；与当前源码不一致的部分已登记到状态页，不能默认视为批准例外。
