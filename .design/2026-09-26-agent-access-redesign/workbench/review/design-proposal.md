# Farfold 全产品改版方案 · 原型 07

2026-10-09。目标是让用户更清楚地开始工作、核对关键选择，并在中断后接着做。本轮覆盖全产品的信息结构、主要界面和可点击流程；交付位置仍是唯一的 `workbench` 原型，不新增第二套产品界面。

这份方案说明当前设计如何回应审查，不是正式产品修复清单。原型中的 Agent、账号、程序、文件、网页、模型请求与结果均为演示；不会安装 Agent、读取正式历史、访问真实账号或替换正式应用。

## 1. 依据与阅读方式

产品边界以当前 [PRODUCT.md](/Users/tw/Desktop/farfold/PRODUCT.md) 为准。旧 README 中“首发后模型与思考固定”“需显式断开”等内容不作为本轮设计依据：当前规则是同一对话固定 Agent 和服务来源，完成一轮工作后可按真实能力修改模型与推理；程序管理自动处理可结束的空闲连接。

本方案核对了 [Agent 区域说明](/Users/tw/Desktop/farfold/.design/2026-09-26-agent-access-redesign/workbench/review/agent-redesign.md)、[对话区域说明](/Users/tw/Desktop/farfold/.design/2026-09-26-agent-access-redesign/workbench/review/conversation-redesign.md)、[设置与历史区域说明](/Users/tw/Desktop/farfold/.design/2026-09-26-agent-access-redesign/workbench/review/settings-library-redesign.md)、当前组件与 [导览映射](/Users/tw/Desktop/farfold/.design/2026-09-26-agent-access-redesign/workbench/src/redesign-map.js)。以实际组件提供的操作判断原型覆盖，映射中的建议文字本身不算实现。

审查基线为 [全量画册数据](/Users/tw/Desktop/farfold/docs/evidence/2026-10-08-ui-coverage-audit/full-review/all-pages/data.json)：134 张证据图，包括 49 张原安装版图及历史、受控状态和补充图；归纳为 24 类界面、31 项已观察问题与 19 项待复验风险。**134 是证据图数，不是独立页面数；50 项也不都是已确认 bug。** 受控状态只能说明其呈现，不能证明真实请求曾执行。

本轮进一步补齐此前明确列出的五类原型缺口：对话与消息菜单、长命令、多附件折叠、通用附加配置和提醒。这里的“已补齐”指可点击设计与模拟状态，真实能力与目标系统验证仍单列。

下文使用三种覆盖标记：

- **交互**：当前原型已有可点击入口及状态变化。只证明原型行为。
- **部分**：已提供一部分呈现或流程，原问题的全部条件尚未覆盖。
- **方案**：保留明确设计，尚无对应完整交互或真实系统能力。

从顶部“改版导览”可按整体方向、六条流程、F 编号或 24 类界面进入。导览按钮通常打开对应工作区，再按下文路径进入子界面；它们不是逐项问题的自动复现按钮。系统与退出两类只打开边界说明。

## 2. 五个工作主面与彼此关系

不另建首页，也不让用户先管理项目才能开始。左栏保持稳定导航；对话中的正文与右侧内容栏属于同一段工作。搜索、设置确认、权限和文件选择都是主面上的辅助界面。

| 主面       | 用户在这里完成什么                                     | 常驻上下文与主要动作                                            | 与其他主面的关系                                                                  |
| ---------- | ------------------------------------------------------ | --------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 新对话     | 先写想法，再决定交给谁、用什么设置、在哪里工作         | 文字、附件、Agent、服务、模型、推理和工作文件夹；主动作是“发送” | 缺少接入条件时进入 Agent 准备，结束后回原草稿；首条消息被接纳后进入对话           |
| 对话       | 看回复、处理审批和问题、安排待发、停止与恢复、查看成果 | 原 Agent、服务和工作位置；状态与下一步紧邻输入区                | 右侧打开文件或网页；从库或搜索回到原对话；设置修复结束后回原位置                  |
| 对话库     | 找回、辨认、整理和接续工作                             | 搜索范围、筛选、位置、更新时间、未发与归档状态                  | 打开具体对话；从“带入已有对话”查找 Agent 历史；分组不改变工作文件夹               |
| Agent 中心 | 发现、准备和管理 Agent                                 | 目录身份、程序、账号与服务、模型及当前准备状态                  | 新接入返回原任务；日常管理使用全局管理上下文，不继承某段对话的编辑限制            |
| 设置       | 管理应用偏好、API 服务和维护操作                       | 通用、API、LifeModel；数据范围和不可执行原因                    | API 保存后还需在 Agent 中明确选用；通用设置中的按位置暂停不妨碍处理已有审批或停止 |

“我的 Agent”提供管理入口，“探索 Agent”服务于发现与添加。两者共用目录与设置组件，区别是当前任务语境，不另造品牌专属页面。当前目录展示 29 项身份；10 个代表条目沿用能力样例，其余 19 项保持能力未提供，不从目录存在推导登录、历史或模型已可用。

草稿、接入准备和已有对话各自保留返回位置。全局管理清除从某段对话继承的工作位置及选择上下文；从对话发起的修复则保留那段对话的精确选择。导览补充对话、分组和服务示例时保留已有同 ID 记录，只有仍与首次使用基线完全相同的 Agent 才补入准备样例，已移除、已修改及准备中的状态不覆盖。

顶部“载入示例”仍是需要确认的整体演示替换，与导览按需补充是两种操作。“重置演示”也单独确认。重启演示用于恢复当前浏览器保存的样例，不发送消息，不代表操作系统退出或 Agent 停止已验证。

## 3. 六条完整体验路径

以下六条是本次设计的体验路线，方便按用户目的评审；**不是恢复已撤销的旧六旅程验收门槛**，也不自动增加真实账号测试或其他机器安装要求。

### 路径 01：从想法到第一条消息

入口：左栏“新对话”，或导览“从想法到第一条消息”。

1. 先写文字、加入示例附件；没有工作文件夹也可以保留草稿。
2. 命令列表可搜索名称和描述，包含长名称、长描述及多条目样例；选择只填入输入，不执行。多附件默认显示前三项，可展开全部并核对完整位置。
3. 选择 Agent。已有内容时切换 Agent 先对比原选择和新选择，确认后保留文字、附件和位置，不发送内容。
4. 在同一选择层核对服务来源、模型和推理。缺少准备条件时前往程序／账号与服务／模型，取消、暂离或完成后回原草稿。
5. 从“更多设置”查看当前来源声明的附加项；已声明说明、范围和时点分别展示，未提供保持未知。可交互样例覆盖确认保存、失败保留旧值和未知暂停发送。
6. 发送前选择工作文件夹；发送前可以更换或移除。取消选择回到原草稿，选完后仍由用户点击发送。
7. 首次请求接纳后进入对话，固定 Agent、服务和工作位置。失败、未确认结果与附件待核对时保留原输入并给下一步，不制造成功对话。

原型已提供这些状态的演示。系统文件选择、附件实际可读性和真实首发结果仍需在正式实现验证。草稿网页只在有准备好的 Agent 与位置后打开；导航暂离保留页面，改变 Agent、服务或位置撤回原许可。

### 路径 02：接入与日常管理

入口：“探索 Agent”，或“我的 Agent”旁的管理入口。

1. 搜索并查看目录身份和能力依据；未提供能力明确显示未知。
2. 首次使用按程序、账号与服务、模型完成准备，步骤可跳转查看，缺前置条件说明原因。
3. 账号与服务优先沿用已有设置；进入后检查是否需要登录，明确需要时才提供当前声明的方式。账号授权、终端登录和 API 密钥使用中文类型标签，官方名称保留为次要信息。
4. 选择来源与模型后对比进入时的值和本次选择；确认后返回原任务，不自动发送。登录结束、身份信息、模型列表和实际请求可用性分别表达。
5. 已有接入从“管理设置”直达分区。更新或更换程序先说明当前与候选；失败、取消或结果未知保留旧选择。移除接入与可选卸载在一个明确范围的确认中完成；闲置受管理旧版本也可单独卸载。

所有安装、认证、检查和卸载均为模拟。真实取消是否已结束、账号退出能力、版本归属以及每一家 Agent 的可用方式，仍由官方接口和正式回执决定。未核实的注册渠道不编造专用网址。

### 路径 03：推进一段工作

入口：导览“推进一段工作”，或打开对话后使用底部“原型场景”。

1. 阅读回复与步骤，普通过程可折叠；审批和问题保持可见并列出对象与范围。
2. 在工作中补充文字会加入待发；队列总数只在标题显示，每条使用序号。编辑、排序、删除与暂停各自有入口。
3. 消息菜单提供“编辑后追加为新消息”和“再发一次”；两者先放入输入框，确认后才发送，原消息和回答保留。原有输入和附件先暂存，取消或追加后可恢复。“从这里开新对话”只带入所选消息文字与附件，不冒充恢复原上下文。
4. 停止区分已发送请求、等待确认、明确失败与结果未知。未知先检查原请求结果，不重复提交工作；草稿和待发始终保留。
5. 恢复原历史后核对原模型与推理；需要时就地重新确认权限。恢复、权限确认和继续待发是三个动作，前一步成功不会自动完成后一步。

同一对话首发后，输入区持续提供模型、推理及附加配置入口。附加项按声明展示，未知类型或未确认可变的项目只读。确认保存成功才更新配置，失败保留旧值，未知暂停发送；忙碌、审批和停止待确认时仍可查看，但不能更改。原型可切换成功、失败、未知和持续等待，重启后未完成保存转为未知；这些模拟不证明真实停止、恢复、设置回执或权限生效。

### 路径 04：查看和修改成果

入口：导览“查看和修改成果”，或对话右上文件／网页入口。

1. 从原对话打开文件列表或网页内容栏，正文与任务上下文持续可见。
2. 文件分别保留加载与失败状态。一个文件失败可重新读取或回列表，其他文件仍可查看。
3. 核对文件版本再写意见；旧意见保留原文件版本和位置。意见回到原对话，由用户确认发送，再查看修改后的版本。
4. 网页打开默认不分享；实际产品应由原对话中的真实工具请求触发单页只读许可确认。原型提供独立的确认演示。
5. 收起或任务导航保留网页；换页、关闭或连接结束撤回旧范围。撤回不声称删除 Agent 已收到的内容。
6. 对话操作中“在访达中显示工作位置”展示路径、等待、成功或失败与重试；没有位置时说明原因。这里只演示结果，不打开系统访达。
7. 对话操作中的“导出 Markdown”准备当前已展示消息的快照；准备中可取消，失败可重试，准备好后再点击下载。下载的是带有原型标记的本地示例文件，不包含隐藏历史、草稿和待发。

文件、差异与网页均为样例。对话导出通过浏览器下载本地 Markdown，准备结果仍为演示。真实磁盘核实、另存、默认应用打开、HTML 页面存档、网络和真实工具调用仍是正式实现边界；不能据此宣称安装版导出故障已修复。

### 路径 05：找回并接续历史

入口：“搜索对话”“所有对话”“收藏”或库中的“带入已有对话”。

1. 全局搜索只查元数据，结果显示时间与位置；对话内查找只查已展示正文，逐处高亮并提供上／下一处。
2. 在库中按 Agent、分组和状态筛选，活动、未发、待回应、进行中、新回复与归档分别辨认。
3. 收藏、重命名、移动或归档。对话页菜单也提供“移到分组”和“删除对话”；移动先看对象及当前分组，再选目的地确认，分组不改变原位置与 Agent。
4. 删除或清空当前归档范围先核对具体对象；运行、未知结果、待发及未发内容受保护，不能悄悄跳过部分对象再显示全部完成。
5. “相同设置再开一段”准备一个新草稿，原草稿先保护；原 Agent、服务身份或模型不完整时重新选择。已有来源地址或格式变化不能静默沿用；这一步不自动发送。
6. 带入历史时搜索 Agent，查找并预览正文，按条区分“列出了历史／正文可看／允许继续”。只读可重新检查，未知仍只读；部分失败保留失败项选择，已加入的项不重复加入。

原型删除只改变演示任务；真实 Agent 历史删除、正文获取、原上下文恢复以及继续能力均未验证。不能以找到列表或显示样例正文判定历史真正可用。

### 路径 06：维护应用与服务

入口：“设置”，或导览“维护应用与服务”。

1. 通用设置按外观、对话整理、更新与诊断、数据与隐私分组，页内索引直达。
2. API 服务先保存到目录，再由 Agent 明确选用。地址或格式变化显示原值与新值；旧密钥不能自动发送到新目标，新增和编辑的放弃提示各自说明范围。
3. 更新有检查中、无通道、失败、当前版和新版状态；无通道提供原发布渠道手动更新步骤，不捏造下载链接。
4. 诊断先选范围和填写问题，再按类别预览实际将包含的样例内容，最后确认导出结果示例；可返回修改。
5. 提醒与声音开关保存原型偏好；权限演示区分尚未请求、已允许、被拒绝和不可用，取消不等于允许。拒绝后可查看系统设置指引并模拟返回重查；测试卡片按具体对话定位，状态已变时提示，目标已删除时不打开其他对话。
6. 清除数据与卸载说明分开。清除前列出删除和保留范围，有未结束工作、结果未知或保存失败时阻止继续。退出及外部系统交接另用边界说明呈现。

提醒卡片仅显示在本页；原型没有真正清理数据、写诊断文件、更新软件、申请系统通知权限、播放声音或发送桌面通知。LifeModel 继续保留未启用说明。API 帮助提供步骤与控制台内容示例，真实服务获取渠道尚需逐家核实。

## 4. 视觉层级、状态词与主动作

### 统一视觉层级

白色主工作区、浅灰侧栏与分隔、深灰主动作构成默认视觉。颜色主要服务于状态：绿色表示已有确认的结果，琥珀色提示等待处理，红色提示失败或危险操作，不用颜色单独传递含义。深色主题使用同一层次关系。

共享样式将正文基础设为 14px，常规按钮 13px，主页面标题约 27px，新对话主标题约 34px；辅助信息保持较轻层级。常规按钮至少 36px 高，导入分页入口单独扩大。输入区使用圆角容器，模型、推理等常用控件靠近发送；工作位置持续可见。窄视口通过换行、独立滚动及内容栏布局调整保留主操作，具体显示效果以统一浏览器 QA 为准。

信息按“结论 → 下一步 → 依据”排列。来源与模型对照、数据删除范围和审批对象不能藏到用户无法作决定的位置；路径、版本详情、技术信息和诊断明细按需展开。弹窗固定标题及页脚，正文独立滚动。

### 状态与动作配对

| 可见状态             | 用户现在能做什么               | 不能从该状态推导什么                 |
| -------------------- | ------------------------------ | ------------------------------------ |
| 未完成设置           | 继续准备、查看缺少条件         | 不表示完全不可用或必须登录           |
| 可以使用（原型样例） | 回到草稿，明确发送             | 不等于真实账号、额度及全部模型已验证 |
| 需要批准／需要回答   | 核对对象后批准、拒绝或提交回答 | 不表示请求已经执行                   |
| 进行中               | 看过程、加入待发、停止         | 不能更改会影响当前请求的模型或权限   |
| 停止中               | 等待回执，保留草稿             | 不等于已经停止                       |
| 结果未知             | 核对原操作、回到待处理事项     | 不自动重试、重发或写成成功           |
| 只读                 | 看正文及原因，按能力重新检查   | 可看正文不代表能继续原对话           |
| 尚未提供             | 查看解释或保留当前选择         | 不伪装成可切换的关闭状态             |
| 已保存／尚未选用     | 在 Agent 中明确选择服务        | 不把保存当作授权分发或实际请求通过   |

每个决定区域优先保留一个明确主动作；返回、取消和暂离用次要按钮。危险动作使用具体对象和动词，如“确认移除接入”“确认卸载旧版本”；禁用时在附近说明原因，并尽可能提供前往相关对话的入口。保存待发不用发送箭头，追加消息不称改写历史，分组不称工作位置。

可访问性以共享语义支持为基础：图标按钮有名称，当前值与键盘焦点分别呈现；弹窗保留标题、初始焦点、Tab 循环、Escape 和焦点返回；页签仅一个选中项并支持方向键。上述代码支持不等于已经通过完整键盘、读屏、缩放或对比度验收。附件折叠已提供 `aria-expanded` 与 `aria-controls`，仍需正式应用中的实际读屏核验。

## 8. 建议如何分批进入正式实现

建议现在进入分批改版，同时优先修复会丢内容、误用来源或长期卡住的功能故障。视觉调整与状态可靠性共用同一批入口交付，避免只换外观后继续保留关键断点。19 项风险作为补验清单，不直接转成 19 个确认故障。

| 批次                  | 正式实现范围                                                                                                              | 进入下一批前需要的证据                                                                                         |

| 2. 关键工作闭环       | 文件读取与导出终态、来源与模型比较、停止／回答未知、权限恢复、待发管理；先解决 F03／F04／F05 的真实失败原因，再替换呈现   | 对应接口与失败路径有结果；成功、失败、取消及未知都保留正确上下文；模型与 Agent 实测依用户条件安排              |
