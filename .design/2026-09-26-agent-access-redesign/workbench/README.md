## 范围与事实来源

原型用于评审页面、对象关系、返回路径及模拟状态。全部 Agent、安装、账号、模型响应、文件和历史内容均为演示，不读取正式配置、凭据或历史，不安装 Agent，不发送真实模型请求。

产品要求以 [PRODUCT.md](../../../PRODUCT.md) 为准；[活动计划](../../../plans/runtime-neutral-lifemodel.md) 安排完整增量落地；[当前状态](../../../docs/status.md) 记录真实实现、安装验证和未完成项。原型操作、状态测试与正式产品验收分别判断。

## 接入、登录与注册

首次准备与日常管理共用能力和状态，入口服务于不同任务：

1. 程序：已有程序添加并连接；缺少程序则先安装。候选失败保留旧选择，断开、移除和卸载分别处理。
2. 使用方式：沿用本机设置、登录账号或选择 API，按当前能力呈现。认证是缺少条件时的动作，方法存在不等于必须登录。
3. 账号：按账号提供方进入注册或登录；外部步骤返回、登录结果、权益与模型可用分别判断。注册返回后继续登录，不能仅因返回就记为授权成功。
4. 确认：核对来源与模型，可显式发起短测；完成准备回到原稿，不自动发送。已有设置不被统一强制要求登录或短测；明确认证失败和结果未知仍需处理。

- 单方式直接操作，多方式先选择；账号、模型和程序使用共同层次。不同 Agent 的方式取决于能力，不能按品牌虚构支持。
- 首次打开只发现本机程序，不自动添加或连接。未完成首次接入时，“准备使用”和设置图标都进入同一三步向导；只连接程序仍显示“继续准备”，明确确认使用方式与模型后才能开始新对话。账号未知不等于需要重新登录，连接成功也不等于模型请求已经验证。
- 首次打开与“重置演示”使用相同起点：无已添加 Agent、无示例对话、无预选来源。已连接条目和示例对话仅由“载入示例”确认后载入；“重启演示”保留当前内容，未完成操作的结果仍需确认。
- 三步接入在连接、登录、API 选择和确认阶段均可暂离。未完成时显示“继续准备”，从卡片、设置或新对话选择器重进会恢复对应步骤和选择；完成接入后才进入日常管理。已有对话与导入保持各自的返回路径。
- 首次接入完成记录与当前配置状态分别保存。已完成的 Agent 重新连接或调整账号后仍可使用日常管理；缺少完成记录的旧状态会继续准备，不把“已连接”自动视为已完成。
- 暂离不等于取消。等待中的认证可找回；取消需要结束确认，迟到结果不能改写后来的选择。
- Agent 自己的服务设置返回不证明账号、模型或额度已验证。设备码、终端、授权和权益样例不能当成真实接入能力。
- API 保存不自动选用；兼容性在选用处检查。修改地址或接口不能自动把旧密钥交给新目标；旧对话保持原来源和模型。
- API 地址校验在字段旁说明错误，保存区说明当前缺少的条件；修正后即时更新，不要求先测试才能保存。
- 从已有草稿、管理页、历史或其他入口准备后，返回各自上下文；应用新选择前处理已有草稿冲突。
- 明确要求登录时直接进入该 Agent 的账号步骤，保留原来源、模型和思考选择；API 来源补 Agent 登录仍保留原 API 服务。
- 未结束的运行、审批、提问或结果未知会保护账号变更；账号页列出具体工作并可逐项打开。处理后返回原账号步骤，多层往返分别保留，恢复不自动发送。纯草稿和待恢复记录不会单独阻止登录。
- 注册准备与执行认证分开：可查看注册说明，继续登录仍需检查未结束工作。不能仅因打开注册或返回页面就视为登录成功。
- 对话中的检查入口直接打开对应 Agent 的账号、模型或程序页，显示来源问题并返回原对话；已有对话的来源、模型和思考保持只读。设置里的账号入口默认显示已添加的 Agent。

## 思考、权限与工作位置

- 思考深度位于输入框内、模型旁。草稿按能力提供选择；首次接纳后保持固定。无能力时不制造选项。
- 资料文件夹表达工作位置，不是文件访问权限边界；分组只整理对话。
- Agent 权限位于输入框工具栏，由当前能力样例驱动。工作模式、一次审批和全局权限分别表达。
- 权限扩大先确认；只有模拟成功回执后才更新值，失败保留旧值，未知暂停发送。界面的恢复动作仍是模拟，真实恢复能力以产品契约与真实证据为准。
- 运行、审批待处理、停止未知或恢复未完成时保护相关变更。权限变化不改原 Agent、来源、模型与思考选择，不自动继续待发队列。
- 按位置暂停后续发送属于通用设置高级管理。恢复不会自动发送；草稿和队列保留，已有审批与停止仍可处理。

## 草稿、对话与恢复

- 未发草稿不占历史；一次请求不是整段对话。首次消息接纳后固定 Agent、来源、模型与思考选择。
- 各 Agent 和各段对话保持独立；操作保护只影响相关工作，不设全产品的单操作锁。
- 停止确认状态固定在输入区附近；等待时显示“停止中”，未知或发送失败时提供“重试停止”。未知结果继续暂停发送，确认后保留草稿和待发消息，不自动续发。
- 导航保留未发送内容、文件意见与设置草稿。历史恢复保留原选择，不套用目录中的新默认值。
- 已有历史查找区分列表、正文和可继续能力；不支持、失败或缺少位置时如实呈现，不制造空白成功历史。
- 本浏览器保存模拟草稿、待发内容、文件意见、归档及工作开关。重启不自动发送，中断结果需确认，附件需核对。

## 目录与运行

- `index.html`、`src/main.jsx`：唯一页面入口。
- `src/`：当前工作台与模拟逻辑；`public/`：当前资源。
- `tests/`：对应状态和组件检查；`vite.config.mjs`：运行和打包配置。
- `dist/`：当前源文件生成的打包输出，可重新生成。

在仓库根目录运行：

```sh
node node_modules/vite/bin/vite.js .design/2026-09-26-agent-access-redesign/workbench --config .design/2026-09-26-agent-access-redesign/workbench/vite.config.mjs
```

验证当前原型：

```sh
node --test .design/2026-09-26-agent-access-redesign/workbench/tests/*.test.mjs
node node_modules/vite/bin/vite.js build .design/2026-09-26-agent-access-redesign/workbench --config .design/2026-09-26-agent-access-redesign/workbench/vite.config.mjs
```

使用仓库现有依赖。原型的 React 状态与计时器只服务于交互评审，正式落地仍复用现有统一界面、元数据、官方接入及认证链路。
