### 00.3 实施阶段、依赖与阶段出口

执行顺序：P0 → P1 → P2 → P3 → P4 → P5 → P6。P1 若被官方兼容性阻塞，可以继续不依赖新版本的 P2–P4；不得因此宣布整体验收完成。每阶段先做针对性工程检查，再在安装版走对应旅程；最终 P6 使用同一最终候选统一复验。

#### P0：冻结基线，准备可恢复的验收环境

1. 核对当前 HEAD、未提交差异、应用身份、实际启动命令、两层版本和已有测试会话；只记录非敏感字段。保留原验收和原始失败证据。
2. 明确本轮测试项目及创建的文件/会话范围。按用户 2026-09-21 的最新要求，本机只保留 `/Applications/Farfold.app`，更新直接替换，不再保留旧应用或独立 Dev/Test/QA 应用。保存源码和验收证据，不复制凭据到证据目录。
3. 普通回归复用现有账号。全新安装/未登录分支使用真实独立 macOS 测试账号或测试机器及其正常 HOME；不改 HOME 环境模拟“干净用户”，不退出日常账号、不删除其历史或凭据。
4. 将需要测试账号、登录操作和现有权限策略才能触发的分支列为前置条件。条件未具备时继续其他工作，相关分支保持未测。

出口：可追溯基线、准确的测试范围与恢复点齐备；不触碰应用源码和用户配置。

#### P1：验证官方 Agent 与接入包的兼容组合（B1/B3）

1. 执行时检查官方发布说明和包声明，找出支持现有 Codex 模型以及 Pi 完成事件的候选组合；不在本计划中猜测最低兼容版本或声称某个“最新版”必然可用。
2. 先记录候选来源、版本、实际命令及替换范围。现有 R1–R7 授权不等于任意全局升级；如需改用户共享 CLI，明确该具体变更的影响及恢复方法后再执行已获授权的范围。本轮规划不执行升级。
3. 在已登记或用户明确配置的命令上，用当前账号和当前模型做最小真实请求，观察完整回复、prompt 结束响应、取消响应、new/load 及进程退出。CLI 与 ACP 分层比较，只重跑能区分原因的实验。
4. OpenCode 保持现状作为对照。记录 Agent 和接入组件的各自版本，不 pin 版本，不新增按版本放行的兼容白名单。
5. 找不到符合边界的组合时，保存精简复现与官方缺口；继续 Farfold 侧修复。禁止修改第三方包、吞掉错误、改模型或用另一条执行链伪造通过。

出口：Codex 在 6 Astra/high 下请求成功；Pi 在既定模型下正常完成且能确认取消；各自可恢复续发。协议检查合格后仍需安装版 J2/J5 证据。若任一项失败，则 B1/B3 保持阻塞。

#### P2：统一失败语义，修复“失败却已完成”（B2）

主要入口：`acp_client/manager.rs`、`pump.rs`、`src/runtime/sessions.ts`、`session_types.ts`、`queue.ts`、`strings.ts`。

1. 在 `acp_client` 内实现接入包公开的结构化失败扩展，再声明相应客户端能力。覆盖 prompt 响应元数据以及 `session_info_update` 中的失败信息；校验形状、严重程度与归属，保留原始事件和未知字段。
2. 向统一状态层输出通用失败语义，不把外部扩展名称带进组件。终止性失败优先于普通 end_turn；警告不能自动终止；取消、拒绝、长度限制、未知或缺失原因分别按实际含义呈现，不能统一算成功。
3. 失败时保留已收内容和待发消息，暂停队列；用户明确恢复后才继续。结果未知不能自动重发。旧通道/旧请求的迟到错误不能污染新请求。
4. 不扫描任意 Agent 正文中的 error/JSON 等文本来判断失败，也不把所有服务错误都归成“请升级”。无法结构化判断的事实保留未知。
5. 对实际模型不兼容场景复验：既看到易懂失败提示，也能证明没有成功标记和额外自动发送。

工程检查：终止元数据＋end_turn、会话更新错误、警告后正常完成、取消与失败竞态、未知结束原因、旧事件、失败后队列与手动恢复。真实错误路径至少保留一例，工程模拟只补不易安全触发的竞态。

安装出口：J2 的成功与失败状态准确，J4 的队列和侧栏准确，J5 的续发失败可理解且不会丢历史。

#### P3：停止未确认与恢复（B4，兼顾 R3/R4/R6）

主要入口：`acp_client/session.rs`、`pump.rs`、`manager.rs`、`sessions.ts`、`queue.ts`、统一会话与侧栏组件。

1. 区分“停止请求已送出”和“Agent 已确认停止”。收到匹配的 cancelled 才显示“已停止”；正常结束与错误按其真实结果处理。
2. 以用户点击停止为起点设置 30 秒确认期限，采用内部常量，不新增环境开关。期限仅判断停止未确认，不限制正常长任务；到期显示“结果未知／尚未收到停止确认”，进入“需要你”并提供恢复操作。
3. 未确认期间和到期后都保留内容、审批及待发消息；仅在明确失效时撤销审批。不假定外部任务已经停下，不自动重发、不允许在同一未解决请求上重叠续发。
4. 恢复优先使用现有官方恢复路径。一个连接承载多会话：不能为了一个会话强制关闭其他运行任务。确需断开共享连接时，先明确受影响会话，由用户选择该操作；不能默认自动杀共享进程。
5. 恢复失败保留原内容并可再试；成功后核对历史和模型。迟到结束只能结算一次；旧通道事件隔离。无法确认前次结果时保留未知标识，不能仅因重连成功就放行待发消息。
6. 项目工作关闭后，新建/续发受限，已有任务和审批可继续；重开后队列仍需手动继续。核验有未处理审批/表单或在途请求的连接不会被空闲回收。

工程检查：无取消回执、迟到/重复回执、断线、恢复失败再成功、共享连接、关闭工作开关与队列。使用可控时钟测试期限，不用长睡眠替代状态验证。

安装出口：J4/J5 中可重现的停止、断线和恢复都有诚实出口；不会永久卡住或误称停止。真实 >30 分钟待办存活留到 P6，不能用虚拟时间测试替代。

#### P4：模型恢复、版本与界面校正（B5/B6）

1. **模型恢复**：沿 `session/load → 官方恢复响应 → configOptions → 现有索引比较 → 续发准入` 核对真实模型来源。使用现有元数据，不增加一致性账本。恢复前后的实际模型和推理等级均应保持；界面只读不能代替真实行为。
2. 对不一致的恢复结果，在前后端阻止静默续发，并清楚显示记录值与实际值。优先寻找官方保持原模型的恢复能力；不得在已建立会话偷偷调用改模型来“修正”。原模型未知时不得编造旧值。
3. 若官方恢复本身不能保持模型，提交明确契约冲突和复现；保护性阻止续发只能算缓解，B5/J5 不能关闭。额外模型差异实验使用测试会话，不修改日常默认模型。
4. **版本**：区分实际 Agent 版本与接入组件版本，来源不明显示未知。统一数据字段和能力驱动显示，避免把 codex-acp 版本当成 Codex CLI 版本；不新增固定版本兼容门槛。
5. **错误与外部说明**：集中中文应用文案；目录说明、后端错误与结构化启动通知转为易懂摘要。原始事件保留在现有内存通道，不新增正文日志。不能用通用正则删除正常回复、Skills 内容或路径。
6. 外部启动信息若被当成普通正文且没有可可靠区分的信号，先核对官方结构化能力。若“外部正文保真”与“任何可见字符串禁词”仍冲突，在状态页明确报告，不擅改 PRODUCT，也不以粗暴过滤关闭缺陷。
7. **历史时间**：核对 Agent 是否回放原始时间。存在则正确使用；不存在则不将恢复时刻冒充原消息时刻，不写回 Agent 历史。

工程检查：草稿可选、首次接纳/未知结果后锁定、恢复立即只读、真实值不一致禁止静默续发、未知原值、版本来源、受控文案及回放时间缺失。

安装出口：J1 版本含义明确；J2/J5 显示与真实模型一致；错误路径无应用自造工程文案。B5 必须有保持实际模型的成功续发证据。

#### 00.8.4 关键设计约束

**W1/W2：可测的性能与行为保真。** 在 W0 固定机器、候选、窗口尺寸、数据量及操作序列；至少覆盖单会话长文本、两会话同时输出并切换、长历史中输入/滚动/审批三组负载。测试回放可以用于可重复性能对照，另以真实 Agent 验证执行语义，二者不能混称。

优化前记录输入响应和切换耗时的 p95、长任务/帧耗时、应用内存与线程数量；固定采样方法和预算后再比较，目标先按输入响应 p95 ≤100ms、切换已有会话 p95 ≤200ms 设计。负载规模与预算须在 W0 写入证据，若测量条件不支持则说明限制，不在看到结果后降低标准。未达项继续定位，不用“感觉流畅”或单测绿替代；无实测不宣称性能提升。关键约束：

- 真正阻塞的 SQLite、Keychain、文件或系统调用仍需合适的隔离；不机械删除所有 `spawn_blocking`，不持同步锁跨 `await`。项目工作开关与新消息接纳之间仍需保持原子性。
- 超时不意味着请求未送达；保留未知结果、迟到响应、停止确认和队列暂停规则，不自动重发。
- 只合并显示层文本通知，保留原始事件与顺序；审批、错误、结束及时处理，结束或切换前冲刷待显示内容。窗口后台节流不能使状态与队列停在旧值。
- 会话订阅须有正确的快照身份与通知；后台会话只更新相关正文和必要汇总，不能因优化漏掉侧栏待办、token 或状态。

**W3/W4：能力保留与恢复出口。** 以同一 Agent、项目、模型和配置做官方直接使用与 Farfold 对照；MCP 至少验证一个实际已配置工具的发现和调用，并分别覆盖新建与恢复。没有可用 MCP/Skills 样本时明确未测，不修改日常配置制造通过。官方声明、静态源码、真实调用、安装交互分层记录。

Farfold 丢失已声明事件或能力时在现有模块修复；外部官方接口缺口记录复现、影响能力与复验触发条件，提供诚实出口，不增加 Agent loop、代跑工具或自动搬运 Agent 配置。非标准公开扩展在 `acp_client` 内解析并保留未知字段，不把包名或扩展判断散入组件。J5 新会话出口显示实际模型，允许用户在新草稿发送前选择；保留旧会话和待发内容，不承诺继承记忆，不偷偷修正旧模型或推理等级。

**W5：安装对象与失败闭环。** 三分支是用户入口，底层状态要区分未发现、已发现待连接、安装中、连接中、连接失败、需认证、已连接与请求可用。只有可靠的协议或结构化错误证据才能判为兼容性问题；模型错误、认证失败和网络错误不能统一归为“请升级”，版本号不作为固定准入白名单。

本轮实施选择：更新前要求用户显式断开该 Agent，后端再次检查，不自动中断已有任务。每次安装使用自身目录内独立暂存目录，成功后才写入新启动目标；保留上一个启动目标供回退，凭据配置保持原值。Codex 接入包自带执行程序，可由用户选择使用；Pi 接入包未包含执行程序，保留选择已有程序及官方安装指引，不把只更新接入包显示为已更新 Pi。安装进度以真实阶段呈现，下载可报告字节；不可测阶段不伪造百分比。

- 为三 Agent 分别记录发现目标、接入包、实际执行程序、来源及版本，说明本次“装新版”改变哪一层。现有 CLI 不兼容时，仅在官方分发和启动方式支持时使用自身目录中的替代版本，验证没有再次选中旧路径；否则提供显式选择已有程序或官方安装指引，保留一键更新缺口。
- 不执行项目目录提供的启动指令；不 fork/patch 第三方包。专属协议处理留在 `acp_client`，安装差异用既有 catalog 声明与通用安装流程表达。
- 下载、校验、安装、连接分别呈现进度；不可测百分比时用阶段状态。提供取消与重试；取消后不启用半成品，仅清理本次明确创建的暂存内容。下载摘要沿用 registry 声明，不校验用户二进制 SHA。
- 新安装准备完成后再切换，失败保留原配置和可用安装；不因更新中断运行中任务或审批。需要重连才能生效时说明影响，由用户操作；验证既有登录、配置和历史继续可用。

**W6：凭据身份、授权与生效。** 先为三个 Agent 列认证方式、实际声明、env 或显式配置入口、已有登录复用、真实请求结果。不能将保存成功、命令退出或打开网页显示为模型可用。

实施状态：设置页提供独立密钥列表、创建/替换、逐 Agent 与变量授权、冲突来源确认、撤销与删除；现有单 Agent 输入继续保留。密钥保存不自动断开连接或宣称登录成功。声明缺少变量时用户显式填写；服务商说明用于识别用途，不生成模型配置。Keychain 采用先写新条目再更新非敏感引用的方式，失败保留旧有效引用；删除先撤销授权，再清理条目，失败显示可重试状态。

- Keychain 条目以独立凭据 ID 区分；只在既有 settings 保存非敏感标签、用途和授权关系，不保存密钥。服务商、服务地址、API 类型与账号标签用于区分兼容范围，不生成或写入 Agent Provider 配置；来源不明时不自动匹配。同名 env 不自动合并凭据，也不自动授权新 Agent。
- 用户明确选择“哪份凭据用于哪个 Agent、注入哪个变量”。已有单 Agent 配置优先保留；共享配置不能静默覆盖它或继承环境中的同名凭据，存在冲突先显示并让用户选择有效来源。未选择共享时沿用既有环境继承规则，不新增环境清空。
- 声明有 env 时可据此提供选择；缺少 env 时走现有显式配置，不按 Agent 名或 provider 猜变量。无法用现有 env 路径实现时保留 Agent 登录方式和已知限制，不扩为统一代理。
- 支持新增、替换、解除某 Agent 授权和删除凭据，删除前显示使用范围。Keychain 写入失败不破坏原凭据或有效配置；旧条目按明确映射兼容，不批量迁移或删除。
