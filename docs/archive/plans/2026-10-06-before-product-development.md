页面分类固定从左到右为程序、账号与服务、模型；新连接进入账号与服务后，由用户按实际条件继续选模型。已有保存步骤、来源与模型不重置。协议认证、终端登录与服务配置使用同一账号区及操作状态；终端登录共用内嵌终端的暂离、取消和重新检查能力，差异只来自实际声明与状态。

请求成功证据依附当前已有连接和选择；程序/参数/官方环境、账号、服务地址/接口/密钥修订、模型或推理选择变化、断线/重启、认证失败、相关请求失败后按作用范围失效。429/额度错误与登录失败分别显示原因，不要求用户为所有请求错误重新登录。旧请求的成功记录不能覆盖新选择，界面暂离也不能使迟到结果写回别的入口。不新增持久“可用”表、连接代次或会话一致性账本。

### 3.3 操作保护与重连范围

统一界面中的操作状态，但保留不同后端职责：认证操作身份防重复与迟到结果，配置互斥防安装/服务替换竞态，相关工作保护防破坏运行/审批/未知请求。先复现误拦并证明哪个条件可删，再缩小保护范围。

| 操作场景                              | 并发与返回要求                                                                            |
| ------------------------------------- | ----------------------------------------------------------------------------------------- |
| 同一目标重复登录、登录中又取消/切方法 | 单一当前认证操作；取消需完成确认，旧结果不能覆盖新操作                                    |
| 登录期间安装/切程序/改服务            | 冲突变更串行或明确拒绝；不出现新程序配旧凭据的混合检查                                    |
| 登录已成功但仍有相关工作              | 不调用全 Agent 断开来完成检查；能独立检查则核实能力后使用，否则显示稍后检查，已有任务继续 |
| 换账号/退出会影响共享凭据或已有连接   | 先查明官方作用范围，列出受影响会话；无法保证旧任务时保留保护，不能仅靠提醒放行            |
| 其他 Agent/不相干入口有工作           | 不全局封锁；暂离/返回恢复原目标和输入                                                     |
| 停止未确认、审批待处理、请求结果未知  | 保护相关工作；不得自动重连后补发未知消息                                                  |

当前 agent_disconnect 仍用于显式全 Agent 断开；认证完成后的检查已改为 auth_recheck，仅在原目录的已有设置连接原子空闲时替换。其他目录与 API 连接保留；API 检查继续由原服务连接入口处理。新方案复用现有管理器与操作身份，不新建第二套生命周期协调器。作用范围的受控测试与安装结果分列，继续补真实并发覆盖。

### 3.4 已有配置与通用执行机制

当前已有 `agent_catalog` 目录/登记、`authMethods` 与 `auth_route`、`recipes.rs` 已核实补充、按 Agent/方法保存的 `manual_auth`、`preparation` 官方入口、`credentials`/`service_config` 服务配置及共用 UI。多个文件承担不同职责，不据此认定维护复杂或登录漏接；同一事实重复且产生遗漏/冲突须有具体证据。

按具体 Agent/方式核对官方来源、声明/已有配置、入口、执行、返回核验和取消恢复。补缺沿已有配置字段及执行器完成，不能只加按钮；不要求合并模块、迁移整套 schema 或重建注册表。出处、核对日期与适用范围随具体补充保存。

- 优先级：当前协议声明 → 已核验的官方扩展 → 适用范围内的配方补充 → 用户显式配置。用户选择的使用方式仍有效；相互冲突时说明原因，不静默替用户选择。
- 标准字段缺省 type 按协议解释为 agent；配方不能按品牌把它强改成 terminal，也不把 description 的自然语言解析成命令。未知 envelope 保留，未知方法不冒充支持。
- typed terminal 的调用语义不被旧扩展覆盖；旧扩展的不同程序须有精确声明/启动形状依据，并满足目录或用户显式配置的命令边界。
- sources 必须能定位每个非平凡字段；缺出处、范围不匹配或声明已变时停用该补充，继续纯协议或显式配置路径。内置配方随源码发布，不从项目目录读取或动态执行脚本。
- mapping 是有限的、有类型的变换与合并规则，不接受任意代码、shell 片段或秘密常量。保留现有非秘密服务身份、冲突检查和恢复来源保护。
- 秘密仅在当前授权交付阶段进入官方通道，不放入会被启动诊断保存的配置对象；序列化配置需要秘密占位/官方引用时仍只携带引用。
- 原有 Host、官方认证、共用终端与服务执行链保留；本轮只为已证实缺口补配置或接线，不把模块合并、删文件或重构当交付。

### 3.5 协议依据与升级条件
