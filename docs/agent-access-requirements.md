| A   | 发现、安装、账号与服务；接入层/认证/凭据模块       | 官方来源与作用范围可追溯；安装/切换/退出的取消、失败、未知保护完整；已选来源、真实身份与实际使用分开核验       |

| C   | 执行、停止、恢复、并发；请求控制/进程管理/对话状态 | 依赖身份归属与 K 保存保护；同对话不重复发送、跨对话不串审批/停止，未知不自动重发；真实停止核到该请求的外部工作 |

| J   | 共用交互、通知、键盘和无障碍；桌面壳/共用 UI       | 依赖 C；成功、需要回应和失败可定位；系统实际送达/点击与应用内卡片分开验证                                      |

| L   | 性能、资源与长期运行；前后端共享设施               | 首批建立测量基线，随后覆盖真实长内容、多任务及睡眠/断网；按测量制定上限并复验，不把受控夹具当实机性能          |
| M   | 工作树与并行目录；工作位置/生命周期                | 先核范围与设计，再依赖 C/K；建议基础创建、分支选择、已有工作树接入、安全回收；不自动升级为合并/PR平台          |

| X   | 超出当前明确范围的决定；产品边界与官方接口调查     | 每项给出已核事实、用户价值、成本、契约影响和明确建议；需要用户决定时留下具体选择，不自行宣布后置或完成         |

每个条目的完成依据 = 下表专项条件 + 所属包共同条件 + 适用的产品标准。按风险覆盖正常、失败/拒绝、取消/未知、断连/重启、并发/共享资源、大文件/长对话、权限/凭据变化与平台差异；不机械要求无关组合，也不恢复已撤销的整组六条旅程门槛。

每次更新条目必须记录：实际改动及提交、Agent/模型/服务/系统与程序版本、验证种类、原始回执、通过/失败/未测、残余限制和下一步。证据可以共用，但不得超出实际覆盖范围。源码检查、夹具、协议探测、安装版、真实 Agent 效果分别记；文档整理不能把条目标成能力已完成。

## 官方接口与范围约束

29 家核查沿[首批名单](../docs/agent-first-release.md)逐项记录官方 ACP 声明、SDK/CLI 补充路径、语义/作用范围、实际接入、版本、证据及阻塞原因；在[现有跟踪数据](../docs/evidence/2026-10-09-host-capability-audit/agent-standard-coverage.json)所指证据基础上增量留证，旧成功/失败原文保留。原跟踪中的 232 个“本版未重新验证”不是 232 个失败。

- 官方客户端文件/终端回调不自动等于第二 Agent 循环；ARCH-44 先核具体需要、权限和生命周期，若必要且合规则落实，不以架构口号跳过。
- ARCH-47、H13–H15、H17 明确比较基础工作树方案、用户已有目录和共享配置/依赖/端口，形成可实施设计；不会仅写“复杂，待定”结项。现有契约不变更前，不擅自承诺文件系统隔离或代写 Agent 配置。
- H16 的自动合并/完整 Git/PR 管理、P29 的登录及敏感网页自动化、H22 的远程/定时/团队编排仍需明确范围结论。该决定必须处理，但范围决定不能冒充功能实现。
- H20 公开分发/签名/公证/更新渠道按用户要求后置；P50、H21 中编辑器、LifeModel 真实采集、多窗口、移动端、Linux 等按既有契约边界保留；不把其中与当前能力有关的普通数据保护一并推迟。
- 对标以 Harnss、Codeg 等同类多 Agent 工作台为主，终端/工作树型产品为邻近参考；不把某个 Agent 自家客户端或同行功能并集当唯一标准。同行公开宣称、源码与实际体验分别判断；已核资料见原审查报告，不继承其修改 Agent、独立 HOME 或自建事件账本的做法。
