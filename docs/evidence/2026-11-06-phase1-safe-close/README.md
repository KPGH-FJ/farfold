# 第 1 阶段：指定会话的安全关闭

本批区分四件事：原会话的回复停止、旧工具是否有独立终态、官方关闭是否落在同一会话、可观测资源是否实际释放。关闭确认不能补写历史工具结果。同一连接的另一条会话须继续保留。 [官方关闭契约](https://agentclientprotocol.com/protocol/v1/session-setup#closing-active-sessions) · [回执摘要](summary.json)

## 独立的资源对照

在各自的自有空目录，按当前登记的官方程序直连。用两个只做协议初始化、没有工具的自有 stdio 进程，分别作为 A、B 的会话内服务；未发送模型请求，未改 Agent 配置、账号、正式应用或用户数据。

- Goose 1.52.0 明确声明支持关闭。关闭前两个服务进程均完成初始化，以 PID、启动时间和父进程链绑定同一个官方连接。仅发送一次关闭 A；1 毫秒收到匹配回执，159 毫秒内观察到 A 原进程已不运行，B 原进程和 Goose 仍运行。A 子进程独立记录到输入关闭并退出，B 的输入直到最后测试连接正常结束才关闭。这个证据只覆盖这两个会话内服务子进程，未声称验证已开始的外部命令、脱离的子进程或旧工具终态。
- Copilot CLI 1.0.106 同样声明支持关闭。在不发消息的两个新会话中，4 秒观测内没有看见这两个独立服务进程启动，因此未发关闭，未取得该类进程的释放证据。这次不能判定为关闭失败。

## Copilot 旧工具未知时关闭 A

Copilot CLI 1.0.106 在同一个官方连接内创建两个不同的自测会话，均使用已有服务 / Auto / Agent / Allow All Off。A 的有界前台命令经两项精确的一次性审批后实际运行，只停止一次。其 shell 和直接子进程在 25 毫秒内退出，官方返回整轮已取消；观察 22.001 秒和随后关闭全程均未收到该工具的终态。没有给进程发送信号。

B 发起自己的请求并等待其单次审批，此时只发一次关闭 A。A 原生记录出现 `session.shutdown(routine)`，随后收到匹配的空关闭回执。独立进程检查显示，同一 Copilot 进程在关闭前各持有 A、B 的一个文件句柄；关闭后 A 为 0、B 仍为 1，且 B 的审批仍待处理。随后只批准 B 一次，B 在同一连接完成独立工具，返回自己的标识与终态。B 未被停止或关闭，直到测试连接正常退出时才记录关闭。A 历史仍存在，原工具没有被改写为完成。该结果覆盖此自测的会话资源和归属，未证明其他命令、脱离进程组的后台工作或正式版的原三个未知对象已经释放。

## Goose 旧工具未知时关闭 A

Goose 1.52.0 初次新会话的默认模型与已授权免费型号不符，预检停在发送之前，零模型请求、零关闭。随后用官方的每会话设置，为两条新自测会话确认原 OpenRouter / Nemotron 3 Ultra (free) / off；只将 A 改为逐次审批，确认 B 模式没有变化。读回了两条各自的原生设置。

A 唯一的固定文字输出停在审批处；B 的纯文字请求已发出后，只取消 A 的请求并取消其审批。A 官方返回已取消，无同一工具终态。仅关闭 A，收到匹配回执。随后使用 Goose 的只读工具列表核对，原 A 返回同一会话不存在（`-32002`），B 在同一连接仍可查询，关闭回执后继续输出并准确完成，零 B 工具调用。A 的保存历史仍在，旧工具结果继续未知。关闭前后未观测到子进程，因为该命令从未获准运行；会话内服务进程退出的实证来自上面的独立资源对照，不从这里推断内存或全部资源释放。 [Goose 1.52.0 关闭实现](https://github.com/aaif-goose/goose/blob/302b60806639ea9f0ae8f053f49f8bf0e88b26f4/crates/goose/src/acp/server.rs#L2621-L2644)

## 正式应用的边界

正式应用仍为 `6ce829c5`。原未发稿的保存摘要、保留 1 份和三个原自测会话的正式通信记录均核对未变。现有普通关闭会保护没有工具终态的活动；直接解除这道保护会把停掉的回复和已释放的资源混为一谈。源代码中的关闭、工具占用和更新检查分别做了定向核对：后端 13 项、前端 36 项通过。本批未改变保护规则，也未强制退出或替换正式应用。

安全恢复需要把审批、工具、同轮取消及原连接精确对应，再验证关闭回执和适用的资源释放。旧 Copilot 运行中取消对照中，实际已运行的命令在协议上只报告过 `pending`，没报告 `in_progress`；缺后一项不能证明命令未执行。旧工具历史仍显示未知，待发保持暂停；晚到审批、活动工具、其他会话、超时、旧连接回执或仍活着的后台进程不能被视为已安全释放。现有正式版的三个自测未确认步骤不由直连样本代为解除。 [旧运行样本](../2026-11-06-phase1-isolation/README.md#copilot-工具回执对照)

长等待如果自然复发，继续用已校验的只读路径、进程和管道探针并行取证。Kilo 跨版本授权仍待具备正式更新条件；安装版写入故障仍缺隔离的 macOS 图形测试账号或实例，本机只见一个交互账号。
