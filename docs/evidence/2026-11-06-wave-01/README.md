# 首波 Agent 只读打开与结果提示

## 旧正式版实测

在 macOS arm64 正式版 `8ac6dcb09` 中，对三家 Agent 观察到四次实际启动。另有一次 Copilot 排队取消，单独计证。操作限已选历史的只读打开，原未发稿、保留草稿及原工作位置保持。

| 对象                          | 实际观察                                                                                                                                                 |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Goose 原自测对话              | 连接检查完成，发出历史读取，收到 9 条更新。120 秒未取得匹配的最终读取回复，界面提示打开超时。                                                            |
| Goose 另一独立自测对话        | 连接检查完成，发出历史读取，收到 4 条更新。120 秒未确认读取完成，界面显示通用重连失败。同毫秒的唯一响应按原日志行序早于读取请求，未观察到额外响应。      |
| GitHub Copilot 已归档自测对话 | 先在等待读取时明确取消一次，该次未观察到进程启动，随后界面显示通用重连失败。正常保存退出并重开应用后，另一次打开实际启动，连接检查超时，未进入历史读取。 |
| Kilo 已归档自测对话           | 实际启动，连接检查超时，未进入历史读取。                                                                                                                 |

两次 Goose 历史读取和 Copilot、Kilo 的连接检查超时分别留证，原因仍未知。全程零新模型发送、零旧请求重发、零审批、零对运行中 Agent 任务的停止。协议观察仅使用有限的事件类型和数量，实际服务、模型生效及审批和停止终态仍未验证。

## 源码修正与受控复验

- 打开对话已经开始且等候结果超时时，管理层和调用方统一返回同一个本机超时结果。既有等待期限、进程清理及请求归属保持。同字节回归由 1 项失败转为通过，关联检查记录 Rust 18 项、前端 51 项通过，覆盖有相交。
- 本机确认取消等待读取后，进度行收起，原对话改为显示“已取消等待读取。原内容已保留。”前端受控复现了原通用错误，最终 4 个文件 39 项通过。旧正式版 Copilot 的实际观察只证明当时显示通用错误。
- 独立复核发现 Agent 错误正文可与本机结果码重名，已隔离直接新建和读取的错误来源。普通路径只按官方认证错误编号保留认证提示，其余远端错误显示固定说明，原网页工具保护路径保持。一次实际协议回归使用 6 个受控响应，由失败转为通过，另有 20 项关联通过，其中包含该回归。最终 11 份源码的独立复核无必改。

## 正式更新与复测

完整七项自然通过。前端721文件、9,642项，Rust 2,404项通过、7项既有忽略，检查前后2,405份声明输入一致。代码、工程和正式交付均有独立复核。候选构建一次，候选9项与安装后6项通过，五个应用文件原子替换，精确重复应用已移除。三份关闭态清单各206,275项且字节一致。

新版 `68aefdb49` 冷启动保留原未发稿、1份保留草稿及原工作位置。同一条 Goose 自测历史再次读取，收到5条更新，仍未取得最终读取回复，已实际显示“打开对话尚未确认完成，等待已超时。原内容已保留”。复测后通过保存退出回收所选读取，再打开确认原草稿。实际排队取消仍只有旧版界面和新版受控覆盖。[本批分项](summary.json)
