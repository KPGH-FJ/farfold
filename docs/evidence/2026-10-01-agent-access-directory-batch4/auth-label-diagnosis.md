# 同名账号方法：只读诊断与下一片最小范围

本轮仅核对已有安装证据和通用选择器源码，未修改生产源码、运行测试、启动应用或 Agent，也未选择或执行 GLM 的任一账号方法。下一片是否实施由根任务在当前候选验收结束后安排。

## 已确认事实

[实际菜单文本](glm-auth-options.txt)显示两个完全相同的 `Z.AI API key` 标签；[本轮问题记录](glm-account-labels.md)和[公开登记](glm-registration.json)确定它们具有不同 ID 与声明：

| 公开 ID        | 原名称         | 已保真分类                                                  | 目前的真实操作边界                                                                             |
| -------------- | -------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `z-ai-api-key` | `Z.AI API key` | 缺省声明，对应 `agent`                                      | 有精确所属连接且未被其他守卫阻止时，可请求 Agent 登录；未证明该请求成功或可在 Farfold 配置 Key |
| `z_ai_api_key` | `Z.AI API key` | 旧 `env_var`，对应 `environment`；公开变量名 `Z_AI_API_KEY` | 只显示说明；目前不能在此自动登录或直接配置/交付变量，不擅自转为 API 配置                       |

[通用选择器](../../../src/components/AgentAuthSection.tsx)第 479–482 行只渲染 `method.name`。其 `option.value`、React key、选中查找和后续动作仍使用精确 `method.id`，没有把两个方法在数据上合并。已选后的说明、变量名和执行守卫能够区分方法，但选择前没有可辨标签。

本批未执行两条方法，因此这是名称辨识缺陷；不能据此声称实际执行了错误登录、配置了凭据或认证失败。

## 最小通用改进

在共享 `auth_method.ts` 或一个小的纯标签函数中，按公开方法名称分组。只为同名组增加由已保真 `kind` 派生的简短操作说明，保留完整原名称。可按浏览器显示的空白折叠来识别同名，但不改方法 ID、原名称或协议载荷。

建议 GLM 的呈现示例：

- `Z.AI API key（Agent 登录）`
- `Z.AI API key（环境变量说明，暂不能在此配置）`

通用类型对应现有操作：`agent` 为 Agent 登录，`terminal` 为终端登录/设置（沿已有 `purpose`），`api-key` 为 API 配置，`environment` 为环境变量说明且标明当前不可直接配置，`unsupported` 为方式说明且标明不能自动执行。标签不宣称登录一定成功；禁用原因和实际按钮继续由已有 `unavailableReason` / 目标所有权 / 来源 / 工作守卫决定。

若同名称、同类型仍重复，再附公开 `method.id` 作为稳定末级区别；不使用列表下标、顺序编号、品牌分支，或从 `API key` 等名称推断可交付凭据。选择后的原说明、原方法名称与公开变量名继续显示，不把任意 description、环境值、命令参数或其他原始载荷拼入菜单。已有不同名方法无需改标签。

范围只需共享标签函数、集中字符串、`AgentAuthSection` 的 option 文本和相称组件回归。无需改变 wire、认证路由、当前选项 ID、持久进度、用户模型/来源或默认选择，也不新增能力状态。

## 必要反例与验收

1. 两个同名的 `agent` / `environment` 声明：实际组件菜单的标签可区别，原名称均保留，value 精确对应各 ID；初次打开不自动选中或运行。选择环境说明后没有普通登录/API 配置按钮，公开变量名可见，原手动说明、重查和返回仍可达。
2. 选择同名的 `agent` 方法：只有明确点击登录才调用其精确 ID，不能调用环境方法或 API 入口；受缓存/来源/目标守卫限制时仍不可执行，标签不改变可执行性。
3. 同名且同类型、不同 ID：附稳定公开身份，列表调序后保持原 ID；不按下标切换方法，也不把重复显示变成自动选择。
4. 不同名方法、刷新和迟到结果：原名称保持，显式选中 ID 不因标签变更被替换；复用现有所属目标与请求失效回归。原始载荷 canary 不进入菜单文本。
