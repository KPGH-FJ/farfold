## 一次现有 UI 路径

1. 根任务按既有候选安装流程核实新 `/Applications/Farfold.app` 的身份及冻结输入，并保存本轮原数据、未发内容、已选 VT Code 启动字段和已存在诊断文件清单。记录打开 VT Code 前的时间，不先发测试。正常启动应用，不输入凭据、不打开登录、不下载模型。
2. 从现有 VT Code 管理入口进入准备页，保持“沿用已有设置”和原工作位置，明确读取一次模型选项。记录连接、读取结果、所有原已记录的模型/推理项及来源；不根据默认显示文本猜具体模型，不选择替代模型或推理值。若读取失败、漂移、需重新确认未知配置、来源改变，或原模型/推理选择无法保持，停止发送，只记录本次未测和可见出口。没有模型选择项本身不授权新增模型；实际底层模型仍可保持未知。
3. 从列表打开原 `连接测试 · VT Code`，只观察旧正文、计划、失败、来源及 `none` 是否保留。历史无法读取时保留旧索引和失败，不为此次分类绕过恢复准入，也不在旧对话点击发送或处理原队列。可返回准备页；该读取不是新 prompt。
4. 只有准备检查允许保留本次原选择且没有待处理动作时，使用现有“发送一条短消息测试”入口，最多点击一次。先记录界面实际将发送的本轮固定标记和点击时间；消息只要求精确回复标记、禁止工具和文件读取/修改，沿当前 UI 提供的短测内容，不附加草稿或资料。该入口产生本轮可辨的新测试对话，原失败对话继续保留。若按钮不满足准入则不发送，不改参数或模型求通过。
5. 等待该次结果的有限窗口建议不超过 90 秒。成功、失败、需处理或未知都如实截图/保存安全文本；不执行认证、审批或重试，不在出现未知状态时再次发送。若必须结束仍在运行的测试，只用现有停止入口并记录停止确认状态，不能把点击停止当作进程已经结束。
6. 在有限窗口结束后，通过现有诊断预览与本机导出查看本轮白名单元数据；不保存原始协议、错误正文、stderr、完整环境或命令行。返回原稿并退出应用，核对旧 VT Code 选择、原失败对话、原未发内容和队列保持；唯一新增测试索引/允许的设置变化单列。退出沿现有 PID+启动时间/程序身份收据和启动摘要分层确认，瞬时未采到的进程不能宣称采样完整。

## 有限观察的关联与结论

为每一步记录开始/结束时间、当前 UI Agent/来源/目录、候选身份及新出现的日志文件名；同一窗口不操作其他 Agent、不另发 prompt。使用既有 VT Code 程序路径及进程身份采样、唯一新短测索引、界面固定标记和安全记录中的请求计数联合定位窗口。日志文件名没有 Agent/请求 ID；若多个文件或后台请求使所属连接仍不唯一，保留这个不确定性。标记只从审阅的 UI/测试结果记录，不加入新协议日志。

- 收到合法 `in / response / protocol` 的类别，可写“本次 VT Code 操作窗口观察到入站 `internal_error`（或实际类别）”。即使窗口仅有一次 prompt，也不能写成 ID 已匹配的 prompt 错误或具体账号/网络/模型根因。
- `responseIdNull=true` 表示合法 null ID，不证明解析失败或属于 initialize。`beforeInitializeAccepted` 只是观察时点；`true` 也可能发生在超时/清理后，`false` 不能据此改称 prompt/auth 阶段。v2 的 `matched_error` 只对该连接的 initialize 有既有精确关联，不扩大到短测。
- `auth_required` 只证明收到该固定码，不替用户登录或交付 Key；`request_cancelled` 不证明 Farfold 曾取消；`other` 不保存自定义数字码。成功标记、失败结算和错误类别分别记录。
- 没有分类、只观察到本地 decode/EOF/超时、文件缺失或队列/窗口遗漏时，写“本次未取得可判定的入站错误类别，原因仍未知”。未发送、未完成和失败分别列明，不把缺记录当作没有远端错误。本片最多验收有限诊断贯通，不关闭 VT Code 首发缺口；原失败保持历史事实。

## 收集器的窄扩展要求（本稿不修改）

batch7 的[旧收集器](../2026-10-01-agent-access-directory-batch7/collect_protocol.py)仅保留六个 v1 基础字段，直接复用会剥掉新类别。应从[当前含 v2 的收集器](../2026-10-01-agent-access-companion-program/collect_protocol.py)派生本候选副本，保持原文件不动；输出应与产品 `safe_record` 同样严格重建：

- 基础字段仍限定已知 version、方向、事件、错误类型，`ts/bytes` 用 `type(x) is int`、非负，不能用 `isinstance(x,int)` 接受布尔。不要从输入字典整体复制。
- 可选组三字段只在 `event=response`、`error=protocol` 时成组保留；两个布尔必须是实际 bool。`out` 仍只有六类 `parse_error / invalid_request / method_not_found / invalid_params / internal_error / other`；`in` 才允许同六类加 `request_cancelled / auth_required / resource_not_found`。部分组、错误类型、未知类或错误上下文剥掉整个组，基础记录可保留；`err` 不接受类别组。
- v2 启动摘要继续沿既有固定枚举、布尔、退出码/信号范围及矛盾检查重建，不增加正文、ID、路径或阶段推断。只收完整换行记录，解析错误计数，不输出坏行。新候选起点与有限观察窗口用于筛选，不能拿旧安装时间无限累计本轮观察。
- 安装核对同时比较诊断预览/已审 ZIP 与收集结果中的合法字段组；导出后的新增事件不进入旧预览快照。未知输入/canary 安全性由作者受控测试验证，不向正式日志注入测试正文。
