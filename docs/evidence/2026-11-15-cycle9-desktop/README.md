## 当前支持范围与实机验收

| 用户场景           | Windows 正常入口验收                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开本地文件与项目 | 用安装版文件选择器选包含中文和空格的本地盘符路径，预览或打开产物并核内容。用自建样本验证拒绝和恢复，确认失败后仍可选合法路径、原文件内容及归属保持。消息里的本地文件链接对 UNC 和设备路径保持拒绝。对实际工作区、附件及交付服务的 UNC 和重解析路径，按各入口的允许／拒绝策略用自有样本独立核验。                                                                                                  |
| 网页与共享许可     | 从安装版打开真实公开 HTTPS 页，切换及关闭页面，检查焦点和窗口内网页范围。让已授权的实际 Agent 发起读取和截图，核授权范围、拒绝可控、换页或关闭后许可撤回及工具结果归属。在隔离环境测试 WebView2 缺失、版本不满足或启动失败如何提示，恢复组件后从正常入口重试。                                                                                                                                    |
| 通知与桌面行为     | 从已安装的开始菜单入口启动，核快捷方式 AppUserModelID 与 `ai.farfold.desktop` 一致。验证允许与禁用、实际横幅和声音、同一自有事件只显示一次、单击回到正确的待审批／提问／异常卡片。保持 Farfold 运行时，点击经 WinRT 回调路由至该卡；正常退出移除本进程维护的通知。核实退出后清理、直接再开无旧通知跳转及退出前单击不触发自动发送。当前产品提示点击定位需保持 Farfold 运行，冷启动激活保持未提供。 |

源码的独立 Windows WebView2 控制器保留网页和应用桥隔离。Windows 通知使用开始菜单快捷方式注册的 AppUserModelID，运行中通过 WinRT 回调定位；通知负载没有启动参数，正常退出尝试移除本进程维护的通知。安装脚本已有快捷方式身份和指向断言，断言实际通过仍等 Windows 安装。文案提示保持应用运行，与现有实现一致。[WebView2 源码](../../../src-tauri/src/browser_workspace/windows/mod.rs) · [Windows 通知源码](../../../src-tauri/src/desktop_notifications/windows.rs) · [Windows 安装验收脚本](../../../.github/scripts/windows-install-lifecycle.ps1) · [架构约定](../../architecture.md#平台边界)

微软将进程内事件回调和可启动关闭进程的 COM 激活注册列为不同支持方式。当前采用前者，只有未来将冷启动定位纳入产品承诺时，才需相应官方激活注册和精确目标验收。[Win32 通知指南](https://learn.microsoft.com/en-us/windows/win32/shell/quickstart-sending-desktop-toast) · [COM 通知激活](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/win32_tile_badge_notif/respond-to-toast-activations)
