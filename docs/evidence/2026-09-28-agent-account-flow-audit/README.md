# Farfold Agent 与账号流程检查

检查日期：2026-09-28

更新：下列三项问题已按用户授权修改当前原型，复测结果见 [修复验证](fix/README.md)。下文保留修改前的观察和边界，不能据此判断最新原型仍未修复。

## 结论

确认 3 个问题。影响最大的是：当前请求明确要求登录后，补登录入口仍因已有工作被禁用，页面又没有指出应处理哪段工作。两个返回入口也未准确承接用户的修复目的。

本轮只通过当前原型的可见界面检查，未查看实现，未修改原型。页面明确标注安装、认证与请求均为模拟。结论不代表真实 Agent 接入或安装版验收。

## 1. 要求登录后，补救入口不可用

**严重度：S2（重大操作障碍）；置信度：高。**

- 正常入口：设置 → Agent 与账号 → 管理 Codex。程序已连接，账号由 Agent 管理且身份未读取；登录和注册因“还有工作待处理”被禁用。与用户截图一致。
- 用评审场景“首次发送 · Agent 要求登录”设置失败条件，输入审查专用文字并发送模拟请求。页面明确要求完成登录，草稿保留。
- 点击“完成登录”，选择登录方式并继续，页面显示“当前请求需要完成账号设置”“需要完成登录后再使用”。
- 同页的登录、创建账号、已在外部完成设置后重新检查均禁用。展开更多方式后，其他官方登录方式和手动登录输入也禁用。文档链接仍在。
- 页面没有标明哪段工作造成限制、该工作是否能停止、处理后如何回到原任务。

**实际影响：** 用户已获得明确失败原因，却无法在此继续修复。仅提示“先完成或停止”不足以帮助用户解除限制。

**尝试的恢复：** 返回后自行进入 Codex 的“等你回应”，出现 5 项不同状态的工作，包括恢复问题、草稿、结果未知和操作确认；列表没有标出哪些工作影响账号操作。未替用户停止或完成这些工作。

**证据边界：** 待处理工作在此次模拟发送失败前已存在；未确认具体锁定来源，不认定失败请求自己造成锁定，也不认定永久死锁。草稿确实保留。

**应达到的体验：** 明确指出受影响工作并提供处理入口；处理后返回原登录步骤。查看注册信息、外部开户、检查现有设置、实际更换账号，应分别解释必要限制。是否必须限制某项操作仍需结合真实 Agent 能力验证。

证据：[初始账号页](./03-codex-account.png)、[发送后要求登录](./15-login-required-result.png)、[登录入口全部受限](./18-required-login-blocked.png)、[其他登录方式也受限](./19-login-fallbacks-blocked.png)、[查找待处理工作](./11-find-blocking-work.png)。

## 2. “完成登录”重新让用户选择使用方式

**严重度：S3（中等流程摩擦）；置信度：高。**

首次发送已明确要求登录，点击“完成登录”却进入通用接入向导的“使用方式”步骤。默认选中“沿用这台电脑上的设置”，提示已有账号或模型服务可直接沿用。用户还要自行改选“登录账号”再继续。

**实际影响：** 按钮承诺补登录，落点却重新询问已经有明确失败背景的问题。默认选项也没有解释为什么刚才失败后仍可直接沿用。

**尝试的恢复：** 手动改选登录并继续，可以进入对应登录步骤；随后遇到第 1 项限制。因此这是目标与默认选项不准确，不是入口完全失效，也未验证无限循环。

**应达到的体验：** 承接触发问题的 Agent、来源和登录要求，直接进入补登录步骤；仍可主动改选其他使用方式，并在完成后回到保留的草稿。

证据：[登录要求与按钮](./15-login-required-result.png)、[点击后的通用选择页](./16-login-repair-blocked.png)、[手动改选登录](./17-login-choice-locked.png)。

## 3. 对话中的“检查 Agent 设置”打开整个探索目录

**严重度：S3（中等流程摩擦）；置信度：高。**

打开“继续聊聊首页的设计”，恢复提示说明原思考选择与返回结果不一致，发送暂停。点击该提示中的“检查 Agent 设置”，实际进入全部 Agent 的探索目录，没有直达 Codex 的相关设置。

**实际影响：** 用户需要重新找到 Agent、找到管理图标，再判断应查看账号、模型还是程序。具体对话和错误原因没有引导到对应操作。

**尝试的恢复：** 目录中的“管理 Codex”仍能打开设置，路径可人工完成。问题是修复入口绕行并丢失目标，不是设置不存在。

**相关表现：** 设置里的“Agent 与账号”也默认打开探索目录，已有账号管理隐藏在各卡片的图标中。

**应达到的体验：** 从具体问题进入对应 Agent 的相关设置，并能回到原对话继续处理。

证据：[对话恢复提示](./12-recovery-task.png)、[点击后的探索目录](./13-recovery-opens-directory.png)、[设置中的账号入口](./02-agent-account-entry.png)。

## 已排除的误报与正常行为

- “程序已连接”和“账号身份未读取”可以同时成立，不能仅凭这两个状态判定矛盾。
- 读取模型列表不等于账号有使用额度或请求一定成功。因此未把“读取模型后仍未检查”认定为认证状态错误。
- 正常模拟连接测试成功后，账号摘要更新为“当前选择已通过测试”。见 [测试后摘要](./10-account-after-test.png)。
- 后续模拟发送要求登录后，账号摘要更新为“当前工作需要登录”，保存按钮也按要求禁用。没有保留过时的成功摘要。见 [失败后的账号设置](./22-account-after-auth-failure.png)。
- 退出补登录流程后，审查文字、所选 Agent/模型和登录错误保留。见 [返回后的草稿](./20-return-retains-draft.png)。
- Cline 的“创建账号”可以先进入账号服务选择页；没有继续前往外部网站或创建账号。此观察用于判断注册与认证的操作边界，不用于证明 Codex 必须具备完全相同能力。见 [注册前置选择](./21-signup-before-auth.png)。

## 过程覆盖与状态

1. 设置 → Agent 与账号 → Codex 设置：已复现用户截图；存在操作限制无法定位的问题。
2. 读取模型 → 模拟短测 → 返回账号摘要：通过；摘要正常更新。
3. 自行查找待处理工作 → 打开恢复项 → 检查 Agent 设置：有绕行；落点是探索目录。
4. 模拟首次发送要求登录 → 完成登录：有绕行；先到通用使用方式选择。
5. 选择登录 → 尝试其他恢复方式：受阻；可见账号操作禁用，未停止用户已有工作。
6. 暂时返回原草稿：通过；草稿、选择与错误保留。
7. Cline 注册前置页：已观察；仅进入服务选择，未开户或登录。
8. 新错误后的 Codex 设置摘要：通过；新的登录要求覆盖先前测试成功状态。
