## 删除与归档保护

从真实保存格式构造只有发送结果未知、没有待发内容的记录，再以新前端实例加载。原实现未能阻挡未打开对话的归档与删除。原生受控 Agent 也接受了同一保存状态下的删除。修复通过前端准入、自动归档候选、原生远端动作准入及最终本地事务使用同一未知保护。已核未加载对话、已加载对话、仍可归档的另一条对话及用户明确确认旧提示后恢复操作。

原生测试另外复现收到待处理审批或提问后仍可关闭并删除，以及关闭等待时新工作到达后的漏检。控制目标按原连接和原对话归属检查；若官方已确认关闭，新增互动或保存的保护状态仍可阻止后续删除。普通关闭沿原语义。实际删除请求发出后的远端结果与最终本地事务分别确认，本地准入不会追认远端动作。

所有过程使用受控数据或临时自有进程。验收以 [ARCH-32](../../status.md#arch-32)、[P34](../../status.md#p34) 和 [P37](../../status.md#p37) 各自的适用原条件为准。
