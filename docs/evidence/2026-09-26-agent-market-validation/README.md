## 安装版实测与问题归属

### Qwen Code

1. 市场条目从“尚未安装”变为“已连接”，版本 `0.24.5`，一份安装。
2. 登录仅提供 `Use OpenAI API key`。点击“开始登录”后显示“登录失败”，没有授权页面或密钥输入。
3. “使用 API 配置”显示此接入尚未提供配置方式。改用“沿用已有设置”进入真实新对话，创建失败并要求认证；发送不可用。

Qwen 实际用 `_meta.type/args` 描述终端认证，Farfold 未识别这种扩展形状，按默认 `agent` 方法调用；该 Qwen 方法仅刷新既有配置，不提供交互输入。当前稳定标准是顶层 `type`，不能把这一兼容缺口直接等同为 Farfold 漏实现标准。Farfold 的另一个明确缺口是暂不提供 Qwen 的新 API 服务配置，而失败 UI 没有有效引导。底层缺少哪项账号配置未读取，不能仅凭界面认定特定密钥缺失。详见 [认证分析](qwen-auth-analysis.md)。

### Amp

1. 市场条目从“尚未安装”变为“已连接”，版本 `0.9.0`，一份安装。
2. “在终端登录”正确识别其 `_meta["terminal-auth"]`，打开内嵌终端，提示输入 Amp API Key。未输入，点击取消后可继续操作。
3. 沿用已有设置可创建新对话。使用 Agent 提供的默认 `Medium`，没有改模型或推理选择。发送 `只回复 FARFOLD-AMP-ACP-20260926-OK。不要调用任何工具，不要读取或修改文件。` 后，立即显示“连接中断，结果未知”，没有模型回复。
4. 本轮仅增加这条验收对话（总数 59 → 60）；原有两条待回应未操作。未归档或删除失败样本。

单独使用已登记命令做一次有界 ACP 诊断，初始化和创建对话成功；首次 `session/prompt` 未收到响应，进程退出码 `1`。stderr 仅保存分类：命中 `ENOENT`、`Executable not found`、`not found in $PATH`，探针 PATH 中无 `amp`。见 [诊断结果](amp-protocol-diagnostic.json)。不保存原始 stderr 或环境值。该结果确认**诊断路径**缺少 CLI；它与安装版断连、安装前有界程序查找及公开源码一致，安装版自身没有保留底层 stderr，不能冒称从安装日志取得原始错误。

责任分开：Farfold 的目录安装只处理入口包，未自动补齐/引导独立依赖；Amp 接入包直到首次发送才启动 CLI，缺程序时本次诊断直接退出，未返回可展示的协议错误；Farfold 最终只能呈现笼统的断连状态。终端登录可以打开并不代表 CLI 已齐备、Key 有效或真实模型可用。详见 [依赖与认证源码分析](amp-dependency-analysis.md)、[公开握手字段](amp-handshake-public.json)。
