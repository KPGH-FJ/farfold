# 第 1 阶段：关闭已停止且未获准执行的对话

前一批的 [Copilot 和 Goose 官方直连](../2026-11-06-phase1-safe-close/README.md) 分别核到了只关闭 A、B 继续、A 资源释放以及旧工具结果仍未知。已运行的 Copilot 命令曾只报告等待状态，没有报告运行中，所以等待状态不用于证明未执行。

本次补 Farfold 的窄范围恢复。仅当原连接声明支持关闭，并可对应同一轮请求、同一工具的首次审批仍未被领取、客户端取消其审批且收到原请求明确的取消回执，才允许检查关闭。已有批准、更多审批、执行或输出迹象、新一轮、其他活动或归属无法确认都不能使用这条路径。关闭由用户另行明确确认，发送前再次核对原对象，只接受与同一请求对应且在等待期限内收到的明确空回执。非空、迟到或归属不明的回执都保留保护；已发出的关闭不复用旧确认再发。普通关闭、归档、删除、设置及更新保护沿用原规则。

界面把「检查」与「关闭」分开。退出确认或资格变化会丢弃这次确认；未发内容无法保存时不发关闭。确认关闭后只结束当前对话的连接，已有消息、工具原始状态、未发内容及暂停的待发均保留。未完成的步骤继续显示结果未知，不产生成功工具回执，不自动重发。其他对话与连接不参与此次关闭。

适用条件见要求参考 ARCH-26、ARCH-28、ARCH-29 和 P18。完整七项及文档检查通过：前端 722 文件、9,651 项，后端 2,416 通过、0 失败、7 项既有忽略。前端覆盖保存失败不关闭、保存期间新一轮出现不使用旧确认、另一对话及草稿和待发保持；后端 9 项相关回归涵盖同一连接里 B 的审批继续、已批准或已经执行的反例、无标签工具输出、迟到回执和等待方退出。独立代码复核确认无剩余阻断。后端此轮用受控连接，不能据此认定真实 Agent 在所有停止情形下都已释放资源。

原三个正式测试连接仍由同一正式应用持有，原工具终态未补齐。现有正式版没有本次新入口，不能靠新源码解除旧进程的保护。未强制退出或替换唯一正式应用；正式版复验、Kilo 跨版本授权与安装版写入故障分别保留。若发生自然长等待，继续使用已验证的只读取证方法。

安装条件具备后，在自有目录使用 Copilot 和 Goose 现有选择，各用两条自测对话验证。A 在首个审批时停止，核对明确取消后，检查并显式关闭 A；从同一会话核对关闭回执和相应文件句柄或进程释放，确认 B 独立完成，A 的旧步骤仍未知、原稿可恢复、待发未启动。前一批已实际运行过的命令只作反例，不借本路径解除其保护。
