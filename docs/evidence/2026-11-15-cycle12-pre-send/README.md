## Claude 和小米 Messages

用户保存 `Xiaomi anthropic` 的 Messages 配置和 `mimo-v2.6-flash`。同一正式版设置的独立 API 测试收到模型响应。Claude 0.81.2 从普通对话确认了该来源和模型，实际出站后约 133.6 秒未得到助手正文，点击停止获得终态。该次只发送一轮，文本同时含此前未发送的另一条自建测试指令。官方更新到 0.107.0 后，普通对话同一服务与模型确认成功，发送唯一干净的自建短指令，约 182.1 秒后收到带请求 ID 的 `auth_required`，无助手正文。真实小米服务的 HTTP 状态未被 Farfold 记录。用户所填密钥、服务和模型均未改写。

0.81.2 和官方更新后 0.107.0 的本机合成服务均显示，给 `providers/set` 增加 `Authorization` 后，实际流式 Messages 仍带适配程序的占位令牌。0.107.0 的模型列表请求可以收到显式设置的 Bearer，Messages 请求则仍被占位令牌覆盖。小米文档给原生 Claude Code 的做法是使用用户密钥作为 `ANTHROPIC_AUTH_TOKEN`。对照使用合成凭据，未探测小米真实请求的服务端处理，尚不能单靠这个差异归因两次等待。[Claude 认证头对照](claude-header-differential.json) · [小米官方 Claude Code 配置](https://mimo.mi.com/docs/integration/claudecode)

在同版厂商公开的会话选项扩展上，单次合成请求可以把真正的指定 Bearer 送到受控本机服务，且不会访问该监听端口以外的服务。这个结果覆盖新会话与一条合成流式响应。官方新建及读取结果仍未回报实际选中的地址或服务身份，本机用户或项目设置也能影响 SDK 环境。要接入 Farfold 已保存 API，还需能锁住该次传递的目标以及区分已有设置，随后补冷开、双会话隔离和真实实答。[受控替代复验](claude-header-differential.json)
