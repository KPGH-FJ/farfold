# 历史恢复：独立审查

2026-10-01。最终只读审查未发现剩余源码阻断。审查范围为本片的历史读取失败分类、保留原稿与来源、重读和新稿出口，以及规范化目录对应的导航返回。没有修改产品源码、运行测试、启动正式应用或真实 Agent，也没有读取用户凭据或私有配置。

## 核对结果

- `HistoryReadFailure` 仅由本次成功的恢复回复及其历史读取检查产生。空历史与未完成读取边界分别保留；远端同名错误正文或带相似字段的普通错误不能取得本地分类和导航权限。真实连接丢失仍使用连接失败路径。
- 已确认恢复成功且本次未观察到连接丢失时，清除旧 `connectionLost`。未知执行、停止未确认、原队列、原正文及模型保护仍保留。仅清除旧连接的活动工具 ID，不把历史中未完成工具改成成功或重新运行；失败后的迟到正文和完成标记不能放行，实际迟到连接丢失仍可记录，旧连接不能影响新的重读。
- 恢复失败保留本次返回的实际目录和已确认来源。服务身份缺失不能被推断成已有设置。明确新开稿沿原 Agent、目录与已确认服务创建独立空稿，不携带原队列，也不自动发送；既有模型与推理保护不因分类改变而放宽。
- App 使用本次成功返回或私有失败类型中的规范化 key。可见跳转同时检查操作序号和当前目标；暂离设置或准备页时仅修正该次原稿的返回路径。切到其他对话或开始页后，迟到结果不能抢回焦点。没有新增持久别名表或按会话 ID 模糊查找。
- 新稿按钮也检查当前组件、目标和操作所有权，迟到成功或错误不影响其他页面。重读与新开稿在按钮及处理函数中互斥，关闭了共享操作序号导致另一忙态无法清除的反例。

成功恢复后规范化 key 的导航遗漏此前已经存在；本片失败状态也改用实际目录，因此失败返回是本片必须覆盖的新增路径。两者已分别纳入受控导航验证。
