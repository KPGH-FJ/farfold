## T8 保存边界

用户已明确授权保存草稿、待发及未提交文件意见，属于 Farfold 用户内容；用现有 `settings` 存版本化记录，不建会话正文、轮次或事件表。不得从 ThreadState 整体序列化；Agent 回复、工具正文、审批表单、认证表单与秘密不落入草稿快照。草稿恢复对象仅含用户未发送文字、附件引用、原目标/选择、文件意见及必要的未发送/结果未知标识。已确认接纳的请求正文删除本地草稿副本；未知请求不能因重启变成普通可自动续发队列。

需要实现明确大小和错误边界：按对象验证版本、字段及大小；写入串行或按修订拒绝旧值；读取完成不能覆盖期间的新输入；写失败保留内存编辑和最后确认的磁盘值并允许重试；不能为腾空间静默淘汰未发送内容。旧 settings、会话索引和凭据引用不变。图片粘贴当前只有 base64 没有源路径：必须选定有界、明确归属的保存方式并覆盖清理，不能仅保存 URI 后声称所有附件可恢复；在既有 meta_store 范围内保存有界用户附件是一条可实现路线，超限要可见阻止添加而非静默丢失。

附件 URI 恢复后属于待核对引用；不得直接沿用 `content` 缓存。发送前按当前 Agent 图片/嵌入能力、文件存在/可读性及大小重验，缺失保留条目并提供移除/重选；不隐式改 Agent/目录。用户显式粘贴的图片数据与磁盘文件引用分别处理。

## 实施依赖与关口

- 根任务统一 drafts/settings/queue 持久写入；本子任务只修恢复边界、固定选择、活动归档与连接状态。共同接口应提供按对话查找未发送编辑/意见，防止各菜单各写一套保护。
- 恢复完成边界可以完全在 Farfold 当前通道与官方 load 结果上实现；不需要外部包变更或第二份历史。匹配标记仅证明渲染器消费了该次 load 的回放前缀，不证明 Agent 未遗漏原本未回放的历史；后者必须由真实已知内容实验验证。
- Codex 原配置漂移、Pi 失败字段/续发以及各服务来源能否继续，是独立真实能力关口。源码保护通过不能关闭这些失败；本子任务没有新真实结果。
- 当前契约没有必要降级。若真实 Agent 确认无法保持原选择，只能保留正文可读与显式新开出口，并向用户提供该组合证据；不得擅自统一到默认推理或修改外部配置。

## 首条发送目标的恢复

根任务追加授权后，在 ComposerDraft 保存 pendingConversation 小型身份指针（实际 agent/canonical cwd/native session、可选服务选择与修订），不复制历史正文、不造索引。EmptyState 在实际发送前保存并等待 flush；unknown 保留指针，accepted 清理原提交，rejected 保留输入。Composer 向发送回调传原快照，避免第二次保存期间的新输入被误认成已发送内容；后续迟到接纳仅清理自己拥有的标记，保留后来输入。恢复按钮只打开实际保存目标或已有对话，不发送任何消息；失败保留内容与可重试原因。没有可恢复正文时保持原稿，另有需明确确认的“放弃本次重试”，说明请求可能已执行且不会撤销或自动重发，确认只清指针并保留输入。放弃确认取消时没有修改。

首发目标的工程覆盖包括：送前等待保存、实际目标/服务归属、cold 序列化恢复、明确拒绝、unknown 保留、接纳期间后来输入、恢复失败保留、显式放弃保留文字、保存途中放弃阻止后续发送，以及恢复入口显示。不存在真实 Agent 或安装验收新增声明。

## 后端归档准入补齐

`session_meta_archive` 保持原参数与单项结果，经现有 manager 找到准确 native session 的处理通道，在该通道内与 prompt/config 准入串行。正在发送、配置变更尚未结束、待审批、待填写、权限 required/unknown、模型选择未确认均拒绝归档。审批与表单同时核对连接所有权，另一 Agent 返回相同 native id 不会被误挡；同 Agent 的闲置对话也不会因其它对话活动而被禁止。复用已有打开预留排除正在恢复，不新增账本、表、持久活动记录。调用超时后已进入的数据库工作保留预留到实际完成。

meta_store 在一次 SQLite 事务里读取 `unsentWork.v1` 并写归档标记，覆盖普通草稿、附件、sendPending、队列编辑、文件意见、待发/未知队列，以及新对话首次发送的目标指针。未知版本或目标内容不可读时拒绝归档，解除归档仍可执行。改名与置顶改为只更新各自字段，避免迟到整行写重新带回旧归档状态。批量调用仍逐项返回结果，现有列表 `Promise.allSettled` 保留失败项选择并提示，不吞掉失败。

工程证据：先用当前行为提取出的原接口执行，运行目标与离线持久草稿两个反例均失败；修复后归档三项测试通过（其中复合场景包含准确连接归属、独立审批/表单、恢复预留、全部未发类别和并发 metadata 更新）。既有权限 subprocess fixture 增加 cold required 与超时后迟到成功仍 unknown 的归档拒绝断言，通过。全部使用临时 SQLite 与合成协议进程，未打开真实 Agent 或用户数据库。所改 Rust 文件定向格式化与 `git diff --check` 通过；完整 fmt/clippy/test、打包和安装由根任务统一。

边界：该顺序只保证本应用已收到且尚未结束的操作，及事务开始前已经保存的未发内容。先完成归档后才到达的新发送/外部通知不被追溯成原归档失败；前端已归档活动对话仍可达。连接结束后现有管理器会移除处理通道，没有官方 per-session 原子空闲查询，无法证明另一个独立进程中的同一历史无活动，也不能重建曾接纳请求的执行状态。无本机处理通道时只核对现有保存的未发内容；前端内存中尚未交付的编辑与断连未知由前端保护，不能声称后端知道这些不可见状态。没有用整 Agent 的活动永久阻止无关历史归档。
