# 认证与权限可行性审查

2026-09-27，当前保留工作区；范围 T2/T3/T5。先读 PRODUCT、architecture/status、计划 00.14 与当前 onboarding/reasoning/permissions 原型修订，再追踪源码。本报告最初结论来自源码和本日官方文档，未执行账号登录、退出、改密钥或模型请求；下文历史安装观察不能算本轮复现。后续修复与定向检查另记在文末。

## 结论

| 承诺                              | 分类                                   | 可落地边界                                                                                                                     |
| --------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 条件登录、认证方法驱动统一入口    | 可实现但需补代码                       | 已有明确 AUTH_REQUIRED 分支可复用；目录/来源必须贯穿认证和返回，不能只传 Agent                                                 |
| 标准终端、Qwen 官方设置入口       | 已实测可复用（仅旧候选的打开/关闭）    | 旧安装覆盖 Amp 取消及 Qwen 返回检查，不含可用账号成功；继续使用真实 PTY 和声明，不解析终端自然语言                             |
| 暂离、重开、取消、超时和迟到      | 可实现但需补代码                       | PTY 所有者和确认回收可复用；视图卸载不能等于取消；需内存输出重接和后台认证结果状态                                             |

| 输入框权限，真实值和说明          | 可实现但需补代码                       | configOptions/modes 可复用，须保留每项 description；普通 mode 不自动标为权限                                                   |

## 当前源码反例与边界

1. **原任务目标丢失。** `AgentAuthSection.tsx:19–28`、`agents.ts:194–207` 仅传 agentId/method。`auth.rs:378–392` 找不到已有设置连接就以 HOME 连接；`manager.rs:654–681` 按 cwd 排序选一个空闲连接；终端和手动路径同样固定 HOME（`auth.rs:493–498`、`manual_auth.rs:111–115`）。`AgentSetup.tsx:120` 还以空 cwd 汇总认证要求，并用应用默认目录做测试（142–145）。这不能证明所有 Agent 真实登录错误，但已能证明原稿目录/来源未到达执行层。
2. **共享账号保护缺口。** 终端与手动认证只有 configuration_guard，没有检查同 Agent 活动请求/待审批；协议认证仅要求被选连接空闲。`manager.rs:892–920` 现有测试甚至明确允许 A 忙、B 登录。`logout` 使用 `run_on_ready` 广播已有设置连接，没有先统一检查工作；官方协议明确不保证 logout 后活动任务是否继续。该风险不等于本轮观察到账号已被替换；应补共享作用域的原子准入。
3. **暂离目前实际取消。** `InlineTerminal.tsx:142–148` 卸载调用 `LoginTerminal.dispose()`，后者调用 close；后台 `PtyManager` 只有流式 sink，没有订阅/重放接口，`await_exit` 还会消耗条目（`pty.rs:246–268`）。保留真实子进程和输出的内存所有者，可实现同次应用运行内暂离；应用退出仍回收，不能承诺重启复活登录。
4. **认证超时是前后端状态分叉。** `operations.rs:170–212` 已发请求超时继续保留 lease 至真实结果/连接结束，且会发 best-effort 取消；`AgentAuthSection.tsx:228–235` 则无条件清 busy。后台迟到结果未发布可重接状态（230–245 丢弃 execute 返回），页面会重新允许操作却不能解释旧操作的最终结果。后端当前不会在同连接重复发起同一 lease，但不能据此声称整体防重闭环已完成。
5. **权限变更未知被压成普通失败。** `sessions.ts:849–855` 丢失后台未知分类并清 configuring；后台 `mutation.rs:71–92` 仍保留请求，`pump.rs:699–701` 阻止后续 prompt。迟到 config 成功只更新 ModelGuard 并发 configCheck（641–660），不主动发完整 config-option 更新；Agent 若不另发通知，前端旧权限值会停留。需要后台真实 mutation 状态/快照投送，队列继续暂停，不能依赖前端重试 setter 冒充查询。
6. **选择说明被丢弃。** `session_projection.ts:279–300` 只保留 value/name/group，旧 modes 的每项 description 同样被丢弃（335–352）。权限扩大确认需要真实说明及接入层核实的含义，不能凭 `category: mode` 或名字猜访问级别。
7. **新旧模式来源可能互相覆盖。** 初始化有真实 config category mode 时不合成 modes（`sessions.ts:445–454`），但 `current_mode_update` 无条件写所有 category mode（`session_projection.ts:457–461`），并未遵守当前官方同时提供时以 configOptions 为准。两路通知乱序应测。
8. **能力空值误判。** `auth.rs:238–244` 对 logout 仅 `.is_some()`；JSON `null` 也会开放。官方规范要求省略或 null 均不支持，只有实际能力对象才能开放。
9. **已建立思考锁需另片核对。** 当前 SessionOptionsList 仍渲染非模型选项；后端允许确认部分 thought 更新并保存（`pump.rs:648–654`）。最新 PRODUCT 要求首接纳后思考固定。权限改动不得顺带改变这一规则；本子任务不改会话模型层。

## 官方接口核查（本日读取）

- [认证](https://agentclientprotocol.com/protocol/v1/authentication)：标准终端复用已配置程序及参数，追加方法 args/env；零退出表示该终端流程成功，随后重连。未定义终端输出成功模式；logout 后活动任务效果不作保证。当前代码不能用重连成功代表实际模型可用。
- [配置](https://agentclientprotocol.com/protocol/v1/session-config-options)：new/load 等初始结果、set 回执和通知可给完整当前配置；选项和取值都有 description；category 只辅助呈现，不是授权语义。新旧模式并存时优先 configOptions。
- [模式](https://agentclientprotocol.com/protocol/v1/session-modes)：可能同时影响提示词、工具和审批，不统一等于权限。设置回执没有结构化当前值，需结合实际通知及恢复验证。
- [schema](https://agentclientprotocol.com/protocol/v1/schema)：列出 set_config_option/set_mode，没有通用只读 get-config。`$/cancel_request` 接收者可忽略，发送通知不是取消完成；仍需等待原请求结果或真实连接结束。
- [工具审批](https://agentclientprotocol.com/protocol/v1/tool-calls)：单次审批选项由 Agent 提供，不能把 allow_always 自动当成全局完整访问。

## 不能照搬原型的部分

- 不搬 Codex 固定三档给其他 Agent；OpenCode build/plan 保留工作模式语义。若需要把某声明显示为“权限”，在 `acp_client` 的已核实能力数据中提供语义，统一 UI 消费。
- 不搬“重新读取权限”计时器。正常迟到返回可以更新真实确认值；无结果时先保持未知。若必须以关闭并恢复原会话代替查询，UI 要明确是恢复连接，且不自动发送。缺 load/resume 或恢复改变模型/推理时，保留未知与新对话出口。把所有 Agent 都承诺成可无损重读会缩减/改变实际安全条件，需要用户先决定具体替代流程。
- 不搬通用认证五分钟或设备码卡片；没有结构化期限即不显示期限。协议取消只有请求和确认两个阶段，无法保证服务端撤销已完成的登录。
- 不把网页返回、终端退出、initialize、短测成功合并成账号/订阅/额度成功。已核实的注册链接可扩展为数据声明，不能生成品牌通用注册链接。

## 最小验证及修复顺序

1. 用现有测试内假连接/PTY 反例证明：A 忙时 B 登录被拒；取消未确认不释放；精确 cwd，不广播；logout null 不开放；过时调用和晚结果仍归原尝试。
2. 认证目标携带 Agent/cwd/source；来源非已有设置时不调用共享账号认证，提供 API 设置出口。页面返回目标和真实认证作用域分别保存于内存。
3. 认证执行所有权独立视图，真实终端输出在内存有界保留；重接不二次启动。取消等待后台退出；不可重启恢复秘密/终端内容。
4. 后台发布认证 waiting/unknown/completed/failed/cancelled；超时不释放受影响操作保护。取消 best effort 与实际结束分开。
5. T5 由会话层统一处理配置状态和安全恢复；先实测一个真实权限 Agent 的 new/set/受控工具行为/load，保留模型/推理，之后逐路线覆盖。
6. 最终安装版覆盖原稿目录返回、API 来源不能串账号、同 Agent 跨目录/另一 Agent 独立、暂离重接、关闭失败、迟到结果及真实请求。无账号仅保留相应未测项。

### 增补：纯附件历史与退出保存独立检查

父任务追加了共享可读消息修复。`message_attachments.ts` 只接纳带必需载荷的标准 image/audio/resource_link/resource；未知或缺字段事件仍为 raw，不能冒充正文。Agent 与用户消息保留附件，导入预览与正式对话使用同一显示；普通恢复由连续性子任务复用相同可读谓词。图片/音频只直接显示安全格式的内嵌数据，不自动下载远程资源；文本资源按纯文本显示，其他文件显示标识和不能预览的说明。应用不新增会话内容存储。

对 `draft_storage` / `draft_exit` / `DraftStartup` 的只读复核：发现退出仅使视图 inert 时，后台队列仍可能在最后保存与退出之间继续发下一条；已交父任务，父任务现已在保存前调用 `threads.pauseQueuesForExit()`。加载失败或未知草稿版本不会覆盖原值；单次写入进行中产生的新修改会继续串行保存；失败后编辑恢复可用，重试保存仍取最新内容。剩余明确边界：整份草稿中任一坏项/未知版本会阻止全部可编辑页面加载，只有重试出口；这保护原数据，但对确定性损坏不能自行恢复。进程强制终止、渲染器崩溃或无法完成本地写入时只能保证最后落盘版本，不应承诺零丢失。安装版退出/重启仍须父任务实测。

### 更新期间的工作保护

父任务追加更新保护后，已在 `managed_update` 中增加短期读写准入；它只随现有工作所有者存活，不记录任务或事件。配置/工作 lease、连接启动、认证尝试、真实 PTY 子进程、安装 Job 持共享许可；更新必须取得独占许可。关闭中的工作把许可交给原连接，直到真实子进程回收才释放。权限变更最后返回但仍为 unknown 时继续保留保护，明确成功或关闭后解除。

安装前有现存工作就直接拒绝，不等到替换应用后再发现；安装期间不接纳新工作。已有审批/停止以及保存草稿使用的 `settings_set` 不受此门禁影响。更新成功后独占许可转入 `ManagedUpdateAuthority`，直至进程退出，调用父任务的 `request_restart_after_save`；保存失败可以继续修复草稿，但不能开始 Agent 工作。更新失败会解除准入。冷恢复权限 required、已知模型不符或记录保存失败本身不是仍未结束的外部操作；在途配置仍由已有 mutation lease 保护。

Rust `update_` 过滤 14 项通过，其中本次新增的连接启动/真实回收两项通过；`managed_update::tests` **4 项通过**，包括独立更新准入、安装成功后保留以及失败释放；当前 `cargo check --offline --locked` 和 `cargo clippy --offline --locked -- -D warnings` 通过。这不构成真实发布基础设施或安装更新成功证据；没有执行更新下载/替换应用。
