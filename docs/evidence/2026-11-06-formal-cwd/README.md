# 正式应用的工作目录对照

在 macOS arm64 27.0（26A425）及唯一正式版 `68aefdb49` 上，对同一 Kilo 登记程序做了如下对照。程序路径和启动参数相同。四次子进程的实际目录都用系统进程接口核对。三次历史查找使用同一个界面入口，均从原生选择器选择相应位置。

| 工作目录         | 动作         | 正式应用结果                                                  |
| ---------------- | ------------ | ------------------------------------------------------------- |
| 应用默认目录     | 程序检查     | 初始化成功，界面可以继续配置账号与服务。                      |
| 桌面内原自测目录 | 查找已有对话 | 初始化超时，未发出列表请求。22次管道观察均有486字节留在输入。 |
| 桌面外自有空目录 | 查找已有对话 | 初始化和列表读取均完成，正式界面显示没有找到对话。            |
| 桌面内自有空目录 | 查找已有对话 | 初始化超时，未发出列表请求。22次管道观察均有486字节留在输入。 |

前序两份 Goose/Kilo 样本的系统库 UUID 与本机一致。本机反汇编确认它们的 `getcwd` 路径调用 `open(".", O_RDONLY | O_CLOEXEC)`。本轮两次 Kilo 桌面查询的主线程各有48个样本停在 `__openat_nocancel`，上层帧未符号化，尚未捕获调用参数或结果。终端父进程用同一无 Agent 的辅助程序做四类目录的 `posix_spawn` 对照，八个打开或取目录操作均成功。[Apple Libc 工作目录实现](https://github.com/apple-oss-distributions/Libc/blob/main/gen/FreeBSD/getcwd.c)

对照后只读查看系统设置，Farfold 的桌面访问开关显示开启。限定窗口的日志没有可归属的拒绝、允许或等待结果。证据定位到这台 Mac 的正式应用子进程在所测桌面位置的访问路径，具体阻塞机制待查。下一次应先取得可归属的系统调用结果，或核实实际启动环境变化，再重试正式原历史。原记录继续使用原工作位置。 [Apple 桌面访问说明](https://developer.apple.com/documentation/bundleresources/information-property-list/nsdesktopfolderusagedescription)

## 三家实际证据

- Goose 前次通过官方直连取得原自测记录的最终回复和33条更新，正式原历史仍缺终态。
- Kilo 本次通过官方直连取得原自测记录的最终回复和34条同对象更新，读取用时2.297秒。正式版在桌面外的空列表和默认目录连接按上述范围计证。
- GitHub Copilot 本次通过官方直连取得原自测记录的最终回复和48条同对象更新，读取用时3.842秒。正式版从全局准备入口完成连接，界面显示已读取当前模型选项。准备流程自动发出一次 `session/new`，本轮未发模型请求。测试进程在正常退出后已清理，未确认 Agent 侧新会话是否持久保存。

首波完整验收仍为0/3，三家的正式原对话续接、实际模型、审批和停止需分别补证。本轮零新模型请求、旧请求重发和审批操作。正式应用冷启动复核了原未发稿、1份保留草稿及原工作位置。两个自有空对照目录已精确移除。
