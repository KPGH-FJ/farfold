# 新草稿准备的模式恢复

本片只关闭受控协议回归。`8d46b23` 安装版的 Pi 模型读取失败观测仍保留；这里的通过不能作为重新安装后的真实读取、首条消息或续接证明。

## 问题与修复范围

准备选择中的 `mode` 可能由 Agent 返回的顶层 `modes` 合成。原恢复循环把它与所有真实配置选项一起发送到 `session/set_config_option`。不接收该配置 ID 的 Agent 会返回错误；设置失败提示进入 `warnings`，其余设置仍继续。

`pump.rs` 现在按声明分流：只有新草稿、可解码的顶层模式声明、且实际配置选项中不存在 `id="mode"` 或 `category="mode"` 时，才使用官方类型 `SetSessionModeRequest`。值须为声明列表中的字符串。真实配置模式保留原设置选项接口。成功且所属操作仍有效时，只更新返回的顶层当前模式，保留声明的其他字段；失败或取消保留旧模式与失败提示，不将迟到成功当作本次成功，取消后不发送后续设置。

本次请求要修改恢复会话的合成模式时明确拒绝；仅历史记录中含模式、没有新修改请求的恢复读取不受影响。新路由条件显式要求 `!resumed`，即使前一配置回执移除真实模式选项也不能进入新路由。已有模型、推理及权限准入规则保持生效。

## 官方依据

- [ACP v1 Session Modes](https://agentclientprotocol.com/protocol/v1/session-modes)：顶层声明提供当前模式与可用模式，切换使用 `session/set_mode`，请求值必须属于 `availableModes`。
- 已锁定并使用的官方 `agent-client-protocol-schema` **1.9.1**，本机缓存 `src/v1/agent.rs`：`SessionModeState`（1854 行）、`SetSessionModeRequest`（1985 行）、`SetSessionModeResponse`（2030 行）。官方响应无当前模式载荷；本片只在成功回执且操作仍有效时回写已声明的请求值。没有新增依赖或修改外部 Agent。
