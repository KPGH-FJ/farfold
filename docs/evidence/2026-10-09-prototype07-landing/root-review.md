## 已核对的正常保护边界

- 保留阶段的保存失败不清空当前输入；最终替换前再次检查输入对象、选择、generation、发送状态及附件状态。
- 恢复后的异步保存失败保留两份备份，并由现有全局保存错误阻止后续发送；UI 立即同步恢复的选择，避免文本显示在之前的 Agent 名下。
- 新建页恢复回调同步本地 Agent、文件夹、来源及复核状态，并清除旧预开 key。来源和模型是否可用仍交现有准备、认证及真实选项检查处理。
- 首发结果未确认的草稿不能通过“保留并新建”绕过确认；历史来源缺失与不可用 Agent 不自动转换为默认来源或其他 Agent。
- Rust 清理保护已识别 `resend:`，与前端 `hasUnsentWork()` 对重发内容的保护范围相符。

上述结论是源码和对应受控测试范围内的判断。真实进程、认证、停止回执、通知投递、安装替换及系统行为仍需各自证据。

## 对话库删除范围追加验证

新增 `ConversationLibrary.deletion.test.tsx` 验证真实组件回调：确认时冻结当前过滤范围；之后新进入归档的条目与其他 Agent 条目不会一起删除；任一确认对象恢复活动或不再归档时，整批在第一次删除之前终止。三个用例通过。

全量测试暴露的 `CollectionActions.test.tsx` 三个失败已区分并修正：标签新增计数后旧 children 断言失效；清空范围文案变化；旧 fixture 没提供实际保存索引而被新的状态复核正确拒绝。修正测试数据与断言后，相关五文件共 54 项通过，没有为通过测试放宽生产保护。
