## 原因与实际证据边界

第三步的自动读取及重新读取将准备进度 `selection.config` 全部传入 `AgentPreparation.prepare`；后者打开 `fresh: true` 的新准备草稿，将这份配置作为 `configOptions`。后端 `pump/open.rs` 在 `session/new` 后逐项执行配置接口，没有先比较返回的当前值。这混合了选项读取与参数修改，与 R5 第三步明确选择、读取/测试/保存分开的规则不符。

自动应用对象是准备配置中的所有条目，可能包含模型、思考强度及其他选项。前序实机只有 2 次配置请求的内容为空记录，不能确定具体 ID/值、是否改变模型或持久设置。可见 `zai-coding-cn/GLM-4…` 不能证明 Cohere 已核实，也不能证明从哪个值改变；本片没有新增实机推断。

真正恢复已有对话是另一条路径：`ThreadsStore.open` 用原 `nativeSessionId` 恢复，后端 `restore_config.rs` 核对服务与已确认的模型/思考选择。本片没有改动它、Rust 或历史数据。`prepare` 默认调用方式也继续保留既有配置应用语义。

## 最小修复

- 新准备页将读取标为 `readOptionsOnly`。仍保存原选择作比对，打开新草稿时交付 `configOptions: null`，不将旧条目作为配置请求。用户明确选定的服务 ID、修订及服务模型身份继续交付和校验。
- 健康读取与选择不一致分开处理：读取结果可显示，原选择不被同步覆盖，保存与测试被阻止；读取失败保留失败结果，只允许明确重试。
- 用户可明确重选并等待实际配置确认；若原选项消失或返回空选项，可明确点击“沿用当前设置”。该动作只接受本次健康草稿的实际返回值，不调用配置接口、打开新草稿或发送消息。
- 确认时重新核对当前目标、页面、步骤、最新准备进度、读取门、草稿身份、实时工作与错误状态。关闭页面、换步骤、改账号方式、失效目标或失败返回均不能通过旧回调确认。未匹配原意图的缓存读取也不能开始测试。

`AgentModelReadNotice` 是共用失配提示，未增加品牌页面或分支。为保持单文件限制，原测试状态文案映射等价移到 `preparationPhaseLabel`；`AgentSetup.tsx` 为 1492 行。`AgentSetup.repair.test.tsx` 只将旧的目录标题子文本断言对齐已有 R5 标题结构，仍检查普通目录与默认目录的真实 title；没有改动对应行为。
