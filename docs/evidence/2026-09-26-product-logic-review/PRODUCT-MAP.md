# Farfold 产品梳理：从用户目标到完整使用过程

2026-09-26 · 供用户评审 · 本文不是实施计划，也不替代 `PRODUCT.md`。

## 1. 产品目标与边界

**建议的一句话目标：让用户在一个桌面工作台里，选用合适的 Agent 完成事情，并能清楚掌握进展、处理决定、使用结果和回来继续。**

重点是用户完成的事情：交流、阅读、写作和编程都应成立。准备和管理 Agent 服务于这些事情，不应成为每次使用的主任务。

| 当前已有的产品边界 | 本文建议如何落实到体验 |
| --- | --- |
| 一个 Farfold 界面使用多个外部 Agent；Agent 负责自己的执行、工具、账号与历史 | 保留统一聊天、回应、内容查看和任务入口；差异在用户需要选择时说明 |
| Farfold 不做编辑器，不替代 Agent，不改写外部程序或用户配置 | 文件、文稿、网页和输出帮助理解结果；修改意图通过当前对话交给 Agent |
| 普通对话无需先选择项目；处理已有文件时明确选择资料文件夹 | 打开即可表达意图，只有任务确实需要时才补资料和工作位置 |
| 当前阶段仅 macOS；LifeModel 真实采集与注入不在范围内 | 不让未来能力成为开始工作的条件；静态说明不得造成已经生效的印象 |

**当前判断：** 有真实工作的基础，但准备、执行、整理与返回之间的规则仍不一致。问题不能只靠统一颜色、重排按钮或增加说明解决。

## 3. 用户理解的对象关系

**建议：以任务和对话为中心。** “任务”是用户要完成的事情，通常在一条对话中推进；不要求用户先创建一个额外的任务容器。

| 对象 | 用户应如何理解 | 与其他对象的关系 | 当前事实／需要明确的规则 |
| --- | --- | --- | --- |
| 任务 | 我想完成的事情 | 在对话中表达、推进与收取结果 | 建议作为产品叙事中心，不新增独立管理层 |
| 对话 | 与一个 Agent 连续完成工作的空间 | 容纳消息、过程、决定、结果及继续输入 | 对话功能已有；契约要求首条接纳后固定 Agent、服务、模型和推理选择，推理选择的实现仍不一致 |
| 草稿 | 还没有发出的内容与选择 | 发送获准后才进入正式对话 | 切页面保留已有基础；重启保留尚未成立 |
| Agent | 负责执行任务的助手 | 使用自己的程序、账号或模型服务；拥有自己的历史 | 同名条目应有足以选择的区别，不让用户猜安装身份 |
| 程序 | 让这个 Agent 在电脑上运行所需的软件 | 通常由准备流程处理；已有安装可以复用 | 多份安装是管理细节，不应默认成为多个难区分的助手 |
| 账号 | 使用某项服务的个人身份与权益 | 可能属于 Agent，也可能属于模型服务商 | 登录方式和收费并不统一；必须按实际入口说明 |
| API 服务 | 提供模型能力的一组服务设置 | 可被兼容的 Agent 选用；保存不等于已经给某 Agent 使用 | 已有集中管理；并非所有 Agent 支持所有服务 |
| 模型 | 本次对话所用的模型 | 必须连同服务来源理解；同名不代表相同服务 | 契约要求草稿可选、开始后固定，恢复不得静默换成其他选择；不以此行替代恢复实测 |
| 分组 | 我整理对话的分类 | 只改变归类，不改变 Agent、资料或工作位置 | 已有独立元数据基础，应保留 |
| 收藏 | 我想快速找到的对话 | 与分组、归档、执行状态互不替代 | 收藏不是“正在执行”，归档也不是“停止” |
| 资料 | 为当前任务提供的文件或内容 | 添加到草稿或消息；资料文件夹指定工作位置 | 选择文件夹不等于授予安全隔离保证，不应默认读取全部内容 |
| 内容 | 任务中需要查看或使用的文件、文稿、网页、差异和输出 | 与产生它的对话及步骤关联，按需显示在右栏 | 现有查看能力保留；不能把整个目录的变化算作当前 Agent 的结果 |
| LifeModel | 用户与 Farfold 长期拥有的知识与偏好 | 将来需来源与用户批准后才可进入工作 | 本阶段只有说明与预留能力，不参与实际准备或执行 |

用户应先理解“我要做什么、由谁做、用什么资料”；只有需要时再理解“使用哪个账号或服务”。程序路径、连接和安装版本属于进一步管理。

## 4. 十条主要旅程

以下是**建议的完整体验规则**，不是对当前实现的通过判定。每条都包含成功、失败和离开后的归宿。

### 旅程 1：第一次打开并开始一件事

- **目标：** 用户知道这里能做什么，并能从自己的任务开始。
- **成功：** 默认新对话；已有可用设置直接复用；缺少 Agent 时进入对应准备，完成后回到原输入。
- **失败／返回：** 程序、账号或网络条件不足时保留草稿，准确指出缺项；可换 Agent，也可离开后继续。
- **当前事实：** 默认新对话与跨页面草稿保留已有基础；完整新用户路径没有全部通过。

### 旅程 2：发现、选择并准备一个 Agent

- **目标：** 用户找到适合任务的 Agent，并完成必要准备。
- **成功：** 查看真实用途与限制，选择后连续处理缺少的程序、授权和配置；无需自己寻找下一页。
- **失败／返回：** 不支持的路径在选择前说明；安装失败保留旧选择，重试针对失败步骤；返回后仍是刚选的 Agent。
- **当前事实：** 官方目录、安装与准备页已有；本轮确认同名 OpenCode 难区分，Qwen 允许选入不支持的 API 路径；入口间丢失目标仍为旧审查证据。

### 旅程 3：使用已有账号、登录或选择 API 服务

- **目标：** 使用用户已有权益或明确选定的新服务。
- **成功：** 能复用就复用；必要时准确指向官方账号、密钥获取或登录位置；返回后继续原任务。
- **失败／返回：** 缺账号去获取账号，认证失败去处理认证，服务不兼容去选择可行方式；不以同一个“重试”覆盖所有原因。
- **当前事实：** 本轮 Qwen 已有设置路径在第三步出现认证错误，却没有直接去登录的主动作；API 路径下一页出现互相牵制的提示且无法继续。本轮未实际登录或发送测试；旧登录终端问题仍按历史证据处理。

### 旅程 4：选择模型并发出第一条消息

- **目标：** 让用户用明确选择的 Agent 与模型执行自己的任务。
- **成功：** 草稿中完成必要选择；发送被接纳后固定身份，展示真实回复；可主动使用短测试，但不强制先测试。
- **失败／返回：** 明确未发出则原稿可修改后重试；是否已发出不确定时不自动重发；补条件后仍回到原稿。
- **当前事实：** 首条接纳和草稿保护已有；本轮 Qwen 在模型选择与测试页被认证／API 条件阻断，未发送测试。市场必须通过指定测试、新对话无相同门槛的差异仍见旧审查。

### 旅程 5：提供资料、交流与迭代结果

- **目标：** 阅读、写作、编程和普通交流都能连续推进。
- **成功：** 用户知道本次提供了哪些资料；回复和结果可阅读、复制或打开；补充意见回到同一对话。
- **失败／返回：** 文件不可读、位置缺失或内容类型不支持时说明对象与原因，保留其他输入；关闭内容栏不丢未提交意见。
- **当前事实：** 普通目录、附件和内容栏已有；旧评审记录内容意见关闭即丢失，文稿定位能力尚不完整。

### 旅程 6：处理问题、审批与任务失败

- **目标：** 用户清楚知道 Agent 正在等什么，并能安全作出决定。
- **成功：** 每个待回应事项明确属于哪条对话、要做什么、批准范围是什么；处理后继续对应工作。
- **失败／返回：** 应答未送达保留输入并给可重试状态；已失效说明原因；切走、收起或整理不使待回应事项消失。
- **当前事实：** 统一审批、询问和待回应入口已有；全部真实并发与异常分支仍不能视为通过。

### 旅程 7：并行工作、停止与稍后继续

- **目标：** 用户能同时交给多个 Agent 做事，又不会失去控制。
- **成功：** 切换不打断后台工作；全局可找到正在执行和需要回应的对话；停止只有得到确认才表示已停止。
- **失败／返回：** 停止未确认显示具体受影响任务，不假装完成；待发内容保留，恢复后由用户明确继续。
- **当前事实：** 并行与停止机制已有局部实测；旧记录确认活动对话可被归档隐藏，需纳入整理规则。

### 旅程 8：寻找、整理并重新进入对话

- **目标：** 用户从大量对话中快速回到需要的事情。
- **成功：** 按标题、Agent、分组和状态寻找；收藏、重命名、分组与归档不会改变工作身份；返回保持列表位置与条件。
- **失败／返回：** 无结果时展示当前条件并可清除；整理保存失败仍保留原状态；同一维度不会暗中叠加两个互斥条件。
- **当前事实：** 对话库与整理基础已有；本轮复现 Codex 入口再筛 Pi 得到空列表，搜索仍不具备所有历史全文能力。

### 旅程 9：带入已有 Agent 对话

- **目标：** 找回在外部 Agent 中已有的工作，而非重新开始。
- **成功：** 选择 Agent、查找、预览并加入；明确区分可继续、仅查看和已加入；原身份与正文保持真实。
- **失败／返回：** 找不到、位置缺失、读取失败和不支持分别说明；不制造空白成功历史；部分成功只重试失败项。
- **当前事实：** 本轮确认三步入口与不自动发送说明清楚；本轮未执行真实查找、加入或继续，不重新宣称通过。

### 旅程 10：离开应用、重启并返回工作

- **目标：** 用户可以放心中断使用，不必记住哪些内容尚未保存。
- **成功：** 草稿与用户整理保持；历史按 Agent 的真实能力恢复；可继续时仍使用原选择，未完成事项有明确去处。
- **失败／返回：** 恢复失败保留可见内容与原因，允许针对性重试或明确新开；不能静默替换模型、变成空白历史或自动重发。
- **当前事实：** 部分真实历史恢复成功；旧记录仍有模型／推理变化拦截和重启丢稿，本轮没有重启复测。

## 5. 建议信息架构与页面唯一职责

以下为**建议**。保留现有三栏和统一组件基础，先消除页面职责重叠，不要求整体重写。

| 页面／区域 | 唯一主要职责 | 不应混在这里的事情 |
| --- | --- | --- |
| 新对话 | 表达任务、选择必要的 Agent／模型／资料并发送 | 不把完整安装管理和 API 表单塞进入口 |
| 当前对话 | 推进同一工作：回复、步骤、决定、输入、停止与继续 | 不在原对话里悄悄换服务或工作身份 |
| 右侧内容 | 查看当前关注的文件、文稿、网页、差异或输出，并将意见带回对话 | 不另开一套聊天，不代替 Agent 执行修改 |
| 所有对话 | 找回、筛选与整理对话，进入已有对话带入流程 | 不承担 Agent 安装与账号管理 |
| 需要回应／正在执行 | 跨 Agent 找到当前需要处理或关注的工作 | 不因收藏、分组或归档而漏掉活动事项 |
| 探索 Agent | 发现、比较真实适用范围，并进入选定 Agent 的准备 | 不把目录收录显示为完整可用 |
| 我的 Agent | 查看已添加的 Agent，继续准备或管理程序、账号与使用方式 | 点击 Agent 不应无说明地变成对话列表 |
| Agent 详情／准备 | 围绕一个明确 Agent 解决当前缺项，完成后回到来源 | 不另有一套与设置冲突的登录、测试和返回规则 |
| 设置：API 服务 | 管理可复用的模型服务与密钥，说明适用范围和使用影响 | 保存不自动授权给全部 Agent，不自动改变已有对话 |
| 设置：通用／LifeModel | 应用偏好、必要维护；明确说明未启用的 LifeModel 范围 | 未实现能力不作为日常导航的主要行动入口 |

左栏可以保留“按 Agent 查看对话”，但应作为对话筛选明确命名；它与“我的 Agent”的准备和管理职责分开。

“搜索”入口可以统一打开查找界面，但必须说清当前是在找对话元数据，还是查当前对话已加载正文；不能承诺不存在的全文覆盖。

## 6. 八条统一产品规则

1. **任务优先。** 默认从表达意图开始；程序、账号、服务准备只在缺少必要条件时介入。
2. **一件事连续完成。** 市场、新对话、设置进入同一个 Agent 的准备，保留来源、草稿与选择，失败直接到解决位置。
3. **测试可选，事实准确。** 固定短回复是诊断工具；首个实际任务可直接尝试，任何成功只说明实际覆盖的配置与行为。
4. **身份稳定。** 草稿可选择；首条接纳后 Agent、服务、模型与推理固定；换选择明确新开，恢复不静默改变。
5. **整理不改变工作。** 分组、收藏、归档与搜索只改变组织和访问；资料文件夹单独选择，同维度筛选保持唯一解释。
6. **状态给出下一步。** 准备情况、当前执行情况、历史能否继续分别表达；结束不等于成功，空闲不等于结果未知。
7. **用户投入不轻易丢失。** 草稿、资料选择、意见和准备目标具有一致的保留规则；离开后重新检查外部状态，不制造旧成功或自动重发。
8. **能力承诺有范围。** 在用户选择之前说明关键限制；保留 Agent 的真实能力，不用模拟成功或无限承诺掩盖尚未接通的部分。

这八条是对整条使用过程的建议。第 3、7、8 条包含需要明确产品决定的内容，不能把本文当作已经批准的变更。

## 7. 契约、原型与当前行为需要对齐的地方

| 当前材料 | 冲突或尚未明确的地方 | 建议判断 |
| --- | --- | --- |
| 契约允许已有凭据／免登录直接对话，未知不提前阻断；原型要求“选择与测试”后开始 | 是否必须先发送指定短消息；市场与新对话实际门槛不同 | 诊断可选，不以测试代替第一条用户任务 |
| 契约首条接纳后固定推理选择；旧评审确认界面和后台仍允许修改 | 规则明确但实现不一致 | 先保留已批准规则；不把现有按钮当作新产品决定 |
| 契约以“收到结束原因”定义已完成，同时要求失败和未知不能算成功 | 技术结束与用户任务结果混在同一用词中 | 结果按实际成功／失败／停止／未知表达；连接状态另列 |
| 契约承诺“不损失各 Agent 能力”，同时按实际接口展示不支持 | 是方向目标，还是对每个目录条目的当前承诺 | 逐项说明真实范围，不宣称目录中每个 Agent 均完全等同原使用方式 |
| 契约写切页面保留草稿，未写重启后的完整保留；当前只有内存草稿 | 用户对“回来继续”的基本预期未完整定义 | 将未发送投入与历史恢复分开制定保留规则 |
| 定位覆盖交流、阅读、写作、编程；现有主要验收更偏接入和代码执行 | 非编程价值缺少同等完整的结果验收 | 沿共同旅程检查四类任务，不以四张演示页替代真实使用 |

这里的目标是确定产品行为，不是增加一套新契约或以修改文字替代修复。

## 8. 最多三个需要明确的取舍

| 取舍 | 推荐默认 | 代价与边界 |
| --- | --- | --- |
| 是否每次准备都先通过固定短测试 | **允许直接做实际任务，测试可选** | 首次真实任务可能暴露缺项；用保留草稿和针对性恢复承接，不提前宣称已验证 |
| “回来继续”是否包含正常重启后的未发内容 | **包含草稿、选择和未提交意见** | 需明确保存范围和删除方式；不因此保存第二套 Agent 正文历史，秘密仍按现有安全规则处理 |
| “不损失能力”是无限保证还是明确范围的目标 | **以保留真实能力为目标，按 Agent 与功能说明当前范围** | 不用单一绿色状态概括所有能力；共同基础应可靠，差异在选择前说明 |

Agent、来源、模型与推理在首条接纳后固定已有批准规则，本轮建议继续遵守，不另开一个无必要的取舍。

## 9. 应保留的现有基础

- 默认新对话、普通对话不要求先选项目、独立三栏和按需内容查看。
- 统一回复、步骤、审批、询问、停止与输入；外部 Agent 保持自己的执行与历史。
- 分组与工作目录分离，收藏与归档使用现有对话索引，搜索不冒充全历史正文检索。
- 程序安装、登录和 API 管理已经形成的真实能力，以及对凭据与用户历史的保护。
- 已有对话的查找、预览、加入三步关系，以及可继续／仅查看和不自动发送的边界。
- 对模型恢复变化、未知结果和不支持能力的保护；需要改善解释和返回，不能删除保护制造顺畅假象。
