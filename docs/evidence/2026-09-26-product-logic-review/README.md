# Farfold 全产品逻辑与体验审查

2026-09-26。本轮围绕“把整个链条考虑完整、降低用户复杂度”梳理产品。保留现有多 Agent、统一对话与三栏基础，未修改产品代码或产品契约。本文是审查索引与证据说明，不是第二份活动计划。

**结论：已有可用的工作基础，但用户仍需自己协调准备、对话、整理和返回之间的状态差异。** 本轮现场确认了准备失败后的出口不足、不支持路线仍可选、同名 Agent 难区分、重复入口与筛选冲突；同时确认已有历史与差异可阅读、原草稿在本轮页面往返后保留。不能据此判定完整 J1–J6 通过。

## 六类产品问题

辅助使用风险：步骤 03 的小状态色点与同名选项增加辨认负担，尚未验证键盘和读屏是否能获得等价的连接状态说明；步骤 14 的禁用按钮无法作为可执行的恢复动作，用户需回退自行寻找可行路线。步骤 15 的图标按钮在可访问性文本中有名称，但这不代表完整读屏流程已通过。本轮未做对比度测量或完整键盘遍历。

| 类别 | 对用户整条流程的影响 | 本轮判断依据 |
| --- | --- | --- |
| 1. 同一个对象在不同入口换了含义 | 选择 Agent、管理 Agent、按 Agent 找对话的职责交叉；同名条目与重复目录增加判断成本 | 本轮 03、04、09；技术性目录简介见 01 |
| 2. 准备流程允许走进死路 | 不支持的方式仍可选，认证失败的主动作不对应缺项；回到原任务的规则不完整 | 本轮 12–14；入口间丢失目标仍按历史记录，准备与实际资料目录差异按源码风险保留 |
| 3. 状态没有回答同一个问题 | 用户难区分已连接、账号可用、任务已完成与历史能否继续；身份稳定性也有契约冲突 | 本轮 07、12；首次接纳后推理选项仍可改见源码核对，未现场修改验证 |
| 4. 未发送投入的保留规则不完整 | 正文、附件、意见和准备选择的生命周期不同，用户难放心离开 | 本轮 02→16 只证明页面往返保留；重启和文件意见丢失由历史记录及源码支持，未本轮重验 |
| 5. 整理和工作状态相互干扰 | 同维度筛选相交形成不可解释的空结果；整理可能隐藏待回应工作 | 本轮 05；活动对话归档隐藏属于源码风险，本轮未归档 |
| 6. 能力承诺比验收覆盖更宽 | 交流、阅读、写作、编程的定位，尚未都有同等完整的用户结果验收；目录和连接不能代表全面可用 | 产品契约与历史验收范围对照；本轮 08、10、11、15 的能力边界说明值得保留 |

这些问题跨越多个页面，不能只逐个修改组件文案。保留统一对话、独立内容栏、元数据分组、真实能力提示及不自动发送等已有基础，重点让规则在各入口保持一致。

## 建议的处理顺序

1. **先统一状态、身份与输入保留。** 明确轮次结果和当前连接状态；兑现首条消息后的身份规则；统一草稿、附件、意见和待发内容在切页、关闭与重启时的归宿。
2. **再打通入口连续性与完整任务流。** 从原草稿进入准备，失败时直接处理所缺条件，准备后回原任务；不支持的路线在选择前说明；恢复、导入与重试使用一致且真实的完成条件。
3. **最后收敛信息架构与视觉。** 明确探索、管理、按 Agent 查对话的职责；同一维度只呈现一套有效筛选；统一名称、状态层次和内容密度。

以上是评审建议与依赖顺序，不是实施授权、完成声明或第二份活动计划。未来修复仍须按唯一活动计划推进，并在同一安装候选上验证正常、失败、取消、返回与恢复路径。
