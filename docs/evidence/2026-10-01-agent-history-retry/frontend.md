# 历史读取失败后的明确重试

本片修复已成功返回的历史读取未通过准入后，再次读取同一目标会碰到仍存在的后台连接记录。改动范围只有前端状态与受控回归；正式应用、真实 Agent、后台源码及用户数据均未在本片定向检查中操作。

## 已证机制与现场边界

上一候选 `59985da` 的 [安装证据](../2026-10-01-agent-history-recovery/README.md) 中，siGit 首次冷恢复明确显示空历史读取失败。点击一次“重试读取”后却退回普通打开失败，并丢失新开会话出口。旧候选的 [内容无关协议收据](../2026-10-01-agent-history-recovery/protocol-metadata-final.json) 中，按启动时间与采样身份对应的 siGit 文件只有一次 `session/load`；不能仅凭协议数组位置配对 Agent，也没有读取响应正文或外部历史。

源码链条可以独立复现：成功的恢复返回先保留后台会话记录，前端随后因空内容或缺少完成标记拒绝历史准入。旧 `threads.reconnect` 未关闭该记录就再次调用 `session_open`；[pump 的已有记录检查](../../../src-tauri/src/acp_client/pump.rs) 会在第二次 `session/load` 前拒绝。前端普通失败处理继而清掉有限历史读取失败状态。现场没有捕获这次本地拒绝的原始错误正文；“已打开”归因来自源码及保留记录的有状态反例，而不是将短错误文字当作证据。

`configOptions: null` 的重读会沿后台已有索引读取原选择与服务，不表示丢弃原模型。本片不改变模型、推理或历史准入保护。

## 实现边界

- [sessions.ts](../../../src/runtime/sessions.ts) 将关闭与读取统一放入现有 `open` 去重操作，覆盖显式重读、列表重开与它们的并发。同一严格目标只关闭、读取一次。
- [session_recovery.ts](../../../src/runtime/session_recovery.ts) 仅对已保留的历史失败目标调用精确 `session_close`。`allowAlreadyClosed: true` 使用现有后台的已确认无记录出口；服务错误仍沿原关闭策略。关闭未知或失败时保留原正文、队列、历史失败、服务及保护字段，不继续读取；确认关闭后才撤销旧通道资格。旧通道迟到断开不能覆盖新读取，关闭等待中明确移除的状态也不会被复活。
- 普通连接恢复不增加关闭步骤或异步空等待。原真实断开事件继续使用既有停止状态语义：已观察断开会清除停止未确认，未知请求与队列保护仍保留；没有断开事件时不清除原停止未确认。
- 旧索引路径未命中而该 Agent 尚有已恢复状态或历史失败状态时，只复用 `agent_work_get` 的已验证 `cwd`，再按 Agent、目录、会话 ID 严格查找和去重。已有状态只提示是否需要校验目录，不能选定会话归属。不应用返回的工作策略，不搜索同名会话，不迁移索引，不新增别名表。接口拒绝或返回非法目录时不退回原路径启动。这是额外的读取失败边界，保留明确失败供下一次重试。
- 该目录校验自己产生的失败占位带一个仅内存的 Symbol 标记，独立允许再校验，不依赖另一页面仍失败；普通打开失败不借此被重新分类。再校验成功后，只有默认空占位、无独立未发内容、无发送中或待确认新稿时才可移除。原页面有内容、队列或保护字段则保留并说明原因，不合并两个目标。`hasUnsentWork` 和 Composer 额外状态均参与检查；错误说明发布使用现有通知路径的保留队列选项，不同步覆盖独立队列。标记不进入存储、日志或协议。

新 [有状态回归](../../../src/runtime/sessions.history-retry.test.tsx) 的 IPC 夹具保留成功读取后的后台目标记录，真实执行前端状态模块，不把每次读取当作全新连接。24 项覆盖空历史再次失败、可读重试、断开前后、关闭失败与已确认不存在、精确来源与目录隔离、普通恢复、列表入口、并发、别名目录、非法目录、移除中的状态、校验失败后再次成功，以及正文、队列、Composer 和待确认发送的保留。终审新增成功后从原路径再入、失败占位期间另一页面成功、成功后仍保留原输入三例，各用独立 Agent 身份避免其他夹具的失败状态掩盖反例。
