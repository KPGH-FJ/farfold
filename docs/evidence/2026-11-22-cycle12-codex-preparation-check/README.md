# 第 12 周期 Codex 模型准备页的实际权限检查

2026-11-22，北京时间。共用模型准备页在已有设置路径下增加「检查实际权限」。需要当前程序、工作目录和模型选项都已匹配；切换目标、离开或取消会结束本次检查并丢弃迟到结果。独立检查保留原稿与选项，回执没有修改现有对话权限、注册或发送资格。

## 官方 CLI 的断网走查

检查使用已登记程序对应的官方 App Server。固定交换只发初始化、读取本机保存的账号工作区、创建无历史的临时只读对话；没有用户正文、模型推理或在线预热。官方返回原本机登录与工作区、OpenAI `gpt-6-astra / Ultra`、实际只读、关闭工具网络、用户审批及空对话。网络和子进程由系统隔离。使用已核对的原安装标识，进程退出后复核原文件身份、字节和先前的临时目录。预热、错误和账号原文不进入回执。

独立测试载入产品的同一份启动和协议代码，同进程临时对话通过了全部检查。真实负控确认本机回环与外网 IPv4/IPv6 均被拒绝，不能读取或写入夹具外的测试文件，也不能访问系统安全存储。没有使用正式安装的 Farfold 界面或打开旧对话。 [最终脱敏回执](mcp-status-receipt.json)

- 首次接线检查在握手前退出。系统记录显示缺少 `/etc` 等启动查询需要的目录元数据；只增加精确路径的元数据读取，保留原数据写入、外网及子进程限制。 [启动失败原件](first-official-receipt.json)
- 补上元数据后，官方实际对话回执已到达。Farfold 先拒绝了同一对话的官方提示，后续按官方字段接收这条提示，以及同一对话的工具连接「开始尝试」「失败/取消」状态。实际就绪、工具调用、审批回调、其他对话通知仍无法通过检查。最后样本只有 `starting → failed`。 [提示归属原件](rejected-frame-receipt.json) · [官方提示字段](https://raw.githubusercontent.com/openai/codex/rust-v0.171.0/codex-rs/app-server-protocol/schema/json/v2/WarningNotification.json) · [官方工具启动状态字段](https://raw.githubusercontent.com/openai/codex/rust-v0.171.0/codex-rs/app-server-protocol/schema/json/v2/McpServerStatusUpdatedNotification.json)

## 正式验收边界

此版本源码已接入共用准备页。前端用受控输入核对显示、取消、迟到和设置变化。实际正式安装的准备页仍待 macOS 走查。该检查只核自有临时对话的实际权限，没有替原 ACP 对话授权。当前本机旧登记的 CLI 0.155.1 缺这次用到的工作区读取接口；独立的 0.171.0 用于本批真实协议复验。新 App Server 日常会话的首次发送、审批、停止和同对话重开继续待接。
