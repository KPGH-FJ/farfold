## 通知现场结果

29ed正式OpenCode沿用户已选Xiaomi MiMo V2.6 Flash，仅发送一次自有公开W3C页读取请求。用户原话：“没有声音，点击后回到了opencode对话，通知出现了一次”。原请求获准后结束；5cc正常冷开看到新标记、答复及此前三条请求，零自动重发。

同一通知的macOS原件独立核实：一次提交/显示，声音载荷存在；系统以`displayShared`/`display shared`抑制声音，随后收到同一通知内容点击并唤回Farfold。不能把提交声音请求写成实际响铃通过，未推断是哪款共享软件导致，未改变系统设置。

页面已关闭、许可撤回，三项提醒偏好恢复全关。此次通过一条待确认通知的显示、点击定位和单次出现；当时其他提问/中断类型及实际声音未齐；提问后来另验如下。P48原完成通知正例保持，不能由待确认通知补认完成声音。

旧OpenCode数据库采集未找到唯一新标记，精确旧目录也不存在；失败原件保留，未重采或广扫。正常冷开UI证明本次内容可读，不代表已核当前原生数据库逐行字节。

9f后续同一OpenCode/MiMo/Build仅新发一次颜色选择请求，真实官方question表单出现；用户确认“看到了，点击回到颜色卡，只出现一次”。选择蓝色并提交一次，原请求正常回答“你选择的颜色是：蓝色。”，等待状态结束。系统同一通知一次接收/显示/内容点击核合，声音本次主动关闭。提醒偏好随后全关恢复并正常退出。这里的发送次数指Farfold实际用户请求，不代表统计过服务端API调用次数。

系统显示另从1920×1080临时改为1280×720（系统显示为缩放分辨率），正式应用截图1280×634：首页、历史带入弹窗底部操作和设置提醒区域均可见可达；随后恢复1920×1080。本机窗口菜单没有半屏入口，一次侧边调整未改变尺寸即停止。该正例不替代精确900×620、更多关键界面、大字号或任意Retina比例。
