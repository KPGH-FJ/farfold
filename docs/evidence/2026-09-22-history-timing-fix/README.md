# 历史工具耗时修复与定向复验

结论：**该显示缺陷已修复，工程检查及安装版真实 OpenCode 定向复验通过。** 这不代表 W0–W8/J1–J6 全部出口或用户真人签收通过；其他已知失败和未测项不随本片关闭。

## 定位与方案

修复前，同一真实工具在实时界面显示 23.6s，重启后变为 `<1s`；本轮再次观察旧安装版，截图 01。原始执行证据见[上一轮验收](../2026-09-22-acceptance/README.md)。

`session_projection.ts` 用本地接收时间生成工具开始/结束时间；`sessions.ts` 恢复历史后只清除普通消息时间，遗漏工具；`thread-items.tsx` 将二者差值当执行耗时。回放速度因此变成了虚假的历史耗时。

方案及实现：恢复历史时，将工具开始时间设为既有的未知值 0，结束时间置空。收到完成事件时，只有曾观测到开始才记录结束时间；首次出现就是 completed/failed 的工具同样保持未知。界面在时间不完整时显示集中中文文案“耗时未知”。恢复后的新工具仍正常计时；后续历史更新不能重新生成一个假耗时。工具内容、产物、状态和模型不改，不新增持久化事件或依赖，不改 Agent。

## 保留边界

当前支持的回放事件没有可用的原始耗时；本片诚实显示未知，没有恢复已丢失的精确秒数。实时计时仍是客户端完整观测区间，不宣称为工具 CPU 耗时。Codex 模型漂移、账号相关验收、MCP/Skills、性能前后对照及其他未测分支继续按唯一计划跟踪；未展开上线准备。
