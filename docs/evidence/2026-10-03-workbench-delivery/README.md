# 文件成果交付与浏览器短验证：本片证据

状态：文件底座与用户已批准的文件交付界面已落源码；浏览器新容器仍在隔离验证，尚未上线。正式应用未更新；本片实施进度仍归唯一活动计划。

## 用户范围与本片结果

用户已批准文件 UI 方案，并明确保留内嵌公开网页方向。本片复用现有对话、内容栏、文件意见和 Agent 执行方式，没有另建 Agent 循环、任务账本或发送队列。保留内嵌方向不等于浏览器已经可用，也不把公开页面验证扩大为真实登录或日常浏览环境操作。

文件底座已提供核实、受限文本读取、文件复制、文本快照导出、系统打开及定位接口。核实回执包含实际路径、大小、摘要及版本；后续读取、复制和打开前重新核对。普通候选限制在当前工作文件夹内；用户经系统选择器明确选择的文件走单文件入口，不把它的父目录保存为通用授权。IPC 检查主窗口与允许来源，远程网页不能调用这些交付命令。

界面真实接线范围：

- `ArtifactPane` 传递原对话 `cwd`，`FileArtifactView` 复用原布局增加文件交付操作。
- **仅 `source === "diff"` 且 `status === "completed"` 的卡片路径提供自动候选入口**；仍须用户点击核实。写入/编辑参数中的路径不冒充已生成成果。
- 无候选时可明确选择文件，或导出该卡片的**修改后文本快照**；后者不是原文件，也不代表完整文档。
- 核实后可打开、定位、另存及读取当前文件。磁盘文本独立显示，不改写 Agent 返回片段，不把新内容套用到旧意见或旧行号。
- 文件变化或操作失败清除旧确认和磁盘预览，原片段与意见保留。组件版本、操作序号、卸载与活动页保护拦截重复点击及迟到结果；系统对话框取消不触发交付。
- 文件意见继续沿现有“加入原输入框 → 用户确认发送”路线，不新增自动发送或改写队列。**本片未证明“意见发送 → 真实 Agent 修改 → 新文件核实”的完整返工闭环。**

## 明确限制

| 项目     | 当前边界                                                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 大小     | 文件核实、复制与打开前核验上限 **32 MiB**；文本读取及快照导出上限 **1 MiB**。                                                                                                                                  |
| 格式     | 当前磁盘预览只接受 UTF-8 文本；PDF/Office 不因可定位或系统打开而视为 Agent 已读取，未新增全格式预览。                                                                                                          |
| 文件来源 | `reportedFiles` 已有 diff、部分协议位置及本地 resource/link 的解析基础；**这些其他结构化来源尚未接到所有产物卡片**，不能写成所有工具成果自动识别。                                                             |
| 系统打开 | 打开前会重核并限制可直接打开的文档类型，但系统按路径交给另一进程。**核验结束到目标应用实际读取之间仍有跨进程路径替换间隙**，不能保证目标应用读到的内容永远等同已核版本。定位也不能保证之后的人工打开版本不变。 |
| 授权     | 工作文件夹不是系统沙箱；单文件选择不授权扫描父目录。已保存浏览环境、登录状态及页面分享是不同事实。                                                                                                             |
| 浏览器   | 新容器仍在隔离验证，尚未接成生产共享浏览器；未证明 Tauri 容器、MCP、Agent 和用户操作同一页面的完整集成。静态 HTML 预览继续保持原隔离。                                                                         |

## 本轮发现与修正

应用切页保留对话挂载，原交付控件只核卸载，导致隐藏页的选择/保存弹窗返回后仍可能继续操作。3个受控失败样本确认后，透传既有 `active`；失活使旧操作序号失效，恢复不复活旧弹窗。已经提交的文件操作保持等待自然收尾，不冒称取消；隐藏期间失败仍清除旧确认和预览，只在当前页面显示错误。第二个失败样本核实这一分支，最终组件19/19通过，纳入全量1724项。原始RED/GREEN日志见 `ui-active-fix/`。

另一个独立原生WK子视图小样通过16/16：同一NSWindow的父WK只有合成应用桥，新同窗WK使用独立controller和非持久store，真实页面看不到该桥，也不能调用父处理器；固定隔离世界读取真实DOM，关闭后拒绝继续读取/调整。没有运行Tauri应用或访问真实通道，只证明候选容器核心隔离方式。以上16/16是前序独立小样边界；后续Tauri接缝及受控MCP证据见下节，正式布局/焦点与用户同页共享仍未闭环。

普通Tauri远程子视图的内置channel fetch路径需要进一步核实来源约束；当前没有利用或证明漏洞。本片继续验证无应用桥的原生WK方向，没有修改内置插件、放宽远程权限或启动远端网页。网络目标检查不构成系统/网络沙箱，公开网页方向不承诺任意网站或登录兼容。

## 后续真实 Tauri 接缝与受控 MCP 验证

`tauri-seam-probe/` 冻结真实 Tauri 2.11.5 探针的13个源文件、日志与回执，排除可执行文件及缓存。它使用新的内存上下文、非持久主页面和合成内容，不加载 Farfold 配置、插件、用户存储或正式应用。官方 `main.with_webview` 挂载独立 WK，19/19 检查通过：主页面自身 invoke 与大消息 channel 往返正常，独立页面没有应用桥，实际 DOM 可读，读取中关闭仅返回取消，关闭后操作与迟到回调受阻。这证明具体容器接缝可行，不能代替正式应用的布局、遮挡、失败重试与导航乱序检查。

`mcp-controlled-probe/` 冻结标准 stdio 初始化、工具发现及一次有效 `read_page_snapshot` 调用。本次调用实际启动新的原生探针并核对 requestId/取得时间，没有转发旧回执；未授权/旧版本与关闭后读取拒绝。协议与授权18/18、官方 ACP 2.2.0 new/load 类型及 wire shape 4/4通过。独立审查留下2项失败复现后，已修复探针失败/超时/坏回执后旧一次性授权未回收；成功原生回执早于此窄修复，修复由18项无GUI测试证明，未为此重复运行页面。

生产缺口仍很具体：外部 Agent 启动的 stdio helper 不能直接调用主界面受来源保护的 Tauri command。必须验证最小受控本地通信，令它与 UI 调用同一个页面读取服务；scope由应用授予，不能信任工具参数中的任务名。之后再接实际分享、撤销/秘密暂停与恢复，并用受支持代表 Agent 核工具发现和读取。当前生产 `session/new` / `session/load` 仍为 `mcpServers:[]`；未调用真实 Agent、模型、账号或公共网站。不能把短命合成页的MCP成功称为生产共享浏览器闭环。

Library交付已恢复：先读回规划同一身份版本2，再以版本保护更新为3；浏览器评审稿单独保存成功。此前失败均发生在只读工具发现阶段（DNS、TLS或响应截断），尚未发出文件保存调用，无权限拒绝，也未通过重建规划绕过冲突。浏览器交互问题已发出，仍待用户答复；它只评审打开/读取/关闭与切页收回，不重新确认内嵌方向或文件交付批准。

## 最后补充：MCP 读取持续运行的同一页面

`running-page-host/` 与 `mcp-running-page/` 保存一次完整受控运行：标准stdio MCP薄工具通过私有AF_UNIX通道，读取已持续打开的真实Tauri/WK合成页。正文从one原地变成two，第二次真实提取得到新内容；同一原生对象检查通过，最终创建1次、实际读取3次。第三次读取在原生结果产生后、发送前被持有，撤回后返回错误且没有正文；关闭后MCP与直接Host请求都拒绝，随后最终计数确认没有偷偷重建。这解决前一探针“每次新建页”的证明缺口，不等于正式Farfold共享已落地。

服务端错误capability与错误scope分别拒绝；范围来自服务端，不由工具参数授予。目录0700、socket0600、同用户、临时授权仅经匿名管道交接。薄层9/9通过；root复核发现final检查与socket写之间的撤回竞态，保留真实UnixStream并发RED，再以同一出站门控序列化最终授权、有绝对1秒截止的写入与撤回/关闭确认，GREEN1/1。原生观察等待不持该门控。撤回只阻止尚未发出的内容，不承诺追回已经写出的字节，也不代表完整秘密输入保护。

重要生产边界：此独立launcher可以向两子进程交接匿名管道，标准ACP `McpServerStdio` 只有command/args/env，没有任意继承FD字段。真实Agent官方启动面能否安全交付临时授权、如何避免诊断/持久化泄漏、恢复时如何重授，仍需代表机制验证。不能直接把探针启动器纳入生产或把秘密塞进argv；没有因此改Agent配置、开放网络接口或创建通用浏览器平台。

该同页Host复用修复后的原生源码，但没有将完整BrowserWorkspace Rust命令编排、正式应用布局、用户分享/秘密暂停UI或真实Agent接通。此次所有自有进程正常退出，临时socket清理；未网络访问、登录、模型调用、打包安装或提交。进一步正式界面接线等待已发出的交互评审；不重复已有批准，也不以本次结果关闭五条产品闭环。
