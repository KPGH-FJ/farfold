## 最需要保留的差异

1. **已有设置是独立路线**：已有身份可显示、没有身份但可继续、明确需登录、检测失败、工作阻止账号操作分别观察。登录方式存在不代表必须登录。
2. **四种“Key”不能混为一页**：Agent 自行执行的 API-key 名称方法；协议提供方专用密钥表单；旧环境变量声明/手动配置；中央 API 服务选择。名称不决定执行类型。
3. **终端也有不同收尾**：标准终端、经核验的旧终端扩展、设置服务终端、需要返回检查的交互终端共用容器，但目的、完成判断与返回路径不同。
4. **中央 API 当前仅两家有已开放路由**：OpenCode 的 Chat Completions / Responses / Messages，Codex 的 Responses。其余 27 项沿用 Agent 自有设置与协议方法，不能用中央 API 页面代替它们的准备流程；这不表示 Agent 本身不支持 API。
5. **程序准备至少三种安装工具链**：二进制归档、npm/Node、uv/Python；另有伴随 CLI、已有程序、多版本管理与无法自动安装。安装成功、连接成功、账号和模型准备分别记录。
6. **模型至少四种数据结构**：现代配置、旧 models、只有模式/固定设置、声明尚未知；现代配置内部还包含模型+提供方同类别、多推理项、权限与其他配置。没有控件与尚未读取不可互换。
