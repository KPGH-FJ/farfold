## 建议最先补的交互复核

1. **已准备 Agent 的管理往返**：分别从探索、设置和对话进入，核账号/程序/模型实际可访问性、原因提示、关闭返回位置；先覆盖无需改变账号/服务的检查。图 05/06 的模型标签必须实际观察按钮状态和点击结果，不能用颜色定案。
2. **权限待确认的恢复**：定位真实入口，核选择/取消/失败/确认后放行与草稿保留；仍未发送时不凭按钮变化判 Agent 请求成功。真实审批快捷键另需真实待处理请求。
3. **29 项共用配置呈现矩阵**：逐项记录入口、实际声明、未知/未准备/可用/忙碌状态、等待、取消、返回、失败出口。每格标“已观察/未观察/缺条件”，把 UI 配置核对与登录/真实消息分开；不以代表 Agent 自动填满其余 28 项。
4. **新对话与资料**：Agent/模型切换、无位置发送前选位置/取消、附件读失败、草稿切页、返回与重启。没有这些过程不能称对话基础 UX 已验收。
5. **内容栏完整类型及网页生命周期**：核文件/差异/日志/网页各自入口与退出；网页载入、收起、关闭、切页和授权失效分别记录，真实工具成功另记。
6. **未打开的管理与设置面**：全量列表过滤/整理/行菜单、导入/导出、API 表单、通知、数据隐私与退出。破坏性确认可以先只观察并取消；执行结果须有明确对象与相应授权，不为凑覆盖删除用户数据。
7. **键盘和窗口尺寸**：对关键页面/弹层检查 Tab、Escape、Enter、输入法合成、焦点归还、窄窗与深色，确认动作能找到且不误执行。对比度、读屏、系统通知和 Windows 各自保留未测，不给截图合规结论。

这些建议没有重新引入已撤销的整组六条旅程门槛；它们定位当前用户所问“全部页面/连接/UX”的证据缺口。真实账号、密钥、付费请求及破坏性操作仍按原授权边界处理。
