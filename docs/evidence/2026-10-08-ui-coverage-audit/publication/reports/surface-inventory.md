## 安全补看顺序

以下是走查建议，不是本清点已经执行的动作。每一步先核当前应用/对话状态；原有任务、草稿、账号和设置保留。不能因标记“缺图”自动取得登录、安装、真实请求或删除授权。

1. **优先补 Agent 管理的静态层**：既有 Agent 详情、三步导航、展开程序详情/管理、展开账号管理；确认模型页是否可到达、禁用原因和返回路径。移除确认只预览后取消。选择账号方式可能立即启动认证；模型页可能自动准备连接或读取配置，不能把点击方式/继续当成纯展示。当前条件不允许就记录未到达，勿反复尝试绕过。
2. **补共用弹层**：新建与已有对话的模型列表、思考菜单、权限菜单、配置摘要；权限确认只看不提交。附加/命令菜单只展开，避免执行或改写原草稿。自定义 Agent 表单仅查看，不保存。
3. **补管理入口**：全局搜索、库筛选/空结果、行菜单、批量选择后取消、分组和重命名对话框后取消、删除/清空归档确认后取消。保存位置选择器不导出、不覆盖。导入先看选 Agent/位置步骤；“查找”可能启动 Agent 并读取其历史，不当作静态菜单直接执行。
4. **补设置完整层级**：通用页下半部、快捷键、隐私、清除确认后取消、高级发送列表、诊断。API 指南/新增空表单可以查看；编辑既有服务不输入/回读秘密，不保存、读取模型或测试。更新检查可能访问更新源，安装与下载另计，不执行替换。
5. **补真实文件与网页呈现**：使用明确获准且已存在的非秘密样例，记录文件核实、全文、差异、HTML 和公开页。只在授权范围内操作；共享确认、读取或动作请求与普通打开页面分开。无样例或无相应状态则保留缺图，不能用工具输出充当文件证据。
6. **再覆盖条件分支与交互质量**：认证/安装/发送/审批/停止/结果未知/破坏性结果，优先用受控测试资料或等待之后明确授权的真实任务；把 fixture 与安装版证据分开。深色、窄窗口和键盘走查需另记录实际结果；改过的展示设置恢复原值。

完整的 Agent UX 评审至少需要连续观察“进入→知道当前状态→知道下一步→返回/取消→再次进入”的过程。此次清点只说明应看哪些界面，不宣称这些缺图界面已有 UX 缺陷，也不把补截图升级为新的真实账号验收门槛。
