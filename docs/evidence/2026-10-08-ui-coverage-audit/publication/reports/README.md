## 新增发现，按优先级

### 优先修复：两处明确布局故障

1. **命令菜单长说明互相覆盖。** 新草稿→命令与模板，在当前 Codex 返回的长命令/Skills 列表里，中下段多行文字覆盖其他选项，菜单超过可视高度；关闭再打开仍复现。应使行高随内容正确伸展、限制菜单高度并可滚动，将长说明折叠或截短后查看完整内容。保留 Agent 提供的内容，不把原始英文当作 Farfold 自有术语违规。证据：[42](../file-inventory.html#file-319)、[43 再次打开](../file-inventory.html#file-320)。本轮未选择任何命令，未断言所有命令均无法执行。
2. **数据与隐私说明被压成一两字宽的竖列。** 设置→通用→查看说明；上半页正常，清除数据、卸载标题与说明窄到无法正常阅读。滚动后仍如此。展开清除范围时，右侧删除/保留列表可读，左侧说明继续挤压。应修正这些分区的宽度、布局和换行，并复核较小窗口。证据：[29](../file-inventory.html#file-306)、[30 滚动](../file-inventory.html#file-307)、[31 范围确认](../file-inventory.html#file-308)。只展开并取消，没有清除。

### 优先改 UX：让用户有依据做下一步

3. **模型差异未并列展示。** Codex 管理可直接点进模型页；读取后显示 `6.1 Sol`，并提示当前设置与原选择不一致，保存按钮 AX 明确禁用。页面未并列列出原选择、当前值与差异；“沿用当前设置”也没给具体值。应展示真实差别及每个动作的结果。顶部“可以使用”可能指连接准备状态，不能直接认定该标签错误。证据：[18](../file-inventory.html#file-295)、[19](../file-inventory.html#file-296)。草稿选择器仍显示保留的 `6 Astra`（[40](../file-inventory.html#file-317)），本轮未切换或保存。
4. **账号管理没有可核对的当前来源摘要。** 已有设置页及展开管理只有“已有设置”、重连、换方式、退出、切账号等动作。应先显示 Agent 实际提供的账号/服务信息；信息未提供时明确未知，不猜测身份。证据：[20](../file-inventory.html#file-297)、[21](../file-inventory.html#file-298)。本轮未检查底层是否能取得这些信息，故不把“没有显示”写成“丢失账号”。
5. **API 获取帮助增加步骤，却没有具体指导。** 添加 API→查看获取流程→输入 `OpenAI`→继续，终页只提示自行获取、使用官方入口，再返回配置；没有定向帮助。保持不猜链接的边界，可以把通用说明合并到原表单，或在确有可靠信息时提供具体指导。证据：[24](../file-inventory.html#file-301)→[25](../file-inventory.html#file-302)→[26](../file-inventory.html#file-303)。这不是 API 请求失败。

### 后续打磨

6. 自定义 Agent 表单首屏看不到取消/添加，滚动后可见，但标题和关闭一起移出；与 API、模型弹窗的固定页脚不一致。按钮没有丢失，应统一弹窗滚动规则。[22](../file-inventory.html#file-299)、[23](../file-inventory.html#file-300)。
7. 登录按钮“登录 Log in with Google”动作重复；应将通用中文动作与原始登录方式名分层，保留官方方法名称。[17](../file-inventory.html#file-294)。未测试登录，不能称登录失败。
8. 收藏空态沿用“没有找到匹配的对话/清除筛选”，未解释如何收藏第一段对话；可以补充与收藏任务相关的起步说明。这是低优先级内容建议。[36](../file-inventory.html#file-313)。

## 对下一轮 UI/UX 改版的判断

应先修两处看不清/用不顺的布局，再统一三条日常路径：**开始新工作、管理已连接 Agent、遇到阻塞后继续工作**。每条路径先明确当前状态、相关信息和一个清楚的下一步；最后再统一间距、颜色和圆角。现有灰白工作台、来源分层、未保存确认、可选测试边界值得保留，没必要整套推翻。
