# Agent 与 API 配置落地证据

更新：2026-09-24。源码基线 `eefa4df` 加保留工作区，未自动提交。用户已认可设置页原型并授权实施；本轮不增加 Agent、模型代理、执行循环、外部配置写入或会话账本。此目录中的模拟服务和直接 Agent 探测不能替代正式安装版验证。

## 实现与原因

| 原问题                                                      | 根因与修复                                                                                                 | 清理与保留                                                                                      |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 已支持的 Agent 在添加后从目录消失；普通用户需要填写启动细节 | Agent 常驻目录，使用实际品牌素材；多个程序折叠管理，按实际状态提供连接、安装、更新和条件登录               | 删除旧添加页主流程、重复 API 卡和新建对话入口；高级自定义入口保留                               |
| 密钥保存后仍需要猜变量，地址和模型未真正配置                | 同一条 API 配置保存来源、接口格式、基础地址、Keychain 引用及多个模型；使用时按已验证官方入口转换为进程环境 | 删除新增授权/变量表单、独立改说明与换 Key 命令、请求观察表；旧 ID、授权、凭据引用及撤销入口保留 |
| 同项目的不同服务可能复用连接，恢复可能换源                  | 来源修订进入现有连接键；草稿、状态、认证、操作、恢复归到具体连接；首条消息发送前保存来源                   | 无第二个连接管理器；旧无来源历史保持未知，不能偷偷套用新服务                                    |
| 换 Key 后可能绕过未结束恢复；本地关闭和发送存在竞争         | 打开预留跨服务修订，直到实际操作结束或进程回收才释放；会话处理端检查空闲后确认关闭                         | 删除快照判断后直接拆路由；副作用未知不自动重发                                                  |
| 断开已返回但旧连接仍可见                                    | 实际进程回收后，先按实例移除连接，再发布完成；连接表清理失败如实报错                                       | 没有增加等待时间、重试或隐藏失败                                                                |
| 安装完成被当成可用，程序切换失败可能破坏旧目标              | 安装与已发现程序复用候选检查、回收和原子选用；错误保留安全分类                                             | 删除未经检查切换；失败、取消和未知结果保留原目标                                                |
| API 测试无真实出口                                          | 三种格式的独立有界请求，模型列表与测试分离，支持取消、迟到结果失效                                         | 保存不等于测试通过；测试通过不等于 Agent 工具/恢复已通过                                        |

## 最终安装与删除证明

唯一安装 `/Applications/Farfold.app`，0.1.7 / `ai.farfold.desktop`，候选 3 SHA256 `1706cc4fa486f563327fd06201dc785acc7c42412e48e1e514b2d8748ca07675`；[安装身份](installed-identity.json)、[生产源码摘要](candidate-source.json)、[工程检查](checks.json)、[候选 3 界面记录](candidate3-ui.json)。工作区未提交，不以 HEAD 单独代表此候选。

正常退出跟踪的 7 个应用及后代 PID 全部结束，旧 UE 进程未触碰；随后同候选重启，目录保留且连接状态重新判定。见 [退出记录](candidate3-exit.json) 与 [重启截图](screenshots/17-candidate3-restarted-directory.png)。生成的重复 `src-tauri/target/release/bundle/macos/Farfold.app` 已在摘要匹配后删除，未清空 target 或数据；[最终核对](final-verification.json) 记录确切路径、删除结果和 134 个生产文件摘要一致。

独立审查清理了旧 Agent 卡片和凭据页 CSS、不可达的旧密钥表单及 `auth_set_api_key` 写入口；旧 Keychain 标记读取、凭据 ID 和历史授权撤销仍保留。`credential_edit/replace/grant/usage`、`request_observations`、`authSetApiKey/auth_set_api_key`、`keyOnlyElsewhere`、旧凭据 CSS 在当前源码无残留。

安装发现的 API 无文字样本已定位：同形直接请求 HTTP200、64 个输出 token 全部用于推理、`finish_reason=length`。Farfold 原文案错误暗示模型/接口有误；现在识别三格式的输出截断，仍不判完整成功，不增加预算、不自动重试。详见 [安全响应结构](atria-diagnostic-shape.json)。候选 3 后续实际测试得到正文，不能覆盖前一截断样本；真实三格式/任意模型兼容仍未证明。
