# 分组记录格式保护：源码与受控验证

## 问题与行为

`conversationGroups.v1` 原解析器会把未知根格式读成空分组，把非法成员或关联静默丢弃，然后发布 `ready=true`。此后创建、改名、移除或移动对话均可能用裁剪后的对象覆盖原设置。首次受控测试用内存设置夹具复现了这一链路，未接触正式数据库。

本片仅修改 [collections.ts](../../../src/runtime/collections.ts) 与新增 [collections.data-preservation.test.ts](../../../src/runtime/collections.data-preservation.test.ts)：解析失败直接进入已有读取失败出口，保持 `ready=false`，更新操作须先成功读取，因此不能提交 `settings_set`。重试读取到修正后的合法记录后，正常编辑可继续。未新增文案、接口、存储或迁移。

接受的格式仍为 `{groups:[{id,name}],assignments:{key:groupId}}`，没有内嵌版本字段。`null`/`undefined` 表示尚未保存的合法空记录；两个空容器也是合法值。分组名称继续去除首尾空白，分组 ID 与关联键保持原字面值。

非对象根、缺失容器、未知根或分组字段、非法容器、非法成员、空白 ID/名称、重复 ID，以及非字符串或指向不存在分组的关联，均拒绝整条记录。未知字段不能被当前写入器完整往返，故保留原记录并要求重试，不自动裁剪。关联键不做目录或对话存在性推断；合法 `__proto__`/`constructor` 键也不丢失。
