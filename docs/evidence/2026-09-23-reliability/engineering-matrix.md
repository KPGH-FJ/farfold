## 首候选安装失败与语义比较修复

首候选可执行文件 SHA256 为 `8f6abc185b35257b4fd86d21ca14818943dc39115495d80100d0ccf602f347f4`。原 Pi 测试会话在旧安装版可恢复；此候选完成 initialize 往返后、session/load 之前失败。正式旧行是合法的非紧凑 env JSON，握手保存将 JSON 文本当作启动配置身份而误拒绝。保留 [失败记录](candidate1-failure.md)、[候选身份](candidate1-identity.json) 和 [失败截图](11-candidate1-pi-handshake-save-failed.png)；未通过改写正式数据库绕过。

临时 SQLite 回归 `access_regression_handshake_accepts_legacy_json_formatting_without_rewriting_it` 先在旧实现实际失败，错误为“Agent 程序设置已变化，请重新连接”；修复后 MetaStore 定向 10 项通过（任务工具回执，未另存独立日志）。修复改为同锁和事务内严格解码比较，保留真实配置变更拒绝要求；另一位后端审查者已独立核对原子性、args 顺序、env 键序和不重写原值。这些是存储工程证据；最终候选已恢复同一 Pi 旧会话并在冷启动保留模型/off，见本目录 README 及截图 20、45。Pi 真实续发仍失败，失败信息由外部接入包丢失；恢复成功不能覆盖续发失败。

兼容边界：历史读取函数对坏 JSON/非字符串 env 曾静默丢弃或默认；新握手比较对这些未知形状明确失败，不能把它们当作空配置。合法旧 JSON 空白和对象键序保留兼容，不新增迁移或第二套存储形状。

## 全量运行中暴露的测试时序问题

shell 成功样本反复在旧测试的 1 秒预算结束时返回 `None`。[分支与状态诊断](shell-state-diagnostic-cargo-test.log) 记录此时读取字节数为 0、未 EOF、确切子进程仍存活、poll 超时；[进程诊断](shell-process-diagnostic-cargo-test.log) 确认同一进程组内仅测试 `/bin/sh` 存活。使用 builtin printf 去掉无关的额外子进程后，[全量对照仍失败](shell-builtin-comparison-cargo-test.log)，不能把该替换当作原因解释。随后仅在临时诊断中对成功样本使用生产已有的 5 秒预算，[对照日志](shell-production-budget-comparison-cargo-test.log) 记录 **1.05175125 秒完成且成功**，该次 132 通过、0 失败、3 忽略。这证明 1 秒形状测试预算过紧；没有证据表明生产读取死锁，也没有证明 shell 启动变快。

最终仅让完整输出/限额/非零退出的形状测试使用既有 `LOGIN_ENV_TIMEOUT`，保留 builtin printf；75 毫秒专门超时及后代回收回归照旧。生产 5 秒预算和代码均未变，临时诊断已删除。这里未进一步归因 macOS 调度或启动耗时，不声称覆盖所有实际登录脚本。

`supervisor::tests::recovery_reaps_descendant_after_leader_exits_on_term` 的 fixture 先观察 PID 文件存在就解析，实际可能读到空文件。测试现于原 2 秒预算内等待文件内容成为有效正 PID；不改变生产恢复逻辑或超时。此修正由后端作者完成并纳入最终检查。

## 替换与证据限制

- S1 已删除自定义名称 slug/命令复用身份分支、Agent 通用 upsert 及隐式握手保留；握手写入不再只按 ID。旧用户 ID 和 Keychain marker 不是待清理兼容层，本轮未迁移它们。
- S4 已删除 shell 超时循环内的阻塞读取、目录固定旧版本 fallback、读写不一致缓存类型及“磁盘坏了就丢弃已知内存目录”的旧断言；Node 版本探测的无界 `Command.output` 路径由共享探测替换。主题不再同时写旧键和元数据。
- S2/S3 的替换包括管理队列中的 Shutdown、无归属请求等待、按进程名猜测/终止、单例表单及失败时伪造整轮结束。会话内正常的 `SessionControl::Shutdown` 仍是本地 pump 清理动作，不能把它误记为残留管理关闭路径。
- 本轮曾在修复前确认失败的核心回归包括身份覆盖、旧握手未清空、shell 超时、npm PATH、缓存重启恢复、缓存保留/失败传播、迟到握手和取消 worker 的锁持有。早期失败输出及独立 rustc harness 回执保存在本次任务记录/系统临时目录，未全部归档到此目录；本文不把它们冒充现存完整红测日志。可持久复查的末态结果是上述 Rust/前端日志和当前测试源码。
- 本矩阵不把工程覆盖扩写为安装通过或真实共享密钥结论。表中“剩余未测”是该工程用例自身的边界；同候选后续定向证据统一见本目录 README。J1–J6 的继承未达项、Codex 恢复漂移、Pi 续发失败和性能限制仍开放。
