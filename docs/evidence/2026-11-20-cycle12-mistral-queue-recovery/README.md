## 官方入口与复验条件

2.25.8 的官方 `session/load` 在回放正文前以 `ResumeSessionIntent` 打开原对话。该方法未处理额外参数。独立 `session/resume` 也使用相同的恢复意图。`session/list` 读取列表元数据，无法取回正文或核对原工具终态。厂商后续发布说明也描述了从中途关闭恢复时原轮继续执行。当前 Farfold 的历史预览同样经过 `session/load`，因此对该中断样本另走预览也可能触发原工作。 [官方载入实现](https://github.com/mistralai/mistral-vibe/blob/v2.25.8/vibe/acp/agent.py#L555-L580) · [官方列表实现](https://github.com/mistralai/mistral-vibe/blob/v2.25.8/vibe/acp/agent.py#L989-L1009) · [厂商发布说明](https://github.com/mistralai/mistral-vibe/releases)

官方 App Server 测试的 `session/read` 使用已经打开的会话，当前登记 `vibe-acp` 的公开方法未提供该读取入口。源代码核对未证实它可以直接被用于读这个未结束原对话。 [官方读取测试](https://github.com/mistralai/mistral-vibe/blob/v2.25.8/tests/app_server/backend_contract/test_session_lifecycle.py#L23-L49) · [登记程序的扩展入口](https://github.com/mistralai/mistral-vibe/blob/v2.25.8/vibe/acp/agent.py#L1127-L1205)

重开原样本前需要官方提供按原对话及原目录读取原文、工具状态的无副作用入口，或先核对和结束原工作再安全重连的方式。另需原工具实际回收及可归属的终态。到位后复验热重连和冷开均不触发模型、工具或旧请求，原草稿及两条待发保持，用户点一次继续后各发一次。样本创建前已有的主动停止及已结束对话冷续答证据仍适用于所测路径。
