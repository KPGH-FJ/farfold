## 新发现：历史工具耗时失真（未通过）

- 重现：真实 OpenCode 执行 sleep 60，在 23.6s 停止；正常退出、重开同一会话后，该工具显示 `<1s`。对照截图 09 与 14。
- 根因：`src/runtime/session_projection.ts` 的 `upsertToolCall` 在创建/结束工具时统一用 `Date.now()` 记录 `startedAt/endedAt`，回放也走该逻辑；`src/components/thread-items.tsx` 的 `durationLabel` 将二者差值直接作为执行耗时。
- 结论：这是 Farfold 的显示错误，历史回放接收耗时不能代表原任务耗时。没有可信原始时间时应保留未知，不能靠补存一套工具事件账本解决。本轮只登记缺陷，未改变验收候选。
- 另一个观察：停止时总状态为“已停止”，工具行仍显示绿色完成符号；截图中保留。工具状态来自外部事件，尚未证明是 Farfold 归一化错误，不将其与已确认的耗时问题混为同一根因。
