# 停止发生在草稿保存期间

范围：P04、ARCH-25。运行中点「加入待发」，前端开始保存本次提交的草稿。此前只在准备附件后核过停止状态，第二次保存返回便直接提交。如果同一对话在这段时间收到停止操作，旧稿会被移入待发；若停止已经确认，旧意图还可能直接发出新请求。

用现有组件、真实前端对话逻辑和受控回执复现。先接纳一条请求，再点「加入待发」，扣住第二次保存，然后点同一对话的「停止」。一例保持停止等待，另一例先交付匹配的取消终态。旧实现 11 项通过、两条新增反例失败：两条都清空草稿，等待时错误入队，已确认时多发送一次。

修复后，同一对话的停止会撤销还在等待保存的提交意图。两种时序均保留原稿并清除本次提交标记，待发保持原样，只有最初的请求。在停止确认后重新明确点发送仍可发送该稿。此次使用受控的前端命令和回执，正式应用实测仍待。[旧正式版升级条件](../2026-11-06-phase1-old-exit/README.md)
