# 停止发生在草稿保存期间

范围：P04、ARCH-25。运行中点「加入待发」，前端开始保存本次提交的草稿。此前只在准备附件后核过停止状态，第二次保存返回便直接提交。如果同一对话在这段时间收到停止操作，旧稿会被移入待发；若停止已经确认，旧意图还可能直接发出新请求。

用现有组件、真实前端对话逻辑和受控回执复现。先接纳一条请求，再点「加入待发」，扣住第二次保存，然后点同一对话的「停止」。一例保持停止等待，另一例先交付匹配的取消终态。旧实现 11 项通过、两条新增反例失败：两条都清空草稿，等待时错误入队，已确认时多发送一次。

修复后，同一对话的停止会撤销还在等待保存的提交意图。两种时序均保留原稿并清除本次提交标记，待发保持原样，只有最初的请求。在停止确认后重新明确点发送仍可发送该稿。此次使用受控的前端命令和回执，正式应用实测仍待。[旧正式版升级条件](../2026-11-06-phase1-old-exit/README.md)

前端全量 722 文件、9,663 项通过，类型检查、生产构建、受影响文件格式和文档检查通过。独立复核确认停止保护仅在原对话实例内生效，待发恢复规则保持。

正式复验使用专用对话和草稿。先让第一条请求进入运行并保存第二稿，再点「加入待发」。需以同一对话的保存与停止回执证明停止确在待发稿的保存返回前处理：只有鼠标点按时间、保存失败，或保存先返回均不算命中。最终核对第二稿及附件仍在输入区、待发不变、无第二次请求、再次正常保存能读回。若自然时序无法取证，只在隔离的图形账号或实例评估受控写入等待；不在用户正式库上锁。系统若直到写锁释放才处理点按，该路径记为未触发。[既有 SQLite 受控桥及边界](../2026-11-04-p01-storage-bridge/README.md)

## 保存期间断线并重连

独立回归用实际输入框提交按钮、旧连接事件和「重连」操作。在第二次保存仍未返回时，同一对话替换为新的连接。旧源码按对话编号提交，清掉输入框，并把旧稿移入新连接的暂停队列；本样本没有立即发起模型请求。新增用例在旧实现为 13 项通过、1 项失败。修复检查原对话仍由原连接持有；重连后旧稿留在输入框，解除这次提交标记，新连接队列不变，零模型请求。正式应用组合尚未验证。

「编辑后重发」另经实际按钮复现断开但尚未重连的间隔。旧源码会清空编辑稿的正文和附件、移入暂停队列并关闭编辑框（14 项通过、1 项失败）。修复后编辑框、附件、正文及原主稿均保持，暂停队列不变，零请求。仍使用原连接的键盘发送与准备对话流程另有回归，原对话已被替换时未接纳稿也不会发送。

最终前端全量 722 文件、9,666 项通过，类型、生产构建、全局格式和文档检查通过，独立复核无阻断。后端未改，未重复运行其全量。两条缺陷及修复在受控前端环境复现，未更换或复验正式应用。
