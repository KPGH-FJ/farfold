## 发送准备与连接结束

受控冷启动反例用实际对话队列与精确连接结束通道。旧逻辑在本地发送准备仍等待时收到 A 的进程结束，尚无任何发送调用，却把队首保存为可能已发，冷开也显示历史未知。源码区分本地准备与已经调用发送：前者在确认原连接结束后保存为明确未发，冷开继续暂停；后者若无匹配回执，仍保留原未知标记。另一对话与两份编辑稿保持，冷开零自动重发。

独立复核又复现相反次序：同一轮的结束回执先于发送调用返回，随后原进程结束，初次修复会把已送达消息保存为明确未发。当前代码在连接健康、原调用仍待返回时保留界面的待发，冷开快照仅排除已有匹配结束回执的那一条。原进程确认结束，或恢复时已确认关闭原会话路线，替换后的对话也只继承真正待发的内容。首条消息已确认送达时，同一连接退出后保留其已有对话身份。测试在原调用仍未返回时重连及冷开，核到后排的相同内容及独立待发都保持，零额外调用；原调用迟到也不会再次移除后排。准备中突然中断且缺少进程结束证据时，仍保留原有保守的重发保护。此处是当前源码的受控验证，正式应用仍待复验。

关闭原连接的对照分别模拟已收到匹配终态，以及发送已接纳但界面没收到终态。只在原关闭确认后发出重连；后一种在新对话状态与冷读中均保留同一条未知和后续待发，零额外发送。两例没有原进程结束回执，关闭确认来自受控回执。最后一组定向 5 文件 118 项通过，独立复核核对了原连接归属、后续同引用待发、首发身份及迟到回包保护。
