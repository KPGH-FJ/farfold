## 保存等待期间仍可处理下一条命令

另用真实应用命令派发、Tauri 测试窗口和独立 SQLite 库验证。临时库持有写锁时，旧草稿保存会占住派发线程，下一条命令只能等保存失败才进入。修复后，草稿保存仍等待结果，但下一条同线程命令可先应答；释放锁后收到原保存成功回执，新连接读回新稿。持续占锁仍返回原写入错误，失败不改旧稿。测试依据是命令回执次序与数据库读回，没有用处理耗时推断是否阻塞。

后续复现后台未读和 Agent 准备进度也会在同一 SQLite 锁期间挡住退出命令。两次隔离原生反例均核到相应写入先返回忙，随后退出派发探针才能应答。源码仅让草稿、未读、准备进度三个明确由退出流程等待的设置走后台写入；外观设置继续沿用同步写入。合并用例持锁时三个写入回执仍在等待，退出派发探针先应答，解锁后三个设置均收到成功回执并由新库连接读回。原生定向 19 项通过。

前端还复现一个独立次序。未读写入等待期间，Agent 准备进度才开始保存，旧逻辑收到未读回执后便发退出请求，准备结果尚未落盘。最终退出流程在同一次退出中重新核对草稿、未读和准备进度。两个真实前端存储配合受控回执的测试确认，未读已保存而准备回执仍等待时零退出，准备成功后只发一次退出请求，并在该时点读回确切选择。相关 80 项通过。两组证据覆盖命令派发和前端退出次序，正式 macOS 界面的写入故障仍待隔离实测。

## 安装版写入故障的剩余步骤

测试仅在独立的 macOS 图形实例，或当前应用正常退出后同机专用账号执行。系统库路径按用户隔离；当前单实例检查使用主机共用的通信地址，因此同机两个账号不可当作可靠的并行隔离。先核唯一正式应用的版本、专用账号和测试库的实际路径及所有者，零 Agent 登录和发送。现机未找到可直接使用的已隔离图形实例。

1. 在空白输入区写一份唯一的自测文字，先以新只读连接核实该值已写入自测库。
2. 仅打开已存在的专用测试库。确认路径、所有者和原文字都精确匹配后，开启只持写锁、不改数据的 SQLite 事务，设定最长占锁时间。锁内改写自测文字，待界面出现保存失败。触发正常退出，核界面仍显示新稿、应用仍在，新只读连接仍读到原值。
3. 明确回滚并核对旧值。点退出提示的重试，核一次正常退出；冷开同一正式应用，界面和新只读连接都读回新值。保留版本、占锁、错误、重试、退出和冷读回执，不采集账号资料。这个分项只覆盖 SQLite 写锁，停止期间保留原稿另按上文要求验证。

独立 SQLite 回归补测含 16 MiB WAV 的暂停待发和编辑副本。原待发先落盘，第二个连接持有写锁，编辑稿保存收到 SQLite 错误码 5，第三个只读连接核对旧记录摘要一致。编辑文字和原待发仍在，释放锁后需显式重试才更新。重开草稿代码再读库，编辑副本、原待发与 WAV 摘要一致，存储只编码一份音频，待发仍暂停，全程零 Agent 请求。该分项通过测试通信接入真实临时库，正式界面写入故障继续待测。

## 待发按钮归属与退出时尚无终态的工作

实际输入组件的受控回归中，前一条待发已通过原队列移除路径离开，但它的编辑和移除回调仍在。下一条文字相同、归属不同，旧回调可以编辑或删除下一条。源码核对点击时展示的确切消息，目标位置已变化或另有编辑在进行时保护现有内容。覆盖旧编辑、旧移除、已有另一编辑及原有效路径，零新增发送。

通过实际退出组件和真实对话存储复现了另一处缺口。已接纳的请求仍在运行，用户确认「保存并退出」时保存快照没有结果未知；冷开时官方历史省略未终态工具，原对话不再显示未知。源码沿用现有冷启动标记，保护仍属当前连接的已接纳请求和活动工具。当前界面仍显示真实运行状态。请求得到终态但其工具还在运行时继续保护，收到对应工具终态并确认活动释放后撤下这次标记，原有未知保持。回归覆盖先取消退出再确认、原稿和另一对话隔离、冷读省略工具及零重发。该退出为实际前端组件配合受控通信，正式应用复验仍待。
