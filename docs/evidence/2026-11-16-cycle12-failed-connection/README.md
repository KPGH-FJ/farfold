# 第 12 周期 · 单独关闭出错的连接

前序正式验证中，Cline 的 `session/prompt` 已发出并收到匹配的 `internal_error`。因为该答复没有确认工作结束，Farfold 保留名额。另一条任务运行时，第三条任务只能在 Farfold 等位，超时后仍保留原草稿。[原 Cline 实测](../2026-11-15-cycle12-pre-send/qoder-history-cline-smoke-2026-11-16.json) · [前序排队回执](../2026-11-15-cycle12-followup/cursor-foreground-pair-2026-11-16.json)

本批沿用显式确认流程。仅在当前已发送的请求收到匹配的协议错误时，可以检查是否只关闭它的连接。检查与确认都会验证原对话、原连接、原请求和其他工作。已发请求的结果仍未知，最终只有该连接归属的进程组真实退出才释放名额。草稿和待发消息保留，旧请求无自动重发。

## 正式应用实测

在 `/Applications/Farfold.app` 正常登记并使用只在本机运行的测试程序。A 返回与原请求匹配的内部错误，进程留在原组内。B 正在运行，C 界面显示已排队，测试程序未收到 C 的请求。

回到 A，点击「检查能否关闭此对话的连接」，核对范围后点击「关闭此对话的连接」。A 的进程组确认清空，B 保持同一进程运行，C 约 138 毫秒后获准发送并完成。B 随后完成原任务。Farfold 未重启，A 原消息和未发送草稿仍在，界面显示「此前请求结果未确认，未自动重发」。三条任务各发送一次。正式测试使用本机夹具，Cline 的官方请求结果独立记录。[正式验证回执](installed-recovery.json)

安装前后 236,586 条保护记录摘要一致，元数据备份完整性通过，重复应用产物已清理。验收后撤下临时接入，目录回到 27 家，三条自建对话仍在对话库。前端 10,945 项、优化版 Rust 单元 2,784 项和集成 10 项通过，共 11 项忽略。格式、类型、正式打包和严格 Clippy 检查通过。受影响回归覆盖两种回执顺序、错连接证明、同连接有其他任务的拒绝，以及进程确实退出后的放行。
