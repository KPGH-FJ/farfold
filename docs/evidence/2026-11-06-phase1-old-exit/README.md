## 为什么没有结束回执，怎样安全保留未知

11 月 7 日 01:05 只读复核，三条停止后的原请求都已返回；同一批通信记录未出现一次 `session/close`，三个原进程组仍在。一个 Copilot 样本的 shell 和子进程早已提前退出；另一个 Copilot 和 Goose 的首个审批未获批准。两个 Copilot 仍无同一工具的终态，Goose 的官方历史没有留下这一工具的可回放记录。这能解释缺少结束证据；不说明各程序内部正在等待什么，也不证明进程没有其他活动。[逐条因果回执](receipt-gap-2026-11-07.json)

安装源码 `6ce829c5` 将三种证据分开：取消只结束原回复；同一工具报告终态才释放旧工具保留；确认原进程和进程组均结束才发独立结束回执。旧版普通关闭和分离在工具未收口时拦截，空闲回收也不接管仍受保护的连接。因此这三条没有进入关闭流程，现场证据也排除了「三个进程早已退出、只是界面漏显示」。此结论不归因于 Agent 内部实现。旧版的全局退出先保存、再结束所有连接，在那次保存里不会为「回复已停止、工具仍未知」补标记。

安全路径是旧应用仍运行时取得原对象的独立进程结束回执，由旧应用保存它留下的结果未知，再对原草稿、保留稿、待发和该会话标记逐项只读核对；若原 Agent 迟到发送同工具真实终态，则按真实结果记录。逐条核清后，还需确认其他连接没有活动工作，再正常退出并核对数据。三个旧对象当前都未满足。外部排查回执只封存证据；Markdown 即使能导出已加载内容，也不包含草稿、待发或可回读的对话未知标记，不能代替应用保存。未重新发送旧请求、写生产库或强制结束任何连接。

01:16 的最终只读核对：原程序、三个进程组和通信封存值不变，可靠结束及已保存未知各 0/3，三条无待发项；原稿对象和正文摘要一致，保留稿仍为 1 份。

## 独立源码补强：冷启动保留未知

已明确取消的原轮若仍有已观察到、归属该轮且未结束的工具，保存时复用当前对话的未知标记。另一工具的终态和新请求不会清除旧未知；只有原连接确认该步骤离开活动集合，才撤下这次派生的标记，原已保存的历史未知仍保留。格式不正确、只改变卡片展示的工具消息不能代替原连接回执；带对话号的同名原始 Agent 消息也不能清活动集合，原内容照常保留。未新增存储字段，没有从普通归档活动反推工具状态，也没有回写旧正式版的三个对象。

同一组受控冷启动测试在旧逻辑为 14 过、4 败，初次补强后 18 项全过；独立复核新增的两个格式异常反例分别先失败，最终 20 项全过。冷启动只传递序列化后的保存值，模拟官方历史省略未结束工具；验证有待发及无待发、同一或另一工具的回执、后续显式请求、已有历史未知、另一对话和草稿隔离，零冷启动重发。最终全量前端 722 文件 9,660 项、类型检查、格式检查、构建和文档检查通过，独立代码复核无剩余阻断。本批无后端代码变化，未重跑后端全量。该证据不解除旧正式版退出保护。
