# 第 12 周期 Codex 新对话零发送新建与冷开

## 正式版复验

用户批准为新入口使用单独的 Codex 目录，并在官方浏览器登录中使用同一个 ChatGPT 账号和工作区。两份凭据由官方程序各自管理。Farfold 从每次连接的官方本机账号回执核对用户和工作区，不保存账号原文或凭据。

完成新建与冷开的 Mac 正式版 `/Applications/Farfold.app` 的 CDHash 为 `e30fb68f7648b2187dbc2c42bccfefaf86a761ee`。新对话从「新对话 → Codex → 选择工作文件夹 → 打开对话」进入。首次返回 OpenAI `gpt-6-astra / ultra`，文件权限只读，工具网络关闭，审批由用户确认。退出应用并确认原进程结束后，从「最近」重开刚新建的对话。官方原 ID、工作目录和以上实际设置全部核合。首次和重开均可见实际权限回执，发送按钮禁用。检查过程零模型消息、零在线预热，官方历史不存在消息或任务项。官方浏览器登录是此前独立的授权操作。

初版曾在冷开时显示重连失败。该新对话的官方文件已保存设置事件，触发回执拒绝的具体字段未取证。独立测试还复现了空对话的冷开采用进程默认模型和权限，以及只在进程参数指定 Ultra 时官方返回空值。冷开修复版在独立程序启动时明确采用原模型及只读和用户审批。冷开以原 ID 加上已保存的思考强度向官方请求，核对一次性回执里的实际值，无另行更新设置。冷开修复版既复验了初版失败样本的同 ID 重开，也在另一个工作目录完整复验了新建、退出、冷开。

Codex 官方 0.171.0 从临时验收程序转到稳定本机安装位置，43 份程序包文件内容一致，并通过正式设置入口选用。原旧程序仍在。未打开两家旧 ACP 对话，也未迁移其来源。两条旧 Codex 与十条 Copilot 的 Farfold 索引逐行匹配，两份关联旧 Codex 历史的文件身份、修改时间与大小匹配，原 Codex 凭据、设置和安装标识摘要一致。 [正式回执](formal-receipt.json)

## 独立存储和官方接口

官方程序在 `CODEX_HOME/sessions` 保存会话，`sqlite_home` 只负责数据库。断网合成样本中更换数据库目录后，历史仍在原 Codex 目录。进程被禁止访问该历史目录时可新建空对话，但厂商无法保存。客户端无法指定新 ID。厂商的内存存储能隔离进程内对话，进程结束后该 ID 无法重开。 [独立存储对照](storage-boundary.json) · [官方历史写入实现](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/rollout/src/recorder.rs#L1619-L1639)

独立目录的官方进程为新对话设置标题以保存该 ID，再读回同 ID 与精确文件位置。重开从对话索引确认对话来源和目录，以原 ID 查找，不以其他历史文件代替。每次运行均再次核对厂商的实际账号和设置。零发送工作进程阻断网络与子进程、限制持久读写到独立 Codex 目录，并禁止写入其账号文件。原账号仅由另一个断网进程读取本机官方回执。 [断网与落盘对照](isolated-name-cold.json) · [官方对话接口](https://developers.openai.com/codex/app-server/)

## 验收边界

本批验的是从正式入口建立与重开同一条空对话，以及账号、模型和权限的实际回执。App Server 正常发送、工作中的停止与恢复、模型服务计费和统一 Responses 实答继续待验。旧 ACP 对话仍走其原接法。

全量前端首次发现共用设置忙状态回归。恢复运行中的原短路顺序后，前端 11,121 项、Rust 2,878 项通过，Rust 10 项按既有配置忽略。类型、Clippy、arm64 打包和文档检查通过。当前 `/Applications/Farfold.app` 的 CDHash 为 `d8394351fa4d844f7d977428d7ea41222a2cb357`，正常退出重开后再次从「最近」核对同一原 ID、账号及实际设置。首次冷开和首次全量失败均保留。
