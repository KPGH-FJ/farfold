## 已核实的共用问题

1. **账号管理并未完整接通。** 当前 `AuthMethodsResponse` 只有方法列表和 `canLogout`；原生账号身份/状态扩展没有成为统一账号页的数据。方法名称和服务名称不能证明当前实际账号或订阅归属。已知提供状态接口的 Agent 仍有客户端覆盖缺口，其他项则继续保留未知。
2. **退出/换号只承接标准 logout。** 当前 33 项仅 6 项缓存声明该能力：Claude、Codex、Dirac、Antigravity、Kimchi、Poolside。其余 27 项没有相应共用退出/换号控件；其中有些已有官方 CLI 或专有接口，不能说 Agent 本身都不支持。API 密钥服务的编辑也不等同订阅账号退出。
3. **7 项旧模型接口未承接。** Gemini、Auggie、Autohand、Kimi、Nova、Qoder、Stakpak 的现有模型路线需要旧接口；当前前端不消费 `models/current_model_update`，生产请求无 `session/set_model`。Autohand 类中虽有新 setter，但安装版 SDK 没注册，不能算可调用。
4. **Factory 响应确认不兼容。** 0.230.0 源码在调用模型 setter 后返回空对象，当前确认链不能确认并保存；实际模型是否已改变未实测。不能显示已切换，也不能自动重试结果未知的变更。
5. **同一位置多对话的隔离有具体反例。** Farfold 按 Agent/目录/服务复用进程；Pi 在同一 ACP 进程内新建/加载对话会结束其他 Pi 会话子进程并移除内存映射，不删除历史，也不影响其他独立进程。Cursor 共享模型、Stakpak 共享消息/模型/停止，与当前组合存在明确实现冲突。没有在本轮实机重现串扰，不能写成新实测失败。Kimi 写全局默认只直接影响后续默认来源，不等于立即改变所有已打开会话。
6. **成功加载与完整历史仍需分开。** 当前客户端已拒绝未完成或不可读/空回放。Agent 的缺失历史空建路径不证明 Farfold 已放行空历史；Nova/Qoder/Gemini 的迟到回放属于具体时序风险，未复现不记丢字失败。既有历史根本不存在时无法恢复，也不应被当作所有有效历史均不可恢复。
7. **部分登录确认语义不足。** Goose/fast-agent 的精确版本 `authenticate` 未执行登录或独立校验凭据，但现有共用确认链可显示“登录成功”；后续检查仅重启到握手。空对象是标准合法成功响应，问题来自这些具体实现与界面表述的组合，不能把所有空认证响应判为错误。

精确代码引用与范围见 [共用审查](common-review.json)。协议参照：[认证与退出](https://agentclientprotocol.com/protocol/v1/authentication)、[历史加载与回放顺序](https://agentclientprotocol.com/protocol/v1/session-setup)。协议要求不能替代各实现的真实成功证据。
