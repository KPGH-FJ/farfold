# 登录后显式重读模型

日期：2026-09-30。这里记录源码与受控回归，正式应用与真实 Agent 验证由本批安装证据另行确认。

## 问题与修复

准备模型返回 `AUTH_REQUIRED` 后，页面记录登录要求。登录后重新握手不能证明模型已经可读，因此不会清除此要求；但此前页面又用同一要求禁止显式重读模型，用户无法发出能确认认证状态的真实会话创建请求。

`AgentSetup` 现在允许用户在模型页明确点击读取/重新读取，即使先前登录要求仍在。其他准备条件、操作中的保护保持，按钮处理器也检查当前准入。自动读取和返回选择仍被登录要求阻塞，没有把握手当成已登录，没有自动发送消息。只有既有 `threads.open` 获得真实 `session_open` 成功结果，才按原有来源范围清除要求。

## 安装反例与后续修正

`c3e8737` 安装候选的 Amp 0.9.0 真实请求返回 `AUTH_REQUIRED`，重查连接保留要求；但不输入密钥也能成功 `session/new` 并返回 Medium 模型，导致要求被清除，截图 05–07 记录了这个反例。上述“会话创建成功清除要求”仅适用于创建本身的失败，不能覆盖请求层的失败。

后续工作区修正同一认证状态入口，保存每个目录/来源要求属于 `session` 还是 `request`。会话创建不能降级或清除请求层的要求，只有对应实际正常回复才能清除后者；显式模型重读继续允许，自动读与返回使用仍受保护。模型可读后用户可以主动发送短测试，失败继续保留登录要求，成功才解除，没有自动探测请求。修复证据 `auth-request-layer-red.log` 的两个用例先失败，`auth-request-layer-green.log` 的 11 项通过。下一 uvx 候选需要重新安装复验，不能改写当前候选为通过。
