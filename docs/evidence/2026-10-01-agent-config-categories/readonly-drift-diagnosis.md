# 恢复漂移时的只读模型说明：显示诊断

本次只读核对安装版文本、截图与现有源码；未修改源码、运行测试、读取数据库或操作应用。建议属于下一片显示修正，不改变原模型、推理选择、服务来源或发送准入。

## 已确认现象

[恢复文本](codex-restored.txt)与[漂移截图](03-codex-drift-blocked.png)显示原 Codex 对话恢复后，检查明确报告 `gpt-6-astra → gpt-6.1-sol`、`ultra → 未提供`，发送入口禁用，历史内容仍在。

随后[模型弹层文本](codex-readonly.txt)与[只读弹层截图](04-codex-readonly-current-choice.png)中，模型行显示 `6.1 Sol`，却同时显示“这段对话保留创建时的 Agent、来源和模型”。用户因而不能在这个弹层内判断 `6.1 Sol` 是原记录，还是 Agent 恢复返回的当前值。

这是显示语义冲突。当前证据没有显示 Farfold 自动更换了原选择；不能把“当前值只读”表述成“恢复已保持原模型”，也不能用显示修正关闭这次实际恢复失败。

## 源码原因与现有保护

- [ThreadView.tsx](../../../src/components/ThreadView.tsx)第 381–384 行从 `thread.configOptions` 的首模型选项取 `modelLabel`；第 830–831 行以普通“模型”标签展示该值。`configOptions` 来自本次返回，不能作为创建时原记录的证明。
- 同文件第 851 行无条件渲染 [workspace_strings.ts](../../../src/runtime/workspace_strings.ts)的 `settingsFixed`。它没有区分 `ready`、漂移、未完整记录或保存失败，且在新稿模型可编辑时也使用同一句绝对陈述。
- [sessions.ts](../../../src/runtime/sessions.ts)的打开流程归一化返回的 `configOptions`，同时独立应用 `ConfigCheck`。弹层模型值没有覆盖 `ConfigCheck.issues[].expected`；[config_check.ts](../../../src/runtime/config_check.ts)保留原值与当前值，并将非 `ready` 状态设置为发送阻止状态。
- 已有与恢复对话的选项修改仍由共享保护 ID 阻止；发送与待发队列的准入也检查漂移。本次无需改变这些守卫。弹层内禁用的其他选项不证明模型已保持，也不是自动修改证据。
- `ThreadState.recordedModel` 当前仅是可选展示字段，源码没有在此次恢复流程中从持久记录赋值；不能为了文案修正从当前首模型反向造出“创建时模型”。可靠的已知原值来自 `ConfigCheck.issues[].expected`，缺失时保留未知。

## 最小通用修正

只调整现有模型弹层及集中字符串：当漂移或检查尚未通过时，将模型行明确标成“Agent 当前返回的模型”，保留当前值；在弹层内复用 `configCheckMessage(check, configOptions)` 展示原记录与当前返回值的差异，再用对应状态的说明替换固定保留宣言。

本例应让用户在弹层内同时看见原模型 `gpt-6-astra`、当前返回模型 `gpt-6.1-sol`，以及原推理 `ultra`、当前未提供；明确已暂停发送，原内容与待发消息仍保留。不能只把主标签改回旧值而隐藏 Agent 当前返回结果，也不能发送修改请求将当前值改回旧值。

状态说明应沿现有事实：

| 当前状态                           | 可表达的事实                                                        |
| ---------------------------------- | ------------------------------------------------------------------- |
| 已有/恢复对话，检查 `ready`        | 当前受保护选择已通过检查，选项只读；可保留保持原选择的说明          |
| `blocked` 或无完整检查但已标记漂移 | 当前返回值与原记录不同或尚不能确认，发送保持阻止；显示实际差异/未知 |
| `confirmation_required`            | 原记录不完整，显示待确认的当前选择；不声称原模型或推理已恢复一致    |
| `record_failed`                    | 保存未确认成功，按已有出口重试；不改称选择已成功保留                |
| 新稿                               | 发送前可选择模型和推理项，不使用“已保留创建时”宣言                  |

来源行仍显示该对话实际保留的来源；本例的模型漂移不能被解释成来源也变了。多个同类别项继续按 ID 逐项展示，不将第一项的检查结果扩大到其余项。现有 `ConfigCheckReview` 可继续供待确认情况显示完整当前选择，`current` 确认仍原样透传。无需新增持久状态、数据库读取、第二份配置快照或 Agent 专属分支。
