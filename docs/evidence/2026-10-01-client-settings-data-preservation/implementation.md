# 同版本未知字段保护：实现与受控验证

`setup_storage.ts` 在原根对象/版本校验中增加已知字段集合检查；`drafts.ts` 在解析根对象之后、恢复任何草稿/选择/意见/队列/活动之前做相同检查。未知字段使既有读取错误传播，存储保持未就绪，原写入门控拒绝后续保存。没有增加格式版本、默认重置、迁移写回或字段筛选。

原 `agentSetup.v1` 缺少 `selections`、`unsentWork.v1` 缺少 `activity` 的兼容路径未改变。没有修改原并发保存、失败重试、附件恢复、秘密清理或迟到结果保护，也没有对正式数据库构造损坏记录。新增内部错误不会直接呈现给用户，界面仍使用现有固定读取失败文案。

首先核对准备补丁及五个受保护源摘要，仅应用测试补丁。[红测](red.log)两文件共 40 项，2 失败、38 通过；两个未知根用例实际尝试编辑和保存后，在“读取应拒绝”断言处失败。没有到达该例后续原值保持断言，不将这份日志说成已经打印或断言完整磁盘丢失结果。生产修复后，相同[绿测](green.log)40/40 通过，包含未知格式原模拟磁盘值保持、所有写入口阻断、修正读取后明确重试、本地编辑保持及旧缺省格式的冷加载。

受控测试使用模拟 IPC 与独立模块状态，正式应用、Agent 或数据库均不由这些测试操作。[source-final.json](source-final.json)记录四个变更文件，最长 541 行。全量工程检查和安装结果分别记录，不把准备进度视为认证/首发成功，也不把未知根检查称为对全部嵌套扩展或原始 JSON 重复键的保护。
