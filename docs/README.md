## 代码与资产

- `src/`：React 应用；`components/` 是统一界面，`runtime/` 是客户端状态与 IPC，不是 Agent 执行器。
- `src-tauri/src/`：Rust 桌面入口、ACP 客户端、安装与认证、元数据及进程管理。
- `scripts/`：更新链路使用的签名工具、文档维护检查和对应测试。
- `assets/`、`src-tauri/icons/`：应用图标源文件与导出资产。
- `.design/2026-09-26-agent-access-redesign/workbench/`：唯一当前原型；旧版本与历史设计报告已按 2026-09-28 授权删除。
- `dist/`、`node_modules/`、`src-tauri/gen/`：生成输出或依赖；不作为实现事实来源。
- `src-tauri/target/`：编译输出与历史本地备份混存，具体保护项见整理记录，禁止整体清空。

新证据改变结论时，已归并条目只更新状态页的对应结论并核对要求参考链接；未归并条目仍同批维护状态页与参考进度；执行顺序或本批出口变化时再更新活动计划。新验收材料放到 `docs/evidence/日期-主题/`，说明提交、应用身份、真实操作及未覆盖项。

状态页只保留当前基线、验证层级和未解决问题；活动计划只保留当前顺序、依赖与本批出口；任务要求参考完整承载151条原始任务、工作包共同条件和对应进度；架构页说明当前代码结构。参考文档不能增加“下一步”队列、重排批次或恢复旧授权，不得演变成第二份计划。累计阶段日志完整移入归档，不继续复制到当前入口。2026-10-17 整理前的原件和解析原链接的方法见[归档索引](archive/2026-10-17-documentation-alignment/INDEX.md)，更早记录保留在各自历史目录。

任务交接只用于定位当时工作、进程和证据。当前事实以 `status.md` 为入口，执行顺序只由 `plans/agent-access.md` 决定；旧交接可保留一个指向当前状态的重定向，不以文件名、schema版本或“下一步”恢复旧任务。已执行的检查脚本、回执和冻结输入保持原件；它们的断言不构成新的产品要求。

151条记录的编号、原题和完成条件在单一参考中完整保留。原文中的29家对应当时核验范围，当前首发名单和八项标准以产品契约为准。当前进度按对应证据更新，不能用整行冻结把旧进度也固化。可执行 `corepack pnpm docs:check` 核对原条件、唯一计划和当前导航；该检查不证明产品功能或真实Agent验收。每次阶段收口更新现有入口，避免再增加一份“当前计划”。

## 按任务读取

首次了解产品范围和契约后，日常续接读取[当前状态](status.md)与[短执行计划](../plans/agent-access.md)，再查询本批ID。例如 `corepack pnpm docs:task P39 P41 P45` 读取要求参考中的指定任务、所属包及共用依据。已归并条目的要求参考只保存指向 `docs/status.md` 的链接，命令直接读取该页的 `task-current` 段落；缺段、重复段或参考表仍有第二份正文时会失败。尚未归并的条目标明为参考进度，不自动认定为最新结论。输出中的相对证据链接以要求参考所在的 `docs/` 为起点。NEW条目须显式指定相关包，例如 `corepack pnpm docs:task NEW-24 --package B,C,K`。错误ID或NEW缺少包会失败。

逐家查看可运行 `corepack pnpm acceptance:index --agent goose`，也可加 `--standard S3` 或 `--requirement P41`。该入口读取原第1阶段29家台账并保留出处、原版本及范围；历史余项和当时0/29不冒称今天的全量结论，当前事实仍看状态页。默认另读[第2阶段分项资料](evidence/2026-11-11-mcp-lifecycle/stage2-evidence.json)，包含两条文件样本及一条官方MCP生命周期观察，按明确的Agent、标准和任务关联筛选；原成功事实与局限一并保留，结果固定为未分类，不生成标准回执或通过数。查询时核对公开证据摘要，本机原件核查保留当时记录及边界。显式标准分项、未分配资料与显式传入的回执覆盖分别显示；`not-indexed`表示未收录，不能当作未测或失败。台账自由文字不自动变成成功/失败或整家通过。按任务查询复用状态页已归并结论，未归并参考进度仍保留来源标记。

维护当前进度时用最新结论、直接证据和剩余缺口替换失效说法。旧失败与当时未测范围留在原始证据中追溯；共用修复须核对所有关联任务，例如工具报告焦点同时涉及P39与P45。提交前运行本批实际任务命令，核对输出与状态页及证据是否一致。结构检查通过后仍需这项内容核对。本次来源排查和新会话读取记录见[入口维护记录](maintenance/2026-11-11-task-entrypoints.md)。

涉及关联任务或共用机制时补齐相关范围。契约、安全约束、源码和证据发生变化，或出现失败、冲突和疑点时，仍须按受影响范围重新读取并验证；不能为减少重复而省略必要调查或降低完成条件。具体代码入口按[架构说明](architecture.md)定位，原始证据按状态或对应进度链接查阅。

## 核对交付结果

在 PR 的 Checks 查看 `Farfold delivery check`。到该 PR 对应的 `Farfold final delivery` 运行核对 PR 编号、合并预览和工程运行编号。适用证据有变化时，按[研发交付](development-delivery.md)重新核验并取得当次结果。
